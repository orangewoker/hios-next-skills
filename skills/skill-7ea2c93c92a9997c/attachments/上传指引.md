# LibTV 上传指引（本文件不要上传，仅供你操作参考）

## 创建表单填写文案

**Skill 名称**：
微缩世界救援导演

**一句话介绍**：
三拍结构出片：微缩灾难、巨手介入、修复欢呼。日常小工具拯救小人国，45 到 75 秒治愈系创意成片一键完成。

**使用场景说明**（表单最下方"使用场景"栏）：
适合制作微缩模型风格的治愈系创意短视频。当你想为环保、健康、情感、城市生活等议题做降维创意表达，或想复刻"巨手用日常工具拯救微缩世界"这类爆款格式时使用。只需说出主题（如"做一支环保主题的微缩救援视频"），Skill 会完成灾难与工具的创意匹配、分段节拍设计和成片生成。也支持指定具体场景（如"堵车的早高峰被梳子梳开"）。

## 本次改写相对原版的变动清单

1. 定位从"提示词生成器"改为"成片导演"。原版产出提示词序列给用户拿去别处生成，LibTV 版指挥 Agent 直接跑完生成、组装、音频全流程
2. 删除了 seedance-prompt 协同模式。LibTV 环境里没有你的 seedance skill，相关渲染要点已并入视觉规范
3. 工作流程改为五阶段，对齐 LibTV Agent 的原生交互（分析、总表确认、生成、组装、自检）。特别加入了"连续性评估"环节，主动声明本类型无需跨片段角色资产，避免 Agent 按默认逻辑给每段建角色资产浪费时间
4. 新增"修改响应规则"，约束 Agent 收到修改意见时只重做对应片段，不重跑全片。这对应 LibTV 的口述修改能力
5. 新增音频和组装规范（硬切、BGM、ASMR 音效、无字幕），原版只管到提示词为止，这些在原版是文章里口头交代的后期建议
6. 视觉规范里的中英对照提示词写法改为纯中文画面描述，因为不再需要适配英文模型
7. 删除了 YAML frontmatter，触发条件描述并入正文开头

## 测试建议

上传后先跑这条验证（也就是公众号文章里的对比实验）：

> 使用微缩世界救援导演，做一支 35 秒视频：微缩城市里堵成一锅粥的早高峰，小人们在车顶绝望躺平，一只巨手用梳子轻轻把车流梳开，交通恢复，小人们欢呼

重点检查三件事：

1. 它是否先出创意总表和节拍分析再开拍（阶段二是否生效）
2. 成片是否为固定机位一镜到底、有移轴虚化（视觉规范是否被读取）
3. 口述修改单个片段时，是否只重做该片段（修改响应规则是否生效）

注意：这条测试指定了单场景 35 秒，与 Skill 默认的 6 到 9 段结构不同。如果 Agent 机械地要凑 6 段，说明它对"用户指定具体场景时按用户要求来"的理解不够，可以在 SKILL.md 阶段一末尾补一句"用户指定了具体场景和时长时，以用户要求为准，跳过多段结构"。我预留了这个坑，方便你在文章里写一次真实的调试过程。
