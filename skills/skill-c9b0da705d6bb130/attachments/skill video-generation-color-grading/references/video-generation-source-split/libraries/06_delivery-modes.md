# 成品模式与输出字段

> 本库来自原始视频生成规则第 866—1013 行，按模块拆分，正文保留。

## 模块启动总控器：

## 模块分为四类：

常驻硬约束模块：事实锁、台词锁、说话人锁、人物身份锁、关键道具状态锁、背景环境锁、平台安全、字段稳定、方位站位锁、站位继承、可拍性、对白节奏保护、真实光线、成品边界。每次必启。

```text
结构流程模块：默认路由、方案菜单、视觉单元队列、逐镜确认表、成品输出、检查模式、局部修改、导出封装。按用户口令和当前阶段启用，一次只能启用一个输出阶段。
```

场景功能模块：情感戏、女频情绪、男频冲突、悬疑、古装权谋、现代都市、玄幻奇幻、多人调度、爽点节奏。按当前 S-Block 的实际剧情功能启用。

素材辅助模块：质感素材库、光影场景库、画幅适配、3D漫剧适配。只服务画面表达，不改变剧情事实。

启动顺序：

先启硬约束模块 → 再锁输出阶段 → 再判定当前 S-Block 的剧情功能 → 再选 1-2 个最相关场景功能模块 → 最后调用素材辅助模块。

单个 S-Block 最多启用 2 个场景功能模块；若同时命中多个关键词，只选对当前剧情最有用的模块，其他模块只作为参考，不得堆满。

```text
题材关键词只构成候选，不等于强制启动。必须同时满足“当前镜头任务需要该模块的镜头偏好”才启动。
```

用户明确指定的方案、题材、画幅或风格优先，但仍不得突破事实锁、台词锁、对白节奏保护和安全边界。

若模块规则冲突，优先级为：事实/台词/说话人/人物身份/关键道具/背景环境/安全 &gt; 输出阶段 &gt; 对白节奏保护 &gt; 站位可拍 &gt; 多人调度 &gt; 当前剧情功能 &gt; 题材风格 &gt; 质感光影 &gt; 情绪留白。

若当前 S-Block 主要是对白推进，任何情感、爽点、题材、质感模块都不得抢台词；对白节奏保护模块压过所有风格模块。

若当前 S-Block 主要是信息揭示，悬疑或线索模块可以启动，但不得凭空新增证据、监控、录音、手机内容或目击者。

若当前 S-Block 主要是关系变化，情感戏模块可以启动，但只视觉化原文已有关系动作，不新增拥抱、亲吻、告白、牵手或哭泣。

若当前 S-Block 主要是冲突反击，爽点节奏模块可以启动；男频/女频模块是否启动，取决于题材和人物关系，不得只因有“反击”二字就强行套男频。

若当前 S-Block 出现三人以上同场，多人场景调度模块必启；它会限制其他模块不得安排多人同时抢动作、抢台词、抢情绪。

若用户要求“检查模块启动条件 / 自检模块”，可输出模块分析；其他成品阶段不得外显模块启动过程。

## V2.2 模块降噪与优先启动协议：

## 模块启动不是关键词堆叠；关键词只作为候选，必须结合当前视觉单元的实际剧情功能决定。

```text
单个视觉单元最多启用 2 个场景功能模块；若多人场景调度必启，则它占用一个名额。
```

文戏对白密集时，优先组合为“对白节奏保护 + 多人调度 / 情绪模块 / 权谋模块”之一；不得同时堆爽点、悬疑、情感、权谋、女频、男频。

冲突反击戏优先判断冲突性质：婚恋羞辱优先女频情绪；身份资源压迫优先爽点节奏；武力威胁优先动作打斗；朝堂博弈优先古装权谋。不得只因出现“反击”就套男频。

```text
如果当前单元只是承接、转场、信息交代或人物反应，不启动强题材模块，只用常驻硬约束、站位继承、真实光线和简洁镜头。
```

若两个模块冲突：对白节奏保护压过情绪留白；多人调度压过强冲突；事实锁压过爽点；真实光源压过风格光；成品边界压过所有后台展示。

成品阶段不得写“本组启用某模块、模块判断、后台裁决、P0/P1/P2、自检通过”等过程性文字。

## 模块启动自检输出格式：

当用户要求“检查模块启动条件 / 分析模块 / 模块自检”时，使用以下格式：

## 【模块启动自检】

当前输入类型：

当前输出阶段：

必启模块：

条件启动模块：

禁用模块：

## 模块冲突裁决：

风险提示：

## 【模块表】

## 模块名｜是否启动｜启动依据｜禁用依据｜优先级/冲突处理

要求：

只列和当前输入相关的模块，不列全量模块百科。

“是否启动”只能写：必启 / 启动 / 候选不启动 / 禁用。

启动依据必须来自当前剧情事实、用户口令、输出阶段或明确场景要素。

如果两个模块冲突，必须说明谁压谁，例如“对白节奏保护压过情感留白”。

## 模块自检不得进入成品正文。

拆分规则：

90 秒左右成片，优先拆成 6-7 个 S-Block。

1.1 若用户指定总时长，以用户指定时长优先。

1.2 若后台判断实际剧情承载超过90秒，则按实际时长拆分制作：100-120秒通常拆成7-9个 S-Block；120-150秒通常拆成9-12个 S-Block；超过150秒按剧情密度继续增加，不得为了默认90秒删减台词或压扁剧情。

剧情偏密时增加 S-Block，不要硬压缩。

剧情特别短时，仍尽量保留 5 个以上的叙事支点，除非原文信息明显不足。

每个 S-Block 目标 8-12 秒，剧情或台词密集时可到 14 秒，但不得因为情绪空镜和慢停顿拉满。

```text
每个 S-Block 内通常 3-6 个有效叙事镜头，按剧情需要浮动；无台词空镜不计入必要叙事镜头。
```

```text
对话超过时长时，按语义拆镜或用过肩反应承载，不硬塞进短镜头，也不得在台词之间插入长空镜；拆镜后每句仍需听清。
```

每组必须有场景继承、人物继承、站位与构图一致性信息。

情感戏 S-Block 的空镜/纯环境镜默认 0 个，必要时最多 1 个；单个空镜 0.5-1.5 秒，强转场最多 2 秒。

台词密集 S-Block 优先保证对白推进，反应镜短促承接，不给每句台词后都留沉默；但不得把反应镜压到听不清上一句或下一句的程度。

低风险承接：

若用户直接调用中间 S-Block 且缺少上一组可见状态，不得凭空编造上一组结尾。

统一使用：

“承接上一组最后可见状态”

```text
并在镜头1里用可见动作重新建立方位基准、人物左右、前后、朝向、动作轴线和空间锚点。
```

成品输出结构（前台可复制正文）：

成品阶段只输出下列字段正文，不输出后台推理。

```text
不得输出【精简规划】、【可复制内容】标题、代码围栏、说明文字、检查过程、后台模块名、S-Block / G-Block 字样。
```

```text
成品标题必须只使用“【视觉单元XX｜剧情语义标签】”，不得出现 S-Block、G-Block、segment、Agent、Layer、SSP、OUTPUT-STABILITY 或后台索引。
```
