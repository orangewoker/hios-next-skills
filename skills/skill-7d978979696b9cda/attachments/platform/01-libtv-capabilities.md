# LibTV 网页内置 Agent 能力边界

准备保存、提交、查询、观察、剪辑或导出，或遇到实际行为与预期不同的时候使用。唯一执行面是LibTV网页内置Agent。用户在网页创建/选择Skill并输入创作要求；Agent在自己实际可见的工具和选项内工作，不调用CLI、外部会话API或外部剪辑软件。

## 当前网页证据：2026-09-06

只读观察已见Agent菜单展示Lib Image、Seedream 5.0 Pro、Seedance 2.5。已有Skill编辑页的上传菜单提供“上传文件”“上传文件夹”；文件输入接受`.md,.markdown,text/markdown`，文件夹输入带`multiple`和`webkitdirectory`。这是本项目浏览器专员的实际界面观察，由主任务转交；本轮没有上传、保存或发送创作任务。

据此，交付ZIP是文件传递包：先在本地解压，再在网页上传包含根SKILL.md的文件夹。没有证据证明网页直接导入ZIP、完整保留相对路径或正确按需读取全部知识。50文件/单文件小于20000字符是本项目包装约束，不宣称为已见网页规则。现有编辑页只见更新/保存，未见私有/发布开关；不能从旧卡片已发布推断本次保存默认公开或私有。

后续只读核验已走通“创建Skill→导入已有Skill（上传.md文件或文件夹）→空白创建表单”，没有创建成功回执。空白表单按钮为“保存”；分类默认图片，实际选项为图片/视频/音频/文本，本影视Skill填写时选择视频。表单仍未解释保存后的公开/审核或费用；另一条“通过与Agent对话创建”路径未使用，不把打开表单当已创建Skill。

## 发布身份与本轮知识可达性

发布身份/版本以[根入口](../SKILL.md)、候选清单和实际可读正文相互核对；网页显示名称、Agent自报标识或“完整加载”不能单独证明加载了哪个包。在本轮记录或回复中写明所需责任模块的真实可访问位置/名称、版本依据、实际读取范围（完整/片段/截断）与失败反馈，有已验证持久入口时再保存。普通读取核验不以另建持久存储为前置；正式制作仍沿原提交协议要求保存并读回意图。只见目录不算读正文；未尝试访问不称附属文件不存在，检索无结果不等于上传缺失。

本地清单和链接通过只能证明本地结构。经用户授权部署后，另核实际上传文件/目录以及入口→路由→本轮所需正文能否访问，具体[安装验收A4](../evidence/02-verification.md#deployment-check)；抽查不冒充全部44份通读。已经有可信读取记录的未变内容可复用，不每轮全包加载。路径错误、内容截断或未能区分版本时，明确哪个操作缺哪段规则，尝试当前已授权可用读取路径；无法恢复只暂停依赖它的正式操作，普通创作与独立分支继续。

## Agent随任务判断能力

1. 先做当前已授权且可行的创作工作。需要某项实际操作时，读取自己在当前网页会话能看到的工具说明、输入选项及已有结果；只核对这项操作需要的能力，不在每次开工前盘点整个平台。
2. 工具若实际接受自然语言、选定模型和素材，就按其提供的方式使用。工具schema如已向Agent暴露可自行读取；没有完整schema、底层model key或开发者文档，不自动使已有网页能力失效。不要让用户提供工具清单、接口、API key或运行代码。
3. 对本次必需的输入、引用、资源范围、结果去向及可能收费保持明确。只填工具接受的字段；没有字段或无法确定效果时记录具体限制，不编造调用。费用不明且可能收费时不试探执行，按[项目契约](../core/01-project-contract.md)处理实际预算缺口。
4. 发生真实操作后，用回执、可回读记录和实际素材说明完成了什么。保存/恢复按[恢复协议](../core/04-state-recovery.md)，模型按[网页模型登记](05-model-registry.md)。一次已知ID回读不证明能找未知ID对象，一次工具成功不证明影视质量通过。
5. 所需能力确实未提供或结果不足时，只暂停依赖该能力的操作。继续可信独立工作，向用户说明缺的结果或当前可交付层级；不要求切换外部执行，不把缺开发者信息变成用户的准备任务。

能力记录按[核心证据状态](../core/03-records.md)只标被实际证明的范围；没有取得证据是unknown，有当前明确不可用证据才写unavailable。不能让Agent一句“我支持”代替真实说明或实际结果。本候选仍未进行网页生产、恢复或媒体验证，见[验证状态](../evidence/02-verification.md)。
