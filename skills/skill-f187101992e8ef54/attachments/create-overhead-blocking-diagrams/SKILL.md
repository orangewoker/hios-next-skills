# AI 视频空间调度

用真实空间底图解决“谁在哪里、怎样移动、摄影机如何通过”。由 `$ai-video-director` 自动触发；本Skill不面向用户另开正式交付部分，也不编译视频平台Prompt。

## 职责边界

只负责：正式2×2场景板规划、复杂单层俯视底图、多层横切面／剖面与分层俯视图、人物起点／终点／路线、摄影机起点／路径／朝向／落点、障碍和物理可行性。结果交回 `$ai-video-director`，由主Skill写入第一部分导演大纲、第二部分资产提交表和第三部分即梦镜头组。

## 1. 建立场景事实清单

记录剧情节拍、人物关系、场景类型、实际存在的区域和结构、人物起终点、关键动作、道具、镜头连续性需求。模板不得自动增加门窗、入口、出口、楼梯、扶梯、电梯、家具、通道、障碍或连接结构。缺少的信息会实质改变空间时才提问；不能确认的内容写“待确认”。

## 2. 判断场景类型

- 简单单层；
- 复杂单层；
- 同一平面多连续区域；
- 多楼层／多高度层级。

先判断类型，再决定后续底图；不机械使用九宫格、横切面或路线图。

## 3. 第1批：正式2×2场景板

读取 [empty-scene-workflow.md](references/empty-scene-workflow.md)。每个正式场景生成一张北、南、西、东四个水平视角的2×2板。方向是摄影机从对应方向朝空间内部观察；四格必须明确摄影机位置与朝向，并保持结构、主要物件位置、尺度、材质、光源与时间一致。第一批不得包含俯视格。

多楼层按层拆成独立场景资产，每层各一张2×2板；每张只表现该层，不凭空补全跨层结构。全部相关场景板必须先生成、上传并审核。

## 4. 第2批：正式空间结构底图

读取 [layout-extraction.md](references/layout-extraction.md)。

- 简单单层没有精确调度需求：可以结束，不生成无意义横切面或路线图。
- 复杂单层／同平面多区域：在换位、绕行、穿行、精确继承或文字易失控时，从已审核2×2板建立该层俯视底图。
- 多楼层／多高度：基于所有已审核楼层板建立横切面／剖面组合图，以及与各层一一对应的分层俯视图。横切面表达垂直关系与真实跨层连接；俯视图表达各层水平位置。未知内容标“待确认”。

结构底图可合并排版或分开输出，成品数量由项目复杂度决定并明确登记。

## 5. 第3批：正式路线

读取 [blocking-notation.md](references/blocking-notation.md)。只有必要结构底图审核通过后，才标人物路线、摄影机路线、跨层路线、站位变化和关键动作位置。

- 同层人物和摄影机路线主要标在对应楼层俯视图。
- 跨层路线主要标在横切面，起点和终点必须与各层俯视图位置一致。
- 不得仅凭文字推测路线，不得只在横切面画完全部同层路线，不得为了路线方便修改已审核空间。
- 标注图可以分开或在不遮挡时合并，数量只由空间层级、路线重叠和可读性决定，不按视频秒数固定。
- 一张俯视调度图可以服务多个相关镜头组，一张多层横切面可以服务整个跨层段落；适用镜头组或范围只作参考登记，不构成时长或唯一绑定。

## 6. 物理检查与交接

检查人物和摄影机不穿越不存在的空间、不跳位；路线与真实障碍、通行宽度和高低差一致；摄影机位于真实可通行区域；跨组位置能继承；复杂路线服务叙事。

只交回“场景板／结构底图说明＋人物路线＋摄影机路线＋风险点”，并交回 `$ai-video-director`，由主 Skill 按照即梦正式模板编译。本Skill不独立输出任何视频平台专属 Prompt。真实底图未出现前，下游统一写“提示词预案／待真实底图绑定”，不虚构精确坐标、路线或完成状态。

若含打斗、快速追逐或复杂身体交互，只把动作辅助需求交回主Skill，由主Skill协调动作部门，不要求用户手动调用。
