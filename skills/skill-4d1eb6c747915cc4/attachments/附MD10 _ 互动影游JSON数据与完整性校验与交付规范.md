## #做什么

本模块为互动影游专属的JSON数据与完整性校验与交付规范库。

解决互动影游“JSON数据与引擎对接失败、完整性校验缺失、交付物不齐、Twine工程无法运行”的痛点。通过JSON数据结构规范、Twine/SugarCube工程规范与完整性校验10项，确保互动影游能落地运行、可直接交付。

## #需要什么输入

**最少提供：**

- 完整节点清单与变量字典
- 结局清单与触发条件
- 视频文件（MP4格式）与Prompt清单

**可选提供：**

- 项目名称与项目ID
- 目标平台（Steam/视频平台/小程序）
- 是否需要输出JSON数据包

## #怎么做

### 一、遵循主MD全局路由表与绝对工作流铁律

本模块执行时，必须严格遵循主MD的【全局 Skill 调用路由表】与【绝对工作流铁律】。JSON数据与交付环节重点参考【顶级游戏开发大师】的节点设计与引擎对接规则。

### 二、JSON数据结构规范

1. **schemaVersion**：JSON数据结构版本号。
2. **projectId**：项目唯一ID。
3. **title**：项目名称。
4. **variables**：变量数组，含变量ID、名称、类型、默认值、最小值、最大值。
5. **nodes**：节点数组，含节点ID、类型、标题、场景描述、选择、下一节点。
6. **endings**：结局数组，含结局ID、类型、标题、触发条件。

### 三、Twine/SugarCube 工程规范

 1. **引擎锁定**：SugarCube 1.0.35（唯一，不可更换/升级）。
 2. **禁用格式**：Harlowe / Chapbook / SugarCube 2.x。
 3. **建立方式**：手动一个一个建节点，禁止使用“导入twee或txt文件”方式。
 4. **变量语法**：标准SugarCube set语法，变量赋值格式为 set空格美元符号变量名空格等于号空格值。禁止使用旧格式。
 5. **变量运算**：标准SugarCube增量语法，格式为 set空格美元符号变量名空格等于号空格美元符号变量名空格加号空格数值。禁止使用加号等于号的简写。
 6. **条件判断**：eq / ne / gt / gte / lt / lte 六个英文关键字，禁止使用数学符号。
 7. **跳转**：标准SugarCube goto语法。链接格式为双方括号内写“显示文字 箭头符号 目标段落名”。
 8. **变量命名**：美元符号F 代表主角，美元符号E 代表对手，美元符号snap 代表快照，逐字符一致。
 9. **临时变量**：也必须用美元符号前缀。禁止裸用 roll 或 read。
10. **保留字禁令**：禁止使用 read 作变量名，改用美元符号readv。
11. **随机数**：random(1,100)，禁止 either。
12. **排版**：相邻宏之间至少留一个空格。

### 四、完整性校验10项（交付前必过）

 1. 开始节点唯一：1个start节点。
 2. 分支节点：至少2个branch节点。
 3. 结局数量：至少2个结局。
 4. 节点ID唯一：全部唯一，无重名。
 5. 选择目标存在：全部指向已定义节点。
 6. 变量引用完整：全部已定义且有实际用途。
 7. 结局条件可满足：每个结局至少有一条可满足路径。
 8. 路径收束：每条可达路径都能抵达结局，无死循环。
 9. 零假选项：每个选择产生可追踪后果。
10. 视觉Prompt完整：所有关键镜头有独立Prompt行。

### 五、交付清单（必交）

 1. 视频文件（MP4格式）：互动影游演示短片。
 2. 视频脚本、Prompt清单、视觉方案。
 3. 完整互动方案（剧情树、变量字典、多结局路径）。
 4. 互动剧本（逐节点可演版）。
 5. 程序化JSON数据。
 6. 引擎对接配置说明。
 7. 互动完整性校验报告（10项全过）。
 8. 配音台词清单与声线规范。
 9. 角色/场景/道具锚点清单。
10. 承制能力页与演示Demo。

### 六、部署与交付规范

1. 视频文件必须与HTML在同一文件夹，缺一个视频就黑屏。
2. 使用VS Code + Live Server测试，禁止直接双击HTML。
3. 推荐浏览器：Chrome / Edge。
4. 交付时必须附上《DEMO使用说明》，含本地测试与部署步骤。
5. 部署到公网推荐平台：Vercel / Netlify。
