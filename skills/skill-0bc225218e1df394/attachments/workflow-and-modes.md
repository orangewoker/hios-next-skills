# 工作流与运行模式

## 目录

- 输入收集
- 全自动状态机

- 异常与询问规则

## 输入收集

从当前对话和附件中提取已有信息，仅补问缺口。

### 必需输入

| 类别 | 需要锁定的内容 | 处理规则 |
|---|---|---|
| 模式 | 全自动 / 分阶段确认 | 未说明时先询问 |
| 宠物 | 照片或动物描述 | 照片优先级高于文字推断 |
| 创意 | 故事、动作类型、情绪或自动构思 | 用户可明确授权自动构思 |
| 动物行为 | 原生步态、习性微动作、自然叫声和拟人化等级 | 未说明时默认0级自然；打斗/持械/特工等只升到完成动作所需的最低等级 |
| 模型 | 当前可用视频模型 | 必须让用户选择；用户明确授权时可推荐或代选，并说明选择理由 |
| 输出时长 | 视频总时长 | 全自动模式也必须询问；只列所选模型实际支持的时长；用户未明确选择时不得代选 |
| 输出规格 | 画幅、清晰度及界面提供的其他导出项 | 全自动模式也必须询问；只列所选模型实际支持的选项；用户未明确选择时不得代选 |
| 路线 | 一次性 / 多段合成 | 提示质量与点数权衡 |
| 多段音乐 | AI纯音乐 / 不配音乐 / 使用用户音乐文件 | 仅选择多段合成时必须锁定 |

### 已有默认值

- 视觉：真实动物外观、真实摄影场景、电影级光影与特效。
- 动物行为：默认按物种原生运动方式和身体力学设计；习性微动作少量、情境化、可见且不机械重复；除非用户明确要求，不采用完全拟人化。
- 声音：环境音、动作音效、动物叫声、必要对白或配音。
- 音乐：一次性路线默认无音乐；多片段路线必须让用户选择AI纯音乐或不配音乐，也可使用用户提供的音乐文件。
- 字幕与文字：无。
- 节奏：第0—1秒强视听钩子，大幅快速动作、较快切镜与丰富同步音效。
- 分镜：每15秒一张至少8格的极简2D导演预演板，以固定角色颜色、红色取景框、蓝色角色箭头、绿色镜头箭头和分类彩色文字表达导演信息；大特写/近景逐格交替、全部使用荷兰角。分镜板同时驱动电影首帧和视频生成。
- 交付：保留全部中间产物，只输出一个最终视频。

不要重复询问默认值。仅在用户主动改变时覆盖。输出时长、画幅、清晰度和导出规格不属于默认值；即使用户选择全自动，也必须先询问并锁定。

## 全自动状态机

1. `收集`：锁定必需输入；全自动模式也必须询问用户视频输出时长、画幅、清晰度和界面提供的其他导出规格，用户明确选择后才能继续。
2. `规划`：生成内部故事骨架与资产清单。
3. `主角`：生成并自检三视图、身份卡；同步锁定原生步态、身体力学、自然行为、习性微动作、自然叫声、拟人化等级和禁止动作。
4. `世界`：生成并自检场景、配角、道具参考图。
5. `叙事`：生成剧本与文字分镜。
6. `预演`：按每15秒8格生成预演分镜板。
7. `首帧与逐段生成`：一次性路线或多段第一段，以起始预演板生成一张电影首帧。多段路线生成并质检第1段后提取实际尾帧，作为第2段首帧；之后逐段递推，不能并行预生成后续段。
8. `提示词审核`：逐条检查实际提交提示词，修正错误、遗漏、占位符、错误引用与冲突。
9. `视频`：按锁定模型、用户选择的输出时长、规格和路线生成。多段路线必须按顺序执行“生成本段 → 质检 → 提取实际尾帧 → 绑定为下一段首帧”。
10. `音乐决策`：仅多片段路线执行。选择AI纯音乐时描述音乐、选择音乐模型并生成；选择不配音乐时跳过音乐生成。
11. `智能剪辑`：一次性模式检查整片；多段模式逐段检查后，通过智能剪辑合成视频、音效以及用户选择的音乐，优先保持动作连续和画面流畅，不使用无动机淡化或破坏动作的转场。
12. `质检与交付`：完成整片检查，展示中间产物，输出一个最终视频和简短质检结论。

全自动模式中的制作阶段除必要成本/权限确认、重复失败、平台拒绝造成实质改写或能力不可用外不暂停；但在制作开始前必须暂停询问并锁定输出时长与输出规格。

## 分阶段确认状态机

### 门1：剧本

提交：标题候选（不写入视频）、一句话梗概、五要素、完整剧本、动作节奏和声音意图。

确认后：锁定故事因果、结局和主要动作，不随意增删主要角色、地点、道具或效果。

### 门2：角色

提交：主角三视图、身份卡、配角、场景和道具参考图；身份卡必须包含原生步态、身体力学、自然行为、习性微动作、自然叫声、拟人化等级、允许动作和禁止动作。

确认后：锁定角色引用名、毛色花纹、体型、服装、道具、场景地标、色彩方向、动物行为边界和拟人化等级。

若素材生成暴露剧本不可执行问题，只提出最小剧本差异；确认差异后更新锁定版本。

### 门3：分镜

提交：逐镜文字表、每15秒一张至少8格的彩色导演标注预演板、一次性路线或多段第一段的一张电影首帧，以及多段连续性矩阵和尾帧传递方案。预演板必须按大特写/近景逐格交替且禁止相邻重复，全部采用荷兰角；每格标出画面、音效、景别、倾斜方向、运镜和拍摄参数，并使用固定颜色语义。第一段首帧由对应预演板第1格生成；后续段首帧只能来自上一段实际尾帧。

确认后：锁定镜头顺序、动作节拍、运动方向、时长分配和首尾状态。

### 门4：视频

按已锁定选择生成。若多段生成，必须顺序生成：每段通过质量门后提取实际尾帧并绑定到下一段首帧，再继续生成；不得跳过未通过段或并行生成依赖其尾帧的后续段。若重做较早片段导致尾帧变化，作废并从其下一段开始依次重做全部已生成后续片段，先更新点数估算。

### 门5：剪辑

提交拼接点、声音桥接、输出规格和多片段音乐选择。需要AI音乐时同时提交纯音乐描述、音乐模型和混音方案；不需要时明确直接合成。确认后通过智能剪辑完成合成并导出一个最终视频。

## 中间产物清单

按清晰名称保留：

- `character-main-*`：主角三视图与身份卡。
- `character-support-*`：配角设定图。
- `location-*`：场景参考图。
- `prop-*`：关键道具图。
- `script`：最终剧本。
- `shot-list`：逐镜文字分镜。
- `previs-01...`：每15秒一张至少8格的彩色导演标注预演板。
- `first-frame-01`：一次性路线或多段第一段由分镜板生成的电影首帧。
- `handoff-frame-01...`：从每个已通过质检的片段提取的实际尾帧；`handoff-frame-N` 原样作为 `clip-(N+1)` 的首帧。
- `clip-*`：多段生成的原始片段；不要把它们作为最终交付视频。
- `music-*`：用户选择AI纯音乐时生成的纯音乐与提示词；不配音乐时不创建。
- `final-video`：唯一最终成片。

## 异常与询问规则

只有在答案会改变产出或继续消耗点数时询问用户：

- 选择的模型/规格不可用。
- 平台显示的点数消耗与之前信息不一致。
- 同一资产达到重试上限。
- 平台拒绝，且合规修改会改变核心剧情。
- 用户提供的多个宠物图片无法确定哪些属于同一角色。
- 用户提供音乐文件时，需要确认使用该文件、改用AI纯音乐还是不配音乐。

遇到非关键缺口时做保守推断，并在阶段摘要中说明。
