# 提交意图、回执与结果核对

## 触发与最小输入

在真实生成/复合制作调用前、收到同步或异步结果、调用中断、查询/保存失败、取消或考虑再试时读取。仅准备提示词不执行本协议的付费步骤。

最少需要当前 Job 的不可变版本与实际请求、[调度](04-scheduling.md)核对结论、可信项目定位与持久操作位置、当前执行/查询契约、授权链和本次费用上界。Job、Attempt、Take 状态只按[核心记录](../core/03-records.md)解释，本文件不新增平台状态或重复枚举。

## 提交前必须持久保存并读回

按下列顺序操作。保存位置与工具只用当前入口已验证的能力；逻辑 ID、操作标记和可读记录都不是服务端幂等键。

1. **冻结此次输入。** 核对目标、提示词、参数、模型/入口、Director Pack 版本/状态/验收判据及 Binding 的确切版本，实际附件/正文逐行消费[同一映射](../assets/03-reference-binding.md#reference-map)。Seedance2.5完整新请求通过其[七段与分支核对](../platform/04-seedance-25.md#request-presentation)，恢复后准备的新提交同样适用。将所需请求快照、用途、输入源定位、预期结果关联和停止条件附于 Job；与当前版本冲突则返回[变更影响](../core/05-change-impact.md)，不提交旧输入。
2. **建立此次 Attempt 意图及费用预留。** 在可找回的持久位置登记独立 Attempt ID、所属 Job 版本、实际请求、授权链/批准依据、累计尝试依据、此次最大可能费用和单位，以及将发生的副作用。复合工具会创建/生成子任务时，必须有可界定的数量、计费上界和总尝试核算；未知时回[项目契约](../core/01-project-contract.md)，不能用预计耗时作报价。
3. **读回意图与预留。** 核对完整内容、真实存储位置、源版本和费用/尝试占用已经可恢复；核对完成且尚未发出时为Attempt.prepared，不等于Job.ready或已发起次数。不是只看“写入成功”提示。发生截断、写错位置、未决创建或读回失真时，停止提交，按[状态恢复](../core/04-state-recovery.md)处理。存储操作登记与索引提交的具体顺序由该模块负责，不另造原子事务假设。

若当前项目已明确进入[受限小样模式](../core/01-project-contract.md#limited-sample-mode)，正式提交前的持久读回条件仍未满足时，不得把 Job 报为正式 `ready`。每次真实小样调用仍建立范围/模式为 `limited-sample` 的独立 Attempt，并按实际证据使用 `prepared`、`submitting`、`submitted`、`running`、`succeeded`、`failed`、`cancelled` 或 `unknown`；其费用预留、已确认消费和已发起次数进入同一授权链。请求卡在当前会话保存实际选材列表、完整正文/参数、版本、上限、风险和回执位置，并标“未持久化、不可跨会话恢复”；只允许已核来源和无unknown依赖的小样，返回后按用途观察。这个分支不改变正式 Job 的 `planned` 状态，也不释放正式生产的前置缺口。
4. **临提交再核对。** 由单一调度写入者重读当前目标与授权账，核对本Attempt已登记预留仍有效且足够，按[预留规则](../core/01-project-contract.md#attempt-reservation)复用这笔占用而不重复扣减；确认没有其他预留/已发起Attempt或新变更使此次条件失效。按核心记录从prepared保存为submitting并读回；中断后必须按可能已发送处理，不能仅因本地状态尚早而判定无副作用。
5. **发出确切请求。** 使用已核验工具契约提交已保存请求，不临场增加输出、换模型或更改引用。实际输入要改就回到新 Job 版本及新的意图核对。若工具自带重试/多个子操作，先确认其副作用和计费已在授权与预留范围内；无法界定时不能把它视为一次无风险调用。

持久意图不是“保证不会重复”的凭据。平台未提供已验证幂等能力时，本协议通过记录与核对降低风险，不能承诺恰好一次。

模板变化本身不创建新Attempt。已提交/未决/unknown保留原请求格式、参数、Binding、状态、预留与回执，先核原归属；只有尚未提交的草案或已有依据要新建Attempt时才重编译。当前编辑器/用户改稿的快照与原请求按[证据分界](../core/03-records.md#execution-evidence)分别保留，历史旧素材按用途复用，不因升级全量重生。

## 收到回执后的顺序

1. 把真实响应关联回原 Attempt，保存真实任务/节点/媒体定位、接收时间、原始可定位回执及已知终态/运行证据。先保存到可找回的意图/操作记录，再按恢复协议推进索引；回执保存失败时恢复记录，不能再提交生成来“补回执”。
2. 核对归属：它是否确实来自该 Attempt 与 Job 版本，还是旧节点产物、晚到结果或同名对象？来源不够确定时留未决，不以“最新结果”抢占当前版本。
3. **同步入口已给真实终态：**按证据登记，不补造异步等待和轮询。**异步入口仅确认受理/运行：**保存回执后按其真实查询方式有限跟进；工具名称、查询标识、频率和限制来自当前契约，不能从 CLI 语义推定内置 Agent 也相同。
4. 执行成功且有可定位产物时逐项登记 Take；一个 Attempt 可能返回零至多个产物，不把返回数量直接当计费或覆盖完成证据。收到了成功文字却无法可靠确定对应产物时保留证据缺口，不能虚构媒体链接。
5. 将 Take 交[观察与选片](../post/01-observation-selection.md)或[资产验收](../assets/02-asset-build-review.md)。执行成功与指定用途可用分别报告；只有当前 Job 的所需素材/必要覆盖满足时才按核心规则认定目标完成，其他未决 Attempt 和费用仍继续核对。

提示词、请求时长、封面、模型自述及返回 URL 都不能代替对产物的实际观察。旧输入的晚到结果保持原关联，再按[变更影响](../core/05-change-impact.md)审查对新目标的用途，不能自动覆盖当前素材。

## 不确定响应：有限核对，不盲重发

以下是核对路径，不是平台命令。仅使用当前实际存在的入口，并在开始前记本次可用路径、查询成本与停止条件。

| 当前证据 | 可做的核对 | 何时停止这条路径 |
|---|---|---|
| 已保存真实任务/节点/媒体标识 | 按该标识读回，核对请求归属、版本、实际状态与产物 | 路径明确不可用，或本次界限内无新证据；不改用猜测 ID |
| 提交或创建响应丢失，但有已保存操作标记 | 仅在入口支持时，按项目范围与唯一标记查候选，核对输入/时间/归属后认领 | 没有这种搜索契约，或候选不能可靠区分；同名不是充分依据 |
| 只有节点当前位置的结果 | 检查是否属于这次 Attempt，而非先前生成遗留 | 无请求/版本关联依据时不能认领；不把节点非空证明本次成功 |
| 只有总余额变化 | 保留总体费用信息，寻找可归因的账单/回执 | 无法归因时，不当作某 Attempt 的执行或退款证明 |
| 有可靠的运行中证据 | 保持真实状态，按入口和本次有界安排后续读取 | 达到本次查询边界后结束本轮跟进；没有新证据不能把它改为失败 |

已知定位的有效回读路径优先；同一错误没有新线索时不重复消耗。查询上限由当前契约、费用与项目安排确定；契约没有提供有效后续路径时，核对现有持久线索后即收束，不能自行编造后台持续轮询。失去受理/完成/产物归属确定性时才按核心规则保留 unknown；查询次数用完本身不是失败证据。

路径用尽仍不确定时，保存旧 Attempt 的 unknown、已发起尝试计数与费用预留，停止受影响链，交[调度](04-scheduling.md)继续其余可信独立工作。输出具体决定：哪次请求未决、已经核对什么、缺哪个可取得的回执/能力、仍占多少已知上界、哪些下游被挡、哪些可继续。

只有用户另行有界接受同请求仍可能执行/扣费与新请求重复的风险，才可建立同请求的新Attempt。改动输入形成独立新Job时，按现有授权和余额核对推进，并告知旧unknown仍可能完成/计费；必须消费旧结果的依赖仍等待。记录新的批准来源、总尝试/费用边界及其与原授权链的关系；旧 unknown 保持，旧预留和计数不清零。有限核对耗尽不构成自动重试许可。

## 输入异常先辨哪一步有证据

沿[核心状态证据](../core/03-records.md#execution-evidence)读原始请求与回执：明确校验未发出则只记该事实；有真实执行失败终态才据此记失败；受理不明保留unknown及原核对路径。预览、待确认、Agent说“已提交/正常”或媒体存在均不能替代归属证据，不猜计费/退款。

同会话的校验拒绝或一条失败文案不足以证明未发出；可靠未发出依据须能核对完整执行链，由唯一发送者确认未调用生成、未移交他人或队列等。旧意图失效及未发生执行的预留能否核销，按[原预留条件](../core/01-project-contract.md#attempt-reservation)处理；旧记录保留，实际已发生的存储等费用另记。受理不明仍保留unknown及预留，不因本段校验分支释放。

引用异常回[诊断](../assets/03-reference-binding.md#reference-diagnosis)，逐行核本项目对象/版本/用途、实际媒体和当前入口。用户重贴标签、Agent改表、删空格或改名不算新核验；未取得新证据不宣称已修复，不用生成试探语法。新提交只能消费重新成立的映射和原有授权/预留核对；保留旧请求/错误/状态，不能让新快照把历史错误抹掉。

## 已知失败与费用如何处理

| 证据/问题 | 下一决定 |
|---|---|
| 参数、引用或输入错误 | 保留原始失败证据，按上节核实当前契约/Binding；改变请求建立新 Job 版本，再核对授权，不机械重复同一错误 |
| 权限、账户额度或授权不足 | 停止相应提交，明确缺失范围；继续可独立规划，不自行换账户/模型来绕过限制 |
| 暂时网络/服务错误，且真实终态已确认 | 在已有重试授权、费用和停止条件内决定新 Attempt；如受理状态不明则先走未知核对 |
| 平台内容拒绝 | 记录拒绝类别，按平台规则修正内容或选择允许的表达；不设计规避机制 |
| 用户取消或平台取消 | 只有真实回执证明取消才按该状态登记；没有取消能力就不声称取消成功 |
| 技术成功但观感不合格 | 保留成功执行事实与独立用途缺陷，走[返修](../quality/02-repair.md)，不伪记为接口失败 |

失败、取消、超时或质量不合格都不证明未收费或自动退款。只有可归因回执/账单足以证明相关费用结清或不再可能发生，才按[项目契约](../core/01-project-contract.md)释放相应预留。预算核对跨 Job、版本、Attempt 和授权链累计；改名、改提示词、换模型不能恢复已用尝试次数。确认执行失败但费用未知时，两项事实分别记录。

## 可浏览产物与原创纸面例子

每次给用户的是“本次目的、实际提交与回执摘要、结果/观察去向、费用已知与未决、下一步”，附相关可读定位；默认不回显整批原始 JSON。必要时展开单次请求快照和核对记录。

**以下为虚构演练，未提交、未生成、未计费：**修理店主镜 J-master v1 的 A-master-1 在提交后无回执，平台也没有按请求检索的能力。预先持久的意图证明可能发生过提交，不能证明成功或失败。核对完已知位置后仍无法归属产物，则保留 unknown 及其额度占用，停止继承它真实末态的后续段；林岚独立反应镜若引用合格静态资产、剩余额度可信且充足，可由调度继续。若用户另行允许可能重复成本的新尝试，则新建 A-master-2，原 A-master-1 仍保留未决。之后原结果迟到，保存到 v1 的原 Attempt，不覆盖当前新版本。

## 检查、恢复与出处边界

提交前查看“持久意图＋费用预留已读回”是否有真实依据；提交后查看是否保存回执再推进索引；异常时查看是否把超时当失败、是否释放了未经证实的费用、是否重复消费了旧授权、是否把局部未知扩大成全局停摆。发现存储缺口立即走[状态恢复](../core/04-state-recovery.md)，不能让用户反复贴回全表作为正常恢复机制。

[AWS](../evidence/01-sources.md#aws)提供超时、副作用与幂等重试的工程依据；本 Skill 的意图记录、费用预留与有限核对协议为原创适配设计，不能制造平台未提供的查询、取消、幂等或事务能力。当前未验证内容见[LibTV 证据](../evidence/01-sources.md#libtv)及[方法边界](../evidence/01-sources.md#method-boundaries)。
