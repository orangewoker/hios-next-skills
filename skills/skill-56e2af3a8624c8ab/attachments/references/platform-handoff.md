# 平台交接契约

把镜叙生成的视觉方案交给具体平台或模型时，先保留叙事与连续性，再做字段适配。平台名称不是审美参数。

## 交接字段

```yaml
asset_type: still | cover | sequence | video_keyframe | video
input_references: []
prompt: |
  平台中立的完整生产提示词
aspect_ratio: auto | 1:1 | 3:4 | 4:5 | 9:16 | 4:3 | 3:2 | 16:9 | widescreen
duration_seconds: optional
continuity_lock: []
preserve: []
avoid: []
approval_point: before_generation | before_paid_generation | before_publish
```

## 适配顺序

1. 先读取当前环境实际可用的图像、视频和参考图能力。
2. 只映射目标接口明确需要的字段；未知参数不猜测、不伪造。
3. 保留故事拍点、主体数量、空间关系、动作阶段、光向、材质和连续性不变量。
4. 若平台只接受一个文本框，把字段按“事件 → 主体 → 构图 → 光色材质 → 运动 → 约束”合并为一个提示词。
5. 若平台支持参考图，说明每张参考图只负责身份、服装、场景、构图或首尾状态中的哪一项，避免职责冲突。
6. 若当前环境没有生成能力，交付可复制提示词和参数建议，并明确标记“尚未生成”。

## 视频交接

- 首帧必须先通过静帧量表。
- 写明当前支撑、目标接触点、接触发生的时间窗和接触后的稳定状态。
- 单镜头只保留一个主要运动事件；复杂事件拆镜。
- 首尾帧路线分别描述允许变化和必须保持不变的项目。

## 停止条件

遇到登录、验证码、权限申请、额度不足、充值、意外付费确认或发布确认时停止并交给用户。生成成功不等于发布授权或商用许可。
