## 1. 使用原则

提示词不是摄影术语堆砌，而是可执行的导演合同。每条提示词必须回答：画面开始时什么状态、发生一个什么主要变化、摄影机如何见证、画面如何结束、下一镜怎样接。

遵守以下规则：

- 一镜一个主要戏剧动作；
- 抽象情绪必须变成可见或可听事实；
- 固定项、可变项和禁用项分开写；
- 先人物与空间连续，再追求风格；
- 复杂动作先拆分，生成后再剪辑或合成；
- 模型无法稳定执行的意图，不以更长提示词强压。

## 2. 把导演判断翻译成生成事实

不要写“她很紧张”“画面很高级”“有宿命感”。改写为：

- 紧张：回答前吸气中断，拇指反复刮杯沿，视线越过对方肩膀看门，最后没有起身；
- 权力变化：弱势者从画框边缘向中轴移动，掌权者被门框切割，反打景别从近景变为更紧的特写；
- 孤独：人物只占画面右下四分之一，左侧空桌延伸到暗窗，远处冰箱压缩机持续响；
- 危险临近：走廊尽头感应灯依次熄灭，人物停步，画外钥匙碰撞声变近。

每个抽象词至少落实到动作、构图、光线、环境响应或声音中的一项，最好两项互证。

## 3. 资产提示词合同

不同资产不得混用同一模板。

### 3.1 character prompt

character prompt 包含：身份与年龄段、可识别面部结构、体态、发型、妆造、服装层级、材质、常用表情基线、姿态习惯、角色记忆点、禁止漂移项、标准光线和背景。

角色提示词不写具体剧情运动；它负责建立可复用身份资产。

### 3.2 scene prompt

场景资产包含：时代/地域、空间功能、平面关系、入口出口、主要材质、动机光源、时间天气、可交互道具、磨损与生活痕迹、色板、禁用元素、无人状态。

### 3.3 大型复杂场景静帧

当场景包含大尺度环境、多个功能区、明确地标和大量微型活动时，先建立 scene graph，再写自然语言提示词。适用于鸟瞰总览、城市/村落、营地、战场、宫殿群、集市和灾难现场。

按以下顺序组织：

1. **成像合同**：媒介、画幅、视角、俯仰角、是否见地平线、主体规模；
2. **环境边界**：地形延伸到画框何处、外围留白、必须不存在的地貌或现代物；
3. **空间骨架**：主视觉锚点、拓扑关系、数量级、路径、环带、层级或分区；
4. **方向地标**：用画面坐标锁定 2–4 个识别点；使用东/西时同时声明其与画面左/右的对应；
5. **功能簇**：只选择 3–5 个支持世界运行的区域，每簇写功能、物件和可见使用痕迹；
6. **生命与事件**：先写整体人流/交通，再写少量局部行为，避免每个角落都争夺注意力；
7. **光线与空气**：光向、阴影方向、材质响应、烟尘、雾、热浪或天气；
8. **材质与色彩**：主材质、磨损、3–5 个主色及少量强调色；
9. **摄影成像**：真实拍摄路径、镜头/高度假设、景深、曝光、胶片或数字调色路径；
10. **针对性禁项**：按构图、尺度、时代污染、视觉风格和生成缺陷分组。

先划分信息优先级，再决定篇幅：

- **P1 硬约束**：画幅、机位、环境边界、主锚点、空间拓扑和关键地标。放在开头，并在禁项中保护；
- **P2 可识别支持信息**：功能区、主要人群、交通、光向和核心材质。以视觉簇出现；
- **P3 纹理信号**：火星、肉架、脚印、织物花纹、微小工具等。只作为局部暗示，不得损害 P1/P2。

建立尺度—可见性预算：大范围总览中，微型细节应写成“可辨认的活动簇、轮廓或材质信号”，不要同时要求极大覆盖范围和大量近景级细节。若某个微观物件承担剧情信息，则降低机位、缩小覆盖范围或另做插入镜头。精确数量难以稳定生成时，在不改变叙事规模的前提下改为可验证区间，例如“约四十，35–45 个彼此可分辨的单元”。

对幻想或科幻场景做物理化：写清真实织物、木材、皮革、骨、金属、重力、承重、磨损、尘土和人工搭建痕迹，让异常元素像现场存在的实物，而不是概念图或游戏资产。

提交前做摄影逻辑检查：

- 真正俯拍通常看不到天空；把“天空开阔”翻译为“无遮挡地形延伸到画面四边”；
- 禁止某种地形时，不要又用该地形作为摄影机来源；
- 光源方向必须与画面坐标及阴影方向一致；
- 选择“真实胶片拍摄”或“数字拍摄后模拟胶片”中的一条成像链，不要混写互相冲突的流程；
- 机位、俯角和透视决定空间关系；不要仅靠焦段名称表达情绪或规模；
- 详细用户提示词只做结构化、去冲突和定优先级，不擅自增加新区域、人物或剧情事件。

可复用骨架：

`成像合同 → 环境边界 → 主锚点 → 空间骨架 → 方向地标 → 功能簇 → 生命与事件 → 光线/空气 → 材质/色彩 → 摄影成像 → P1/P2/P3 → 针对性禁项`

### 3.4 prop prompt

道具资产包含：尺寸、材质、年代、磨损、握持方式、剧情可见细节、正反侧面、状态变化和禁止变形项。

### 3.5 storyboard still

storyboard still 用来验证叙事构图，不承担复杂运动。包含：镜头编号、画幅、景别、机位高度、焦段感、人物站位和视线、关键动作瞬间、前中后景、光线、色彩、画面信息优先级、连续性锚点。

### 3.6 blocking diagram（调度图资产）

多人、群戏、障碍物分隔空间或多次正反打之前，先做一张高位斜俯视调度图。它服务于几何和连续性，不追求最终美术质感。提示词按以下顺序写：

1. 逐一声明角色、场景、道具、生物和色卡参考各自的锚定职责；
2. 声明高位斜俯视/鸟瞰角度，并明确这是一张 staging/blocking diagram；
3. 按 `foreground → near side → far side → farthest layer` 锁定纵深顺序；
4. 锁定人物位置、朝向、姿势、视线、行动路径和彼此可见性；
5. 标出障碍、出入口、关键道具、视线轴/行动轴和预期屏幕方向；
6. 用光向、投影和材质分离帮助读懂调度，不让气氛遮蔽几何；
7. 禁止交换近/远侧、左右身份、障碍方向或道具相对位置。

调度图批准后，将其作为 `scene/composition anchor` 连接到同一场景的镜头族。不要把它当作漂亮概念图，也不要让下游镜头自行重新发明空间。

### 3.7 minimal-delta asset edit（最小改动资产修正）

当资产已大部分正确、只需删除或替换一个局部时，不要重写完整角色/场景提示词重新生成。使用最小改动合同：

`只改变的对象与位置 → 应如何补全物理材质/光影 → 其余必须完全不变 → 低编辑强度/局部遮罩 → 修改后差异检查`

明确写“change nothing else”，冻结脸、体态、姿势、服装其余部分、构图、背景、光线和色彩。保留原版与修正版；批准修正版后，将它升级为唯一正式 anchor，避免新旧参考同时输入导致旧缺陷复现。

## 4. 视频提示词标杆与单镜头骨架

视频提示词必须描述画面如何从状态 A 因果地变化到状态 B，不得只描述“一张漂亮画面开始运动”。以以下合同作为生成、重写和审查的默认标杆。

### 4.1 先写共享锁定层

在逐镜提示词前独立声明：

`画幅/时长/帧率感/生成模式 → 世界与角色身份 → 场景几何和屏幕方向 → 时间天气和动机光 → 色卡和材质 → 摄影成像链 → 参考资产及版本 → 全场连续性禁项`

这些内容属于项目锁定层或场景锁定层。逐镜只能改写镜头变化层，不得重新发明角色、空间、光向、色板或道具状态。图生视频应优先说明参考图中什么被锁定，文生视频则补足可建立 opening state 的必要事实。

### 4.2 单镜头强制顺序

按以下顺序组织，避免模型把次要信息当主动作：

1. **shot purpose**：本镜改变观众的信息、情绪、关系、空间理解或节奏中的哪一项；
2. **opening state**：开场人物、道具、空间、前中后景、光线和摄影机的确定状态；
3. **trigger + one main action spine**：触发、主要因果动作、速度/节律和停止点；
4. **subject motion**：主体真实世界中的起点、终点、路径、屏幕方向和遮挡关系；
5. **camera motion**：摄影机初始机位、物理路径、操作者反馈、速度和停止点；
6. **composition evolution**：opening → transition → ending 三态中，前景遮挡、中景主体、后景深度和画内相对位置如何重排；
7. **motion hierarchy**：P1 主动态、P2 支持动态、P3 环境微动态各是什么，次级运动不得争夺主动作；
8. **light/environment/sound response**：光、阴影、材质、衣料、烟尘、天气与声音如何对动作产生物理响应；
9. **ending state**：镜头结束时可截图、可复用的最终姿态、位置、道具和信息状态；
10. **handoff**：留给下一镜的视线、动作、屏幕方向、声音、构图或状态接口；
11. **prohibitions**：针对本镜真实风险的 negative constraints 与连续性禁项；
12. **fallback**：首选失败时优先减少什么、固定什么或从哪里拆镜。

压缩公式：

`共享锁定 → 镜头目的 → 开场状态 → 触发/主动作脊柱 → 主体路径 → 摄影机路径 → 三层构图演变 → 动态层级 → 物理视听响应 → 结束状态 → 接力点 → 禁项 → 降级`

默认交付必须显式分成 `[SHARED LOCKS]` 与 `[SHOT CONTRACT]` 两部分，并让上述字段可被逐项定位；不得只把它们隐含在一段流畅文案中。平台要求单段纯提示词时，可以在复制用提示词中合并自然语言，但仍需附一份简短合同审计，证明字段没有丢失。只有用户明确要求极简版本时，才压缩字段标签；压缩不等于省略结构。

### 4.3 构图与动态的最低标准

- **前景**必须有叙事职责：遮挡、框定、速度视差、权力压力或揭示；不得为了“电影感”随机塞物体。
- **中景**承载主要人物、道具或动作，不得被前景长期遮死。
- **后景**提供目的地、威胁、世界运行或运动来源；不是无功能的模糊壁纸。
- 分别写清主体的真实路径、摄影机的物理路径、主体在画框中的相对位置。三者不是同一件事。
- 动态感来自速度差、方向差、遮挡揭示、视差、环境滞后和构图重排，不等于让所有元素同时剧烈运动。
- 每镜只允许一个 P1 动作中心；P2/P3 只负责支持空间真实性和动作力度。

“one main action”指一条可读的因果动作脊柱。不中断长镜头可以有 3–5 个顺序微节拍，例如“受惊 → 四肢着地逃窜 → 试图站起 → 跌倒 → 爬起继续逃”，只要它们都服务于同一目标、顺序不可交换、空间方向一致，并且 ending state 清楚。若出现第二个独立目标、跨时空、换装或需要剪辑重新建立地理，则拆镜。

运动应写成关系而非孤立形容词：分别定义主体真实路径与节律、摄影机物理路径与操作者反馈、主体在画面中的相对位置，以及两者之间的稳定/失衡对比。例如“人物步频稳定，摄影机持续后退，手持起伏与摄影师后退脚步同步，人物基本保持画面中央”。风、烟、尘等环境锚可声明贯穿整镜，不必在每个节拍重复发明。

骨架示例：

> 开场她坐在画面右侧，双手压住未拆封的信，窗光从左后方进入；听见门锁转动后，她只做一个动作——把信推入桌下抽屉。摄影机以胸口高度从中近景缓慢推进至近景，在抽屉合上时停止；她从右侧边缘进入画面中轴，桌面空白扩大。暖色台灯在她手背形成短促反光，纸张摩擦声清晰。结尾她的手仍按在抽屉把手上，视线停在门外，给下一镜保留向左的视线接口。禁止新增人物、禁止信件变色、禁止手指畸变、禁止突然摇移和自动变焦。

### 4.4 平台支持的单节点多镜头

只有在模型/模式明确支持多镜头生成时，才把一段 coverage 放进同一个视频节点。先建立共享空间图和锁定层，再用显式 `HARD CUT` 分段；不要用含糊的“然后镜头切到”。建议限制在 3–5 个子镜头。

每个子镜头都要包含自己的：`戏剧目的 → opening state → 景别/机位/视线 → 可见主动作 → camera → ending state → 与下一段的切点/声音接口`。各段共享并不得改写：角色身份、空间两侧、障碍方向、光向、色卡、道具状态、对白归属和 voice anchor。反打、反应、插入和台词镜头必须由视线、道具揭示、声音或反应形成可审计的因果链。

若模型不支持该模式，或第一次风险探针出现左右交换、背景重建、角色漂移、对白错配等问题，立即降级为独立视频节点，并用批准尾帧、视线或声音桥连接；不要因为用户说“一个节点”就牺牲连续性。

## 5. 首尾帧与交接

### 5.1 first frame

first frame 是动作的物理起点，必须稳定描述：

- 人物位置、姿态和朝向；
- 手与道具的准确关系；
- 视线方向；
- 摄影机位置和构图；
- 光源、时间和背景状态；
- 哪些元素必须保持静止。

### 5.2 last frame

last frame 是动作结果，不是“动作做完了”的空话。明确：

- 人物最终姿态；
- 道具最终位置/状态；
- 构图相对 opening state 的变化；
- 情绪通过什么可见事实落地；
- 是否能直接成为下一镜参考帧。

### 5.3 handoff

handoff 可选接口：

- 视线接：上一镜看向右，下一镜从对应方向承接；
- 动作接：抬手、转身、开门等在剪辑点延续；
- 构图接：形状、明暗块或主体位置匹配；
- 声音接：J-cut/L-cut 或画外声音提前引导；
- 状态接：同一服装、伤痕、湿度、道具和环境变化。

没有 handoff 的镜头，往往只能单独漂亮，难以成片。

## 6. 文生视频与图生视频

### 6.1 text-to-video

text-to-video 适合空间和身份尚未完全锁定、动作简单、允许一定视觉探索的镜头。提示重点：

- 建立清晰 opening state；
- 限制人物数量和动作数量；
- 给出物理环境和动机光；
- 将镜头运动控制为一种；
- 明确 ending state 与时长内节拍。

### 6.2 image-to-video

image-to-video 适合角色、构图、场景和首帧需要严格稳定的镜头。提示不要重复改写参考图全部视觉信息，重点写：

- 参考图中哪些内容锁定；
- 哪个局部开始运动；
- 动作幅度、速度、路径与停止点；
- 摄影机是否锁定或怎样运动；
- 环境的次级响应；
- ending state；
- 防止身份、服装、背景和构图漂移的 negative constraints。

### 6.3 选择规则

- 一致性优先：image-to-video；
- 新空间探索、无固定角色：text-to-video；
- 复杂动作：关键帧/分段图生视频，再合成；
- 强表演特写：稳定首帧 + 微动作，不要求模型一次完成长台词和复杂走位。

## 7. 时间轴提示词

时间轴只在模型或制作流程需要时使用。每段描述一个可观察事件，不写不可见心理。

示例结构：

| 时间 | 画面/表演 | 摄影机 | 声音/环境 | 连续性 |
|---|---|---|---|---|
| 0–1.5s | opening state，人物压住信封 | 固定中近景 | 空调低频 | 信封在右手下 |
| 1.5–3.5s | 门锁响，眼睛先转，身体不动 | 极慢推进 | 钥匙声接近 | 视线向左 |
| 3.5–5.0s | 信封推入抽屉，手停住 | 推进停止 | 纸张摩擦，环境降弱 | ending state 可接反打 |

短镜头优先 2–4 个节拍。动作越多，越应检查它们是否仍属于同一因果脊柱；属于则按顺序写清，不属于则拆镜。

## 8. 负面约束

negative constraints 必须针对真实风险，不堆通用废话。分组写：

- 身份：不换脸、不改变年龄、发型、肤色和体型；
- 服化道：不换装、不增减首饰、不改变道具颜色与数量；
- 空间：不新增门窗、人物或家具，不改变时间天气；
- 动作：不多做手势、不突然转身、不口型乱动；
- 摄影：不自动变焦、不无故环绕、不突然升降或抖动；
- 画质：避免肢体畸变、物体穿模、纹理闪烁、背景呼吸；
- 叙事：不提前揭示信息、不改变 ending state。

每镜优先选择 5–10 条与其风险最相关的禁项。

## 9. 连续性与版本变量

提示词分三层：

1. **项目锁定层**：画幅、帧率感、世界观、角色身份、总体质感；
2. **场景锁定层**：空间、时间、光源、色板、服装、关键道具；
3. **镜头变化层**：动作、机位、景别、运动、ending state。

只允许镜头变化层随镜头改写。所有生成记录引用角色、场景、服装和道具版本号，避免“凭描述记忆”造成漂移。

## 10. 失败诊断与降级

生成失败先分类，再改提示：

- 身份漂移：加强参考资产与锁定项，减少运动；
- 动作失败：减少 one main action 的复杂度，拆成多个镜头；
- 构图漂移：改用 image-to-video，锁定 first frame 和摄影机；
- 镜头运动失控：改固定机位或单一轴向运动；
- 手/道具错误：使用插入镜头、局部参考或后期 composite；
- 空间连续失败：分开生成人物层和环境层，再 composite；
- 表演空洞：回到 scene-truth，把情绪改成刺激、判断与 playable action；
- ending state 不可控：缩短镜头，把结果制作成明确 last frame。
- 单节点多镜头失稳：先减少 `HARD CUT` 段数；仍有左右/身份/场景漂移时改为独立节点，用调度图、尾帧和声音桥维持连续。

### fallback 层级

1. 减少次要环境运动；
2. 固定摄影机；
3. 缩短时长；
4. 一镜拆二镜；
5. 全身改中近景或插入镜头；
6. 人物与背景分层；
7. 用静态帧、声音和剪辑制造动作结果。

## 11. 输出模板

### 单镜头生成合同

| 字段 | 内容 |
|---|---|
| 镜头号/目的 | 本镜改变了什么 |
| 模式 | text-to-video / image-to-video |
| 参考资产 | 角色、场景、服装、道具版本 |
| opening state | 起始姿态、构图、光线、道具 |
| one main action | 触发、动作、速度、停止点 |
| subject motion | 主体起点、终点、真实路径、屏幕方向、遮挡 |
| camera motion | 初始机位、物理路径、速度、停止点、操作者反馈 |
| composition evolution | opening → transition → ending 的前中后景变化 |
| motion hierarchy | P1 主动态、P2 支持动态、P3 环境微动态 |
| 光与环境响应 | 可见的物理反馈 |
| ending state | 最终姿态和信息状态 |
| handoff | 下一镜接口 |
| negative constraints | 本镜高风险禁项 |
| fallback | 首选失败时的降级方案 |

默认外层格式：

```text
[SHARED LOCKS]
format/mode | identity | space/screen direction | time/light | palette/material | imaging | references/versions | continuity prohibitions

[SHOT CONTRACT]
purpose | opening state | trigger/main action spine | subject motion | camera motion | composition evolution | P1/P2/P3 motion hierarchy | physical audiovisual response | ending state | handoff | shot prohibitions | fallback
```

### 资产提示词交付清单

- character prompt；
- scene prompt；
- prop prompt；
- storyboard still；
- blocking diagram（多人或复杂空间时）；
- first frame；
- last frame；
- text-to-video 或 image-to-video；
- timeline（需要时）；
- negative constraints；
- fallback。

## 12. 交付检查

- 提示词是否只有一个主要动作？
- 默认交付是否显式区分 `[SHARED LOCKS]` 与 `[SHOT CONTRACT]`，而不是只把结构藏在自然语言中？
- 这个主要动作是否被理解为一条因果脊柱，而非机械限制肢体次数？
- 多人复杂空间是否先批准了 blocking diagram？
- 单节点多镜头是否经过平台能力门，并用显式 `HARD CUT` 和逐段镜头契约？
- 局部资产修正是否使用 minimal-delta，而非重生成全部已批准内容？
- 是否同时定义 opening state 与 ending state？
- 抽象情绪是否转成可见/可听事实？
- 主体路径、摄影机路径和主体在画框中的相对路径是否被分开定义？
- composition evolution 是否覆盖 opening、transition、ending 三态，并说明前中后景职责？
- 是否只有一个 P1 动作中心，P2/P3 没有争夺注意力？
- camera 与 composition evolution 是否互相一致？
- light/environment response 是否服从物理来源？
- 是否给出可剪辑的 handoff？
- negative constraints 是否针对本镜真实风险？
- 文生/图生模式是否选择合理？
- 失败时是否有 split、composite 或 fallback 路径？
- 提示词是否继承正确的角色、场景和道具版本？
