# 建筑风格智能适配器

## 输入优先级

1. 用户上传建筑图片：锁定外观、角度、材料、比例和细部。
2. 用户指定建筑风格：锁定风格语言和材料方向。
3. 建筑名称：补足身份、典型构件和合理施工层级。

名称与图片冲突时，不擅自混合，必须说明冲突并让用户指定优先级。

## `building_profile` 生成规则

| 类型 | 识别重点 | 合理建造层级 |
| --- | --- | --- |
| 中式宫殿/寺观 | 台基、柱网、斗拱、梁架、屋顶、彩画与瓦作 | 地基 -> 台基 -> 柱网 -> 梁架/斗拱 -> 屋顶骨架 -> 瓦作与立面 -> 收口装饰 |
| 哥特/欧式教堂 | 石砌基础、拱券、立柱、扶壁、尖塔、彩窗 | 基础 -> 墙体/立柱 -> 拱券/扶壁 -> 屋顶/尖塔 -> 窗与立面 -> 装饰收口 |
| 巴洛克/古典建筑 | 对称台基、柱式、梁楣、穹顶/屋顶、雕饰 | 基础 -> 平台 -> 柱式主体 -> 梁楣/承重 -> 顶部 -> 立面雕饰 -> 收口 |
| 现代主义/玻璃建筑 | 基础、结构框架、楼板、幕墙、屋面、入口细部 | 基础 -> 核心/框架 -> 楼板 -> 幕墙 -> 屋面 -> 入口与细部 -> 完成 |
| 日式传统建筑 | 石基、木柱、梁架、屋顶、障子/木格、庭院近景 | 基础 -> 台基 -> 木柱梁架 -> 屋顶 -> 墙面/木格 -> 收口细部 |

未列类型时，根据建筑的体量、主承重系统、顶部形式、立面材料和特色构件推导同样清楚的 6-8 层建造逻辑。

## 提示词改写合同

每张提示词都要填入 `building_identity`、`architecture_style`、`silhouette`、`construction_layers`、`material_palette`、`context_policy`、`environment_mode` 和 `environment_policy`。保留统一 2.5D 斜侧俯视、居中、单体建筑、清晰构图这些跨建筑不变的约束；把结构层级、材料、特色构件和环境模式按建筑实际重写。

## 环境模式适配

| `environment_mode` | `environment_policy` |
| --- | --- |
| `model_showcase` | 干净、克制的近距离基础环境；不出现人流、车流、城市街景或复杂背景，重点是建筑本身。 |
| `real_environment_timelapse` | 真实可信且与建筑身份/时代相符的地点环境：道路、广场、植被、邻近尺度与远景必须稳定。历史建筑可使用当代游客步行与合规道路车流，但不混入不合时代的建筑；现代建筑使用合理城市人行道与车道。视频中人流车流是背景延时摄影元素，不抢占建筑主体。 |
