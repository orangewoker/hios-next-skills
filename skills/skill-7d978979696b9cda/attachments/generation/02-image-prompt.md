# 把资产与镜头意图编译为图像请求

## 触发与最小输入

在制作身份/状态/空间参考、镜头关键画面、视觉探索或局部图像返修时读取。正式资产或正式候选的最少输入为已标 `accepted-for-generation` 的[导演质量闸门](../core/02-routing.md#director-control-gate)版本、明确的图像用途、当前导演/分镜或资产设计版本、保持与允许变化项、参考来源及用途资格、目标模型与执行入口。缺真实引用或参数契约时可以完成文案，但须标“请求草案，待绑定/能力核验”；没有导演闸门只能标 `exploration`，不能直接落版为正式母板或正片候选，补齐用途设计、实际观察和闸门后可按[核心五值](../core/03-records.md#director-pack-record)判断晋升。

用户意向为 Lib Image、Seedream 5.0 Pro 时保留名称；分别读取[Lib Image](../platform/02-lib-image.md)、[Seedream 5.0 Pro](../platform/03-seedream-5-pro.md)。不得由旧缓存缺席推断模型不存在，也不把 Lib Image 自动映射为 GPT Image 2，或把 Pro 写成 Lite 参数。

## 先决定这张图要解决什么

| 图像目的 | 重点表达 | 避免的误用 |
|---|---|---|
| 身份/基础设计 | 可辨特征、关键结构及足以看清它们的观察条件 | 给所有图套复杂气氛光和极端表情，掩盖需验收的身份 |
| 状态变体 | 父资产身份、准确的服装/湿损/伤势及生效时段；其余可变项 | 说“一切保持不变”同时要求换装，造成输入自相矛盾 |
| 空间/关键道具 | 需要显示的结构、地标关系、可接触面和机位用途 | 把画面左右当世界位置，或靠装饰词掩盖不可行的布局 |
| 镜头关键画面 | 本 Shot 的观看理由、动作相位、构图、注意力和光源 | 用单张画面证明整段动作或表演顺序已实现 |
| 视觉探索 | 一个要比较的创作问题及有意义的方案差异 | 未经选择将实验外观写成全片已定风格 |
| 局部编辑 | 精确缺陷、拟改范围、必须保留的源特征和验收项 | 未核验编辑能力却杜撰遮罩、区域控制或强度参数 |

具体图的形式、可填写模板与完整例见[人物/表演](../assets/04-character-and-performance-templates.md)、[场景/调度](../assets/05-scene-and-blocking-templates.md)、[道具/交互](../assets/06-prop-and-interaction-templates.md)，本节沿用同一请求卡编译，不复制一套字段。人物身份母板默认单图；设定板整板探索须逐区说明职责，无头正面区只供服装，不作人物整体或复制成多个演员。必要背面/脸部单图优先复用清楚的合格源，否则按真实可用提取/派生路径制作，不假造ROI语法。首次设计不等已有母板。

空间请求写新观察位置、观看方向、固定地标、盲区设计提案及阶段/光源，不能只写反打或左右互换。图例编号映射角色，箭头、人偶色仅作说明不进入成片。参考超限先按[必要事件与容量](../assets/03-reference-binding.md#reference-capacity)核图像入口自身限制，多职责候选逐用途观察。

## 编译与校对

从已选设计提取必要信息：主体与职责、当前状态、空间/视角、光源/材质、要保留和允许改变的内容、使用目的。组织顺序服务于本任务，不强制每个提示词填满所有栏目。风格术语只有能改变可见决定时才保留；名导演、画师或“电影感”等标签不能替代这些决定。

参考职责与实际参数分开：文案说明“此图只供身份，照明随本场改变”；[Binding](../assets/03-reference-binding.md)负责真实素材定位与引用映射。调用参数只来自当前模型与入口契约，包括媒体类型/数量、尺寸、输出数量、编辑方式等实际暴露项。没有证据就不填写推测数值，也不把提示词中的参数样式当工具字段。

<a id="image-spec-check"></a>
同一图像请求卡须保留资产输出类型与所需形式：把默认母板/设定板等目标、正文版式与比例，逐项对照当前入口已暴露的ratio、size或等价尺寸/比例字段。正文写9:16身份母板而实际字段为3:4时，先按当前有效目标统一再发，不以字段可提交代替规格一致。字段名及取值只按真实入口，不照抄此处名称作为调用语法。

入口没有独立尺寸字段但确实支持文字表达时，按其真实方式提交已授权请求，记录比例控制的限制，不臆造字段或一律阻断；只能提供替代规格时，说明实际值、与目标差异和未满足用途，不冒称默认图组合格。结果仍须按实际尺寸与可见内容验收；文字意图不是精确尺寸证明。

若源设计互相矛盾，先回[资产规划](../assets/01-asset-planning.md)或[风格设计](../visual/01-style-art.md)作决定；不让提示词擅自裁决故事事实。约束只针对会伤害用途的偏差，例如伤势换边；不堆砌全能否定词或承诺“零漂移”。

## 可浏览产物与原创短例

交付“图像请求卡”：用途与目标版本、已选模型/入口、紧凑提示词、来源/Binding 清单、已核验参数与未知项、待观察判据。用户可直接阅读关键文案，完整工具结构仅用于实际调用，不用 JSON 替代展示。

**纸面例子，尚无引用图片，未提交生成：**

> 为修理店夜场准备林舟的工作服状态参考。沿用已选身份设计的可辨轮廓与面部特征；他穿本场工作服，肩包仍背着，双手自然放低。以能清楚查看面部、领口和肩带的角度呈现，背景简洁，照明柔和，保留衣料质感。此图供身份与服装检查；正片中的机位、动作与店内灯光另按镜头设计变化。

这段文案来自“邀请前尚未卸包”的场状态和资产用途。实际提交仍需合格母版、Binding 和入口参数；文案本身没有完成绑定。若为“钥匙落桌”关键画面，应改写为具体动作相位与空间，不沿用这套身份图组织方式。

## 检查与返修

提交前检查：每个要求是否对应设计来源；身份与状态是否冲突；所要展示的部位是否可见；是否加了未授权的新人物/道具/故事事实；按[同一请求规格核对](#image-spec-check)检查正文与实际尺寸字段一致；参数与参考是否可执行。通过后进入[调度](04-scheduling.md)和[提交核对](05-submit-reconcile.md)。

返回后按[资产制作与验收](../assets/02-asset-build-review.md)看实际图，不用提示词自检代替结果验收。图像没有实现正确文案时，比较换候选、局部编辑或有界再生成；源要求错误时回源修订。每次改变提示词、参数或参考建立新 Job 版本，沿用同一授权累计，详见[核心记录](../core/03-records.md)与[返修](../quality/02-repair.md)。

## 出处与适用边界

[S06](../evidence/01-sources.md#s06)、[S07](../evidence/01-sources.md#s07)支持状态与空间设计；上述编译顺序、检查项与短例为原创方法。模型能力以[模型证据](../evidence/01-sources.md#models)和[LibTV 入口证据](../evidence/01-sources.md#libtv)为界：发布说明可提示可能的能力方向，未取得正文的指南不能被转述成已验证提示词规则。本文件不保证多图身份完全一致，适用性须由实际用途观察决定。
