# 迭代工作流与版本选型 · Iteration & Versioning

本文档是 MJ Prompt Expert 的深度参考，覆盖四步迭代工作流、Describe 学习工具、以及版本选型指南。

---

## 一、四步迭代工作流

生成一张四宫格然后接受结果，是抽奖行为。专业化的 Midjourney 使用遵循一个刻意的循环。

### 第一步：快速探测

V8.1 标准分辨率模式下约 4 秒出一张，利用这个速度生成多个高 chaos 和适中 stylize 的网格来遍历可能性空间。

| 参数 | 推荐值 | 目的 |
|------|--------|------|
| `--chaos` | 50–80 | 遍历可能性空间 |
| `--stylize` | 适中（100–200） | 平衡控制与创意 |
| 分辨率 | 标准 | 快速便宜 |

**在这个阶段不评判单张图片的优劣，而是评判方向：**
- 这个构图家族是否可行
- 那个光线方案是否对味
- 这种色温是否匹配需求

### 第二步：锁定后收敛

当出现有希望的方向时，开始单变量迭代。

| 参数 | 调整 | 目的 |
|------|------|------|
| `--chaos` | 降至 20–50 | 收敛 |
| `--seed` | 锁定最强候选的种子号 | 隔离变量 |
| `--stylize` | 根据需要微调 | 精细控制 |

**单变量迭代原则——每次改动隔离一个变量：**
- 改变光线，重新生成
- 改变镜头，重新生成
- 改变色彩调色板，重新生成

> **同时改变三个变量的调试是无法归因的行为**，在长期来看反而更慢。每次改动隔离一个变量，结论才干净——知道究竟是哪个变量驱动了画面变化。

### 第三步：精修而非重来

使用 **Remix 模式**在最强候选上进化，而非推倒重写。

**Remix 提示词示例：**
```
keep the composition but make the lighting warmer and add morning fog
```

这条 Remix 提示词同时：
- 守护了已成功的部分（构图）
- 定点修改了有问题的地方（光线、氛围）

> 这比从零重写提示词的效率高出一个数量级。

### 第四步：HD 定稿

当构图、光线、风格都已锁定，点「Run as HD」输出最终 2K 成品。

| 阶段 | 分辨率 | 原因 |
|------|--------|------|
| 探测 / 收敛 / 精修 | 标准 | 快速便宜地探索 |
| 定稿 | HD（2K） | 交付质量 |

> **不要在探索阶段支付 HD 模式的 4 倍 GPU 成本。** 标准分辨率存在的原因就是快速便宜地探索。HD 是为交付服务的，不是为发现服务的。

## 二、Describe——反向工程的提示词学习工具

Describe 是 Midjourney 内置的图像转文本功能——上传一张图片，模型返回四条可能复现该图的提示词。

### V8.1 的关键变化

V8.1 版本的 Describe 返回的提示词不再是逗号分隔的关键词堆砌，而是自然语言的描述性句子。这恰好与 V8.1 模型本身的提示词偏好（描述句优于标签堆）对齐。

### 正确用法

Describe 的正确用法**不是**让它代替自己写提示词。它的正确用法是当作**风格词汇学习工具**。

**工作流：**
1. 将一张喜欢其调性但无法准确描述的画面拖入 Describe
2. 观察它用什么语言来拆解光线、构图、色彩和材质
3. 连续对同一张图运行 Describe 两到三次（每次输出都不同）
4. 收集其中反复出现的共同术语——那些就是 V8.1 对这类画面的「视觉关键词汇」
5. **将这些词汇纳入自己的提示词写作中，而非直接复制 Describe 的输出**

### 写-测-缩-跑反馈闭环

Describe 加 Prompt Shortener（提示词缩写器，V8.1 中提示词超出长度限制时自动触发）构成了一套完整的反馈闭环：

```
写一条详细描述
  → 用 Describe 反过来分析自己生成的图，看模型实际理解了什么
    → 用 Prompt Shortener 压缩到可控长度
      → 再跑新一代
```

## 三、版本选型

### V8.1 Alpha（当前默认版本）

**推荐用于几乎所有工作。**

| 特性 | 详情 |
|------|------|
| 分辨率 | 原生 2K |
| 速度 | 比 V7 快约 5 倍 |
| 提示词遵循度 | 显著改善（有效解析窗口约 1300 字符） |
| 文字渲染 | 引号内短文本渲染改进 |
| 图像提示词 | 已恢复（V8.0 中曾暂时不可用） |
| 视觉美学 | 重新校准以匹配 V7 的标志性风格 |

> V8.1 的视觉美学经过重新校准以匹配 V7 的标志性风格，回应了社区对 V8.0「丢失了 Midjourney 的灵魂」的反馈。

**适用场景：**
- 写实摄影
- 复杂多元素场景
- 任何包含文字的提示词
- 需要高分辨率最终输出的项目

### V7

仍然可用，且在特定工作流中仍有价值。

**适用场景：**
- 围绕 Personalization 配置文件与 Moodboard 做了大量调校的项目
- 拥有产出稳定且品质一致的个性化配置文件
- 不需要 2K 原生输出

> V7 的提示词风格比 V8.1 更偏好短促的高信号短语。

### Niji 7

动漫和插画专用模型。

| 特性 | 详情 |
|------|------|
| 专用领域 | 动漫、插画、动画、漫画 |
| `--style expressive` | 响应更好 |
| `--creative` 模式 | 响应更好 |
| `--weird` | 在主模型上效果有限，但在 Niji 中表现出显著的创造性差异 |

**适用场景：** 任何插画、动画或漫画风格的输出。

## 四、版本选择决策树

```
需要动漫/插画/漫画风格？
  ├─ 是 → Niji 7
  └─ 否 → 需要高分辨率(2K)或包含文字？
            ├─ 是 → V8.1 Alpha
            └─ 否 → 已有稳定的 V7 Personalization + Moodboard？
                      ├─ 是 → 继续用 V7
                      └─ 否 → V8.1 Alpha
```

## 五、迭代检查清单

每次迭代时对照以下清单：

- [ ] 是否锁定了 `--seed`？（未锁定则无法归因）
- [ ] 本次只改变了一个变量吗？（同时改多个无法归因）
- [ ] 探索阶段用的是标准分辨率吗？（不要在探索期付 HD 成本）
- [ ] 收到方向后 `--chaos` 是否降低了？（探测期高，收敛期低）
- [ ] 写实场景是否加了 `--style raw`？
- [ ] 画幅比 `--ar` 是否显式设定了？
- [ ] 最终定稿是否切到了 HD？
