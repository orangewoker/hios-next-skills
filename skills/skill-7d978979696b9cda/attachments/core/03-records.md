# 核心记录与状态契约

在建立正式版本、生成任务、素材引用、恢复或审查时读取。创作草案可先自由探索；只有被选作生产依据、对外约定或下游引用时，才登记为正式记录。记录服务于决定，不要求先填全表才写戏。

本文件是术语、状态枚举和记录身份的唯一责任处；其他模块使用这些定义。它们是本 Skill 的逻辑记录，**不是 LibTV 的工具名、字段名或数据库 schema**。按已验证存储能力保存为可读 Markdown 或工具要求的结构。没有脚本也能逐项核对，但未实际计算就不能称为哈希校验。

## 通用信息与版本

正式记录保留稳定 ID、类型、版本、所属项目及适用集/场/故事时段、来源、决定及理由、所引用的确切版本、真实存储定位和更新依据。未知信息写“未知＋影响”；不编造定位符。未持久化的内容标草案，不冒充可恢复记录。

显示场号、集序和镜头顺序可以变；稳定 ID 不随重排更名。修改引用依据、创作目标、生成输入或已发布正文时建立新版本，保留旧版。当前索引指向已核对版本，不能以“最后收到”代替“当前有效”。短小记录可同页分块，长篇按集/场组织；不强制每条记录一个部署文件。部署文档数与运行项目的记录数是两回事。

来源区分用户原文、用户决定、创作推断、外部资料、工具回执、产物观察。草案中的时长/机位/动作是计划；观察到的时长/事件另记，不能覆盖来源后假装计划已实现。

## 不是一一对应的单位

Scene 是戏剧单位；Shot 是观看与摄影单位；Job 是版本固定的制作请求方案；Attempt 记录一次提交的准备与真实执行；Take 是实际返回；Clip 是选中源区间；Timeline 是选段的装配关系。一次生成可能含多个Shot，一Shot可由多次生成挑选或合成实现。多Take之间不能假设表演天然同步。每个Clip都要说明承担的必要事件，完整性由场级覆盖核对，不由素材数量证明。

同Job的相同请求再提交建立新Attempt。提示词、参数、参考或目标改变建立新Job版本，再建Attempt。每次都链接同一授权链；换版本、改任务名、换模型不会重置累计次数/费用。一个Attempt可返回零至多个Take，先保留原关联再逐项观察。

<a id="director-pack-record"></a>
## Director Pack 与产物结论

`accepted-for-generation` 是 Director Pack 自身的放行状态，必须记录版本、适用级别、核对者/时间、事件映射、空间/引用依据和验收判据；它不是 Take 的质量结论，也不替代后续实际观察。正式请求卡、Job、Attempt、剪辑候选和晋升记录都回显所消费的 Director Pack 版本。

产物与用途审查只使用本文件的五值：`unreviewed`（未审）、`acceptable`（该用途范围合适）、`repair`（须修复才满足指定用途）、`unusable`（该用途不宜使用）、`unobservable`（缺所需观察手段）。导演闸门结果不得另造 `accepted` 或 `rejected`；导演选择不通过时，用 `repair` 或 `unusable` 记录具体原因。

<a id="execution-evidence"></a>
## 界面事实与执行状态分别记录

沿用本文件原状态枚举，不把界面词新增为生产状态。规划ID、待确认/预览卡、节点已创建、请求已受理、媒体存在、媒体已观察是不同证据：预览不能证明提交；节点有旧媒体不能证明当前Attempt成功；只见封面/时长不能证明完整声画合格。按真实回执核是否发出及归属；只确定校验未发出时保留准备/校验事实，不虚构失败任务或已发起次数；无法确定是否受理时按原规则保留unknown，不能凭文字总结“进度正常”。

实际请求快照归原Attempt；当前编辑器草稿/槽位快照另记观察时间、对象版本及是否能关联该请求。用户改稿或重排附件不反向更新历史输入，当前存在也不证明历史存在。旧记录的缺口和后来新增证据分别留存；真实终态、费用结清和用途资格各有依据，不互相推导。

<a id="continuity-snapshot"></a>
## 故事时点快照与图组索引

ContinuitySnapshot是逻辑记录职责，不要求平台提供数据库表/schema；按实际可保存并回读的Markdown条目或节点存储，可与其他记录同页但须独立标识和定位。保留稳定快照ID、记录修订、剧本/集/场版本、故事日期/时点、变化事件、父状态与证据来源；同故事时点的制作纠错建新修订，旧版保留。

分别列计划状态、实际候选Take观察、最终Clip出点（确切源版本、区间和时基），不能拿计划或Take末尾代替选段出点。状态链接角色服饰/伤势/声音、场景布局/光源/陈设、道具持有/位置/开合及知情变化；缺观察维度明确保留，不猜出点。

场末/集末保存叙事末段的实际选段出点索引，以及故事各相关时点的快照。非线性剧集可以以闪回结束，不能用最大故事时间、最新生成时间或最后播放的状态通用于下一场；按下一场故事关系与真实接续职责选对应快照。Checkpoint记录生产更新时间、当前工作与这些真实位置，不把它本身当最新故事状态。

Asset图组索引保留实体身份、故事状态与制作修订的区别，列图的形式/用途、当前消费者、覆盖阶段、设计前置或直接输入职责、真实文件/图内区域、来源版本与资格、缺项及延后触发。依赖边注明身份、布局、外观、道具设计、故事状态或实际引用用途；具体模板负责出图标准。恢复与影响分别交[Checkpoint](04-state-recovery.md)和[Change](05-change-impact.md)。

<a id="production-purpose"></a>
## 正式与探索的任务范围

正式批次是本轮已承诺将产物用于当前正式作品、稳定生产依据或指定接续来源来推进的任务范围。明确探索针对当前限定的创作/能力问题，写明范围与停止条件，结果保持候选，不自动投入正式链。按实际决定和当前消费者判断，不按名称、是否付费或未来可能被采用来分；已经承担正式用途的任务不能仅贴“探索”标签绕过前置。两者都遵守实际能力、授权、费用与次数约束；这是用途范围，不是新增状态枚举。能力缺口下的受限小样必须另记会话、上限、风险和未持久化状态，不能把它改称正式批次。

构建或补齐前置资产的Job，即使是用户直接要求的正式资产交付，也只等待它实际消费的上游设计/合格源及该任务的执行条件；正要生成的本图、须由本图派生的下游整套图组不作自身前置。从零身份母板可从已明确的文字设计起步，取得并观察身份源后，再派生同身份设定板/必要补图；相关正式镜头批次仍须本用途必要图组与设计核对完成，不能借“构建资产”或“探索”名称放行缺前置的视频。

首次身份、声音或视频探索不等待尚不存在的同类合格产物，也不要求全季资产先齐；只核本任务真正需要的设计、来源和执行条件。探索产物之后补足拟正式用途的设计/图组，核实际素材、故事/制作版本及所需确切出点，逐用途验收并记录采用决定和依据，才可晋升适用来源；沿用原Take/Attempt及费用记录，不因晋升虚增生成次数。相关路径见[资产验收](../assets/02-asset-build-review.md)与[空间设计消费者](../assets/05-scene-and-blocking-templates.md#scene-consumers)。

## 状态的唯一枚举

### Job 计划状态

| 状态 | 含义与变化依据 |
|---|---|
| planned | 制作意图已登记，执行条件尚未全部满足 |
| ready | 当前目标/引用/能力/持久性/授权条件已核对，可发起下一次有界Attempt |
| active | 有已发起Attempt或正在处理结果；不能只读最新回调推导其全部状态 |
| complete | 当前版本目标所需素材/必要覆盖已满足；其他未决Attempt和费用仍须核对 |
| superseded | 目标或输入已被新版本替代，不再提交；其Attempt保持真实状态 |

planned可在条件满足后ready；ready条件失效则退回planned或被新版本superseded。active在仍需同请求的新尝试且授权/依赖重新满足时可ready，在目标满足后complete。complete若因新证据推翻素材资格、但目标和输入不变，回planned并重新核对执行条件；若目标或输入改变，旧版superseded，新版本从planned开始。保留更正原因，不改写旧验收历史。Job上的“目标是否满足”与“所有尝试是否结清”分别报告。

### Attempt 执行状态

| 状态 | 进入依据 |
|---|---|
| prepared | 此次意图与预留已保存读回，尚未发出提交 |
| submitting | 正要/正在发出真实调用；中断不能据此推断未提交 |
| submitted | 已获真实受理回执，尚未确认运行 |
| running | 真实返回表明运行中 |
| succeeded | 真实终态证明执行成功；不代表质量合格 |
| failed | 真实终态证明执行失败；不代表未收费 |
| cancelled | 真实回执证明取消；不代表退款或从未运行 |
| unknown | 是否受理/完成或对应产物不能可靠确定，保持未决及预留 |

prepared描述这次意图的准备事实，不是可执行许可；目标有效且临提交条件再次核对后才进入submitting；尚未发出的prepared不计入已发起次数，已登记的预留仍须核算。异步按实际回执经过submitted/running；同步直接返回终态时可从submitting进入终态，不补造中间轮询。submitted/running在状态可靠时不因本次查询上限到了就变failed；只有失去确定性时按证据记unknown。unknown凭可靠回读转为已知真实状态，不因查无结果转prepared或failed。任何再次提交都是新Attempt。迟到证据纠正历史状态时追加解释及回执，不能隐去以前的不确定性。

旧记录迁移只处理类型明确且确为“意图已读回、尚未发出”的Attempt.ready，将当前解释记为Attempt.prepared并保留旧词和核对依据；Job.ready不变。类型或实际提交事实不明时先按[恢复](04-state-recovery.md)核对，不能借改名把submitting或unknown变回未提交。目标或输入改变时旧Job按版本规则退出执行，旧prepared意图保留其归属且不得再发出；新目标另建Job版本与Attempt。

### Take/用途审查结论

以上五值是唯一的 Take/用途审查结论。结论逐“素材版本＋区间＋用途＋维度＋证据/审查者”记录，不存在可通用的全局accepted。

只取已观察身份图，不强迫声音也合格；消费实际动作末态，必须有相应末态观察；消费声画接续，必须覆盖所需声与画。用户接受某个未观察风险时单列决定，不把unobservable改写为已观察通过；这也不能创造必需的真实末态或工具能力。资格检查入口见[参考绑定](../assets/03-reference-binding.md)。

### Capability 证据状态

`documented`：某作用域有可定位说明，未完成对应执行验证。`verified`：确切入口/版本/范围有真实操作与回读/观察证据；只对已测部分成立。`unknown`：证据未取得、过时、新鲜度不明或结果不足。`unavailable`：当前入口/账户/操作有明确不可用证据，注明条件与日期；不推广到所有平台版本。文档与实际证据冲突时保留两者并收窄可用范围，不能默默挑有利条目。

## 可读记录范例

以下均为虚构演练，无平台ID、产物或计费：

> Job J-door v2：实现 S-repair 的 Sh-master 中“邀请之后才卸包”；引用 Asset 林舟工作服 v1；等待身份/服装用途观察。状态 planned。  
> Attempt A-door-1：若实际提交则归属 J-door v2；现在尚未建立可提交意图。  
> 计划接续：主镜看到钥匙落桌；反应镜允许改变机位，保持此刻钥匙在桌角、包尚在肩上。没有真实Take，因此没有实际出入点。  
> 覆盖：钥匙交还、邀请、决定留下、坐下均是必要事件；同一镜可承担多个事件。

生成意图保存在[提交核对协议](../generation/05-submit-reconcile.md)指定的持久步骤中；预算由[项目契约](01-project-contract.md)管理；恢复依[状态恢复](04-state-recovery.md)。本定义是本项目架构的原创系统设计，状态名不是平台枚举。[来源与证据边界](../evidence/01-sources.md)保留工程方法与专业工艺出处。
