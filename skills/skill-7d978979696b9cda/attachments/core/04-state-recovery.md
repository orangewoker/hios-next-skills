# 持久记录、检查点与恢复

新项目初始化、正式依据写入、索引更新、换会话、超时或恢复时使用。输入为真实项目定位、已知可读索引/操作登记、当前存储契约和未决记录。不能要求用户把六表或全部剧本反复贴回；对话摘要只导航，主记录必须来自被证实可找回的项目存储。

## 先确认保存能力

从[平台能力](../platform/01-libtv-capabilities.md)确认：定位项目入口、保存文本/媒体引用、按已知ID完整回读、保留旧版本、更新索引，以及按项目范围/唯一操作标识查找未知ID记录。这是不同能力，不因一个“保存成功”全部升级verified。真实工具不存在的文件系统、数据库、脚本、事务或内容哈希不能成为假装可运行的前提。

若只能保存文本节点，可把逻辑记录作为可读Markdown分块，索引保存真实节点定位。实际可读容量、截断和更新语义要有证据；分块不等于丢掉原文。若写入/回读不可靠，暂停依赖持久状态的长篇付费生产，继续独立研究/创作草案并明确未持久化。不能把“让用户贴回”当常规后端。

## 可恢复写入顺序

这是由Agent遵循的操作协议，不承诺服务端原子事务。

1. 从可再次定位的项目入口读取当前检查点和操作登记，确认项目/版本；首次初始化须有可找回的项目位置或唯一标记，不能只靠会话记住新随机ID。
2. 在已知可回读位置保存此次操作意图：操作ID、项目范围、拟写记录/版本、依据版本、预期内容/用途、后续索引动作。读回确认后才进行正文创建或更新。
3. 保存新记录并保留旧版本。收到真实定位后立即回写操作登记；读取新正文及必要媒体引用，核对完整性/版本/关键约束。无实际计算工具时称逐段比对，不伪造摘要。
4. 只有新记录内容已核对，才创建/更新指向它的检查点与索引；保留前检查点。读回新索引并确认指向真实记录后，才宣布该版本已提交为当前依据。
5. 记录操作完成与残余问题。任何中间失败都保留操作意图、旧检查点及已取得的真实ID，不重新执行整套创建来碰运气。

生成Attempt的提交意图、费用预留和回执同样通过这一可靠路径保存；具体调用顺序由[提交核对](../generation/05-submit-reconcile.md)负责。没有“先提交后补记账”的快捷分支。未证实可靠并发写入时由单一调度写入者更新索引，逻辑独立不等于多写入者安全。

场末/集末在已核对的真实位置保存[故事时点快照](03-records.md#continuity-snapshot)，再按上面顺序更新Checkpoint中的快照/叙事末段出点索引。恢复先辨剧本版本、故事时点、快照修订与生产更新时间，分别取计划、候选观察和选段出点；闪回结尾不以该集最大故事时间代替。缺定位只报未持久化，不能让用户重贴全表当常规恢复后端。

## 按断点恢复

| 读到的事实 | 下一步与成功判据 |
|---|---|
| 新索引可读且所指版本完整 | 核对版本/依据及未决Attempt，再从可信依赖继续，不全量重建 |
| 正文已保存，操作登记有真实ID，索引仍旧 | 按ID回读并对照意图；匹配则补提交新索引并读回，保留旧检查点 |
| 操作登记存在，创建回执/新ID丢失，但有项目内受限检索 | 用唯一操作标识、拟写版本和预期内容找候选；唯一匹配才认领并补登记，零候选不是“未创建”证明，多候选不能随便选 |
| 新ID未知且没有受限检索/可靠回执恢复 | 明确孤立记录无法自动发现，保持该操作未决；停止该记录链，不重复建相同对象；已有可信独立记录可继续 |
| 只有旧索引，没有操作登记或新ID | 只能恢复旧版已知内容，不能称找回最新稿；可形成明确基于旧版的候选，更新当前正式依据须找到证据或获得具体分叉决定 |
| 已知ID回读截断、内容不匹配或索引归属不明 | 停止消费受影响记录，保留原证据；核对确切版本和存储限制，不用摘要补全正文后声称一致 |
| 初始入口自身丢失且无定位办法 | 初始化恢复未通过；提出缺少的项目定位/真实回执，不宣称后续协议已经保护首次创建 |

从旧版另开新分支是用户可选择的恢复策略，必须说明未纳入的版本与影响；不是成功找回丢失正文。恢复摘要列当前可确认版本、未决记录及范围、已结算/未决额度、可继续项和具体缺口，给定位，不回显全表。

## 执行结果未知的恢复

状态词含义见[核心记录](03-records.md)。先读持久Attempt意图、请求范围、回执及节点/任务定位，再只用实际支持的查询核对。同步终态已经取得则保存结果，无需假造异步轮询；异步仍running就保持running。超时、停止等待或查无结果不等于failed。

unknown保留最大已授权预留和已发起次数，冻结直接重发与必须消费其产物的依赖；不冻结所有创作与独立任务。依赖/授权/索引可信，且扣除预留后的余额足够时，独立工作可继续。索引或授权自身不可信时才暂停受其影响的提交。

按当前可用路径和批次约定有限核对。穷尽可靠路径后保存检查点，保留unknown，停止受影响链，并呈现具体未决请求、可能费用与可选处理。用户另行明确接受可能重复扣费并批准新的有界尝试时，可建新Attempt；旧unknown及其预留仍在，不能改名当未发生。没有服务端幂等契约，不承诺恰好一次或自称去重已保证。

## 恢复后的检查

核对当前目标版本、Job/Attempt归属、[历史请求与当前编辑器证据](03-records.md#execution-evidence)、用途所需素材证据、未提交旧任务是否失效、在制旧结果资格、总授权累计。只恢复任务列表而没恢复依赖/额度/来源，不足以进入长期付费生产。恢复旧Attempt不套新模板或改写请求；有依据准备新提交时回[提交核对](../generation/05-submit-reconcile.md)，使用当前有效映射及模型编译检查。[变更影响](05-change-impact.md)处理晚到结果；[原创新例](../examples/03-timeout-recovery.md)展示分支。

本协议是系统设计推论，借鉴[幂等重试工程原则](../evidence/01-sources.md#aws)，不代表LibTV具备相应服务器功能。真实初始化、已知ID回读、未知ID发现与跨会话恢复各自待[验证](../evidence/02-verification.md)。
