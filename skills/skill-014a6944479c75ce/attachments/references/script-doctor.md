## 工作边界

先记录用户不可改变项：人物关系、核心事件、结局、主题、尺度、集数、平台和必须保留的台词或画面。优化不得悄悄改变这些约束。

用户只要求诊断时，只输出问题、影响和改法，不擅自重写。用户要求优化时，保留原稿、优化稿和修改理由，使每项变化可追溯。

不要因为现成套路更容易写，就把独特创意改造成通用爽剧。优先修因果、人物和可视化，再优化类型效率。

## 诊断顺序

严格按以下顺序检查，避免用台词润色掩盖结构问题：

1. 核心故事能否一句话说清
2. 主角想要什么可观察结果
3. 谁或什么主动阻止他
4. 失败代价是否在当下成立
5. causal chain（因果链）是否连续
6. 每场 scene function（场景功能）是否不可替代
7. 人物是否通过选择推动剧情
8. 信息、setup、payoff 和反转是否公平
9. 行为是否可见、可演、可拍
10. 台词是否保留潜台词和人物差异
11. 时长和 AI 制作是否可行

前一层失败时，先修前一层。不要先压缩对白，再发现整场戏本可删除。

## P0–P3 问题分级

| 等级 | 定义 | 处理原则 |
|---|---|---|
| P0 | 不改就无法成立、无法理解或无法制作 | 阻止进入分镜；先修复并确认 |
| P1 | 明显损害人物、情绪、反转或追看 | 在视觉设计前修复 |
| P2 | 损害节奏、专业度或类型满足 | 在完整分镜前修复 |
| P3 | 风格、措辞和细节提升 | 不阻塞，可提供备选 |

每个问题按此格式记录：

`等级｜位置｜症状｜根因｜观众影响｜最小修复｜可能副作用`

不要把个人偏好误标为 P0/P1。只有能解释对因果、人物、理解或制作的实际影响时才升级。

## 故事与因果链

用一句话写故事发动机：

`因为___发生，主角必须___，否则___；但___持续让他付出更高代价。`

逐事件检查 causal chain：

`原因 → 人物判断 → 选择 → 行动 → 后果 → 新问题`

如果两个事件之间只能用“然后”连接，检查是否缺少人物选择或因果。巧合可以制造困境，不应持续替人物解决困境。

### 反事实测试

对关键事件问：

- 如果主角不做这个选择，后续是否仍完全相同？
- 如果删除这个事件，剧情是否照常推进？
- 结果是否来自人物行动，而不是作者突然安排？

答案为“是”时，人物或事件缺少因果作用。

## 场景功能

每场必须至少改变一项：

- 关系
- 知识
- 权力
- 风险
- 承诺
- 位置
- 可用选择

写出 scene function：

`本场通过___迫使___从___状态变成___状态，并为___建立条件。`

场景进入与离开状态相同，且没有有效 setup 时，合并、压缩、转为视觉蒙太奇或删除。

### 场景必要性测试

- 这场完成的是新动作，还是重复说明？
- 信息能否通过冲突、道具或后果呈现？
- 是否同时推进外部任务和人物关系？
- 场景末尾是否产生新的选择、问题或代价？

## 人物与选择

为主要人物写：

`外部目标｜内部需要｜恐惧｜错误信念｜底线｜当前策略｜不可逆选择`

目标必须能被观察或验证。“想获得幸福”过于抽象；改为“今晚让母亲签下手术同意书”。

人物弧光不要只写性格变化，追踪行为代价：他在结尾能做出开头做不到的哪项选择？为此失去或承认了什么？

反派和阻碍方也必须拥有合理目标与策略，不能只在剧情需要时出现。

## 可视化证据

把心理、背景和抽象判断转换为 visual evidence（可视化证据）：

| 抽象文本 | 可视化证据方向 |
|---|---|
| 她不再信任他 | 她收回共同钥匙；回答前先确认出口 |
| 他一直控制家庭 | 账单、座位、灯光和他人的行动都需经过他 |
| 她很紧张 | 重复整理已对齐物件；关键名字出现时停止 |
| 他们曾经亲密 | 熟练完成共同动作，却不再看对方 |
| 时间紧迫 | 可见倒计时、外部声响、身体恶化或机会关闭 |

一项 visual evidence 应能在后续获得 payoff，而不是只作象征装饰。

## 信息、反转与兑现

维护信息台账：

`信息｜谁知道｜观众何时知道｜如何知道｜何时重释｜何时兑现`

区分：

- 悬念：观众知道威胁，等待角色遭遇
- 惊讶：观众与角色同时获知
- 谜团：观众知道存在信息缺口

### Setup/payoff 台账

| Setup | 首次出现 | 显著度 | 双重解释 | Payoff | 未兑现处理 |
|---|---|---:|---|---|---|
|  |  | 低/中/高 |  |  | 删除/延后/明确悬置 |

好反转会重新解释旧信息，而不是依靠新角色突然说明真相。反转前必须存在可回看验证的 setup，反转后必须给人物和剧情后果。

## 台词和潜台词

逐句检查：

- 这句话是人物为了获得什么而说？
- 人物为什么不直接说真话？
- 台词是否重复画面已经说明的信息？
- 删除后是否损失人物、因果或节奏？
- 不同人物的词汇、句长、回避方式是否可区分？

将解释台词优先转为：行为、物件、打断、回避、错误回答、沉默、画外声或后果。

不要把潜台词写成演员要“表现的情绪”。写可执行策略：安抚、试探、拖延、羞辱、转移、讨好、逼迫、隐藏、夺回。

## 优化流程

### 1. 保留创作核心

列出：必须保留、可以调整、明确禁止。

### 2. 修复 P0

修因果断裂、人物无目标、关键事实缺失、结局无法建立和无法生产的内容。

### 3. 修复 P1

强化选择、代价、关系变化、反转 setup/payoff 和追看问题。

### 4. 修复 P2

合并重复场景、压缩解释、调整 beat、视觉化心理并优化时长。

### 5. 处理 P3

提供风格、台词和细节备选，不强制覆盖用户偏好。

### 6. 连锁影响检查

修改后重新检查人物知识、道具状态、时间、地点、setup/payoff 和结局逻辑。

## 输出格式与确认门

### 导演诊断单

1. 一句话故事与当前最大问题
2. 不可改变项
3. P0–P3 问题表
4. causal chain
5. 场景功能表
6. 人物选择与弧光
7. setup/payoff 台账
8. AI 制作风险

### 优化对照

| 位置 | 原稿 | 优化稿 | 修改原因 | 对后续影响 |
|---|---|---|---|---|

### Confirmation gate（剧情确认门）

在进入完整导演设计前，明确展示：优化后的故事逻辑、人物动机、结局和主要修改。获得剧情确认后再进入视觉圣经；用户只要局部服务时不强制扩大范围。

## 常见失败

| 失败 | 修正 |
|---|---|
| 一上来重写 | 先记录不可改变项并诊断 |
| 只改台词 | 先修 causal chain、选择和 scene function |
| 为反转藏掉必要信息 | 提供低显著度但可回看验证的 setup |
| 用旁白解释心理 | 转成 visual evidence、策略和后果 |
| 把节奏快等同删光停顿 | 保留选择、反应和 payoff 的可读时间 |
| 为 AI 简化到人物失真 | 先拆镜和换表达，不先牺牲人物逻辑 |
