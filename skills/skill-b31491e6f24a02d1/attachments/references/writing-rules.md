# 写作规范、降噪、风格与维护

## 十二、编写规范

## 五、编写规范


1. **减法优先**：删掉这行AI还会生成同样画面吗？会→删掉。

2. **正面描述**：描述"做了什么"，不描述"没做什么"。

3. **控制与放手平衡**：参考图能承载的信息不在文本中重复。

4. **负面提示词**：仅使用官方约束词（见@NEGATIVE）。

5. **音效层次**：对白最优先→关键动作音效→环境音。

6. **动作控制**：肢体细化+程度量化，拆解复杂动作，优先低缓小动作。

7. **材质具体化**：`matte metal / frosted glass / weathered leather`。

8. **写实质感追加**：`cinematic quality, cinematic lighting, bokeh, HDR`。

9. **情绪具象外化**：用具体身体细节表现情绪（见@EMOTION），替代抽象形容词。

10. **运镜克制**：单镜头1种运镜，不超过2种。

11. **引用语法**：引用区使用 `@图片N=nodeKey` / `@色板_XXX=nodeKey`；正文按文档层使用 `{{Node <nodeKey>}}`，Agent 工具执行前再转换为 `{{nodeKey}}`；禁裸写 `[asset-xxx]`。

12. **符号规范**：台词`{}`，音效`<>`，音乐`()`。

13. **构图描述**：使用定性空间描述，如"主体位于画面左侧，视线方向预留开阔空间"。

14. **手法过载自检**：每个镜头输出前静默检查，若运镜/光影/构图手法在前3个镜头中已使用2次以上，从@ALTERNATIVES检索替换。

15. **色彩脚本同步**：色彩脚本的文本必须与当前镜头引用的色板参考图在情绪和色调上吻合。

16. **调度优先**：含角色走位的镜头，先确定调度方案再填充模板。摄影机运动与角色走位分层描述，不在同一句内混写。

17. **动作结果导向**：武打场面只给风格方向和攻防节奏，不逐招描述。动作过程由视频模型自主填充。

18. **速度差默认**：摄影机速度不与角色完全同步。使用极慢/慢速/中等/快速/极快等定性速度级描述角色动作、摄影机运动和镜头内元素运动，禁止写具体速度数字。

19. **声画关系标注**：每镜标注声画关系模式。台词与画面可同步、对位、平行、断裂、错时、聚焦或投射。画外音不要求口型匹配。

### 新增编写规范

20. **Seedance2.0 边界优先**：时长、参考素材数量、音视频总时长超过限制时，必须拆分任务。
21. **复杂动作处理**：动作复杂时，不逐招描述，优先写动作结果、方向、节奏和关键姿态。
22. **调度细节保留**：触发 @BLOCKING 时，分镜正文保留速度差、空间纵深和角色走位；可执行性评级、降级方案和所用模块只放外部审核/状态区，不进分镜正文。
23. **无执行功能的描写删除**：不能改变画面、声音、动作、光影、构图、运镜或素材使用方式的句子必须删除或改写。
24. **警告外置**：所有警告、阻断错误、强警告、优化提示和拆分建议必须出现在回答顶部的【编译警告区】，不得写入分镜脚本正文。
25. **LibTV / Agent 节点插桩闭合**：正式分镜若服务于 LibTV CLI，参考素材引用区列出的每个 nodeKey 必须先作为当前生成节点的左侧上游入边节点连接，再在 prompt 正文中以 `{{Node <nodeKey>}}` 出现在对应对象紧后方；若交给 Agent `generate_video_v3` 工具执行，调用前必须转换为 `{{nodeKey}}`。主体锚点插在主体名称后，场景锚点插在场景名或场景描述开头，色板锚点插在色彩脚本或色板名后，屏幕状态锚点插在屏幕状态描述后。
26. **分镜转工具**：正式分镜是人类可读制作文档；调用 `generate_video_v3` 前必须转译为工具参数，不能把整份分镜文档原样塞入 `prompt`。
27. **制作时间线信息**：启用时间线重组时，每镜写 `制作时间线信息：制作顺序 X/N，原始镜号 [镜XX]，衔接类型 [连续动作衔接/跳转衔接]，连续性锁定 [无/延长模式/首尾帧模式/派生参考图模式]`。
28. **资产在场声明**：每镜只引用相关的场景资产清单或运动主体资产清单，写“必定在场 / 可能在画面内 / 本镜移除”；不得把全片总资产硬塞进每镜。
29. **主体方位一致**：同一场景资产清单或运动主体资产清单下，主要主体必须沿用清单中的画左/画右/居中、由左至右第几个和常用朝向；若换轴、越轴或构图反转，必须在空间与朝向中说明原因。
30. **运动三要素**：需要连续性判断的镜头必须分开写角色动作速度、运镜速度、镜头内元素速度；三者可不一致，均使用速度级。
31. **动态衔接字段**：首尾帧模式和派生参考图模式必须写落幅运动状态、运动余势、起幅运动承接；衔接点是运动延续，不是静态定格。

## 十三、编译降噪规则：删除无执行功能的累赘描写

本系统不禁止情绪、心理、氛围或文学感，但禁止无法执行的空泛描写。

所有描述必须至少服务以下一类输出：

1. 主体稳定
2. 空间定位
3. 动作节奏
4. 调度关系
5. 运镜动机
6. 表情微动作
7. 台词语气
8. 声画关系
9. 光影色彩
10. 材质风格
11. 参考素材约束
12. 模型限制

判断句：

> 这句话会改变模型生成的画面、声音、动作、光影、构图、运镜或素材使用方式吗？

- 会：保留，并尽量落到具体字段。
- 不会：删除。
- 不确定：改写为可见 / 可听 / 可执行描述。

## 十四、情绪与心理描写边界

情绪和心理描写不禁止，但必须承担执行功能。

凡是能转化为表情、微动作、身体姿态、台词语气、声画关系、光影、色彩、构图、节奏或调度动机的情绪 / 心理描述，允许保留。

凡是只表达作者感受、不能改变生成画面或声音结果的抽象抒情，必须删除或改写。

| 执行功能 | 合格写法 |
|---|---|
| 表情 | 眼眶泛红、嘴唇微张、眉心收紧 |
| 微动作 | 手指攥紧、肩膀下沉、喉结滚动 |
| 身体姿态 | 后退半步、重心前移、身体僵住 |
| 台词语气 | 语速变慢、音量降低、停顿异常 |
| 运镜动机 | 摄影机推进到表情变化的瞬间 |
| 光影映射 | 冷白顶光压低眼窝，阴影遮住半张脸 |
| 色彩脚本 | 冷蓝基底压制肤色，暖色只保留在画面边缘 |
| 声画关系 | 台词平静，画面动作暴露真实情绪 |
| 构图关系 | 主体被置于画面边缘，大面积负空间压迫 |
| 调度关系 | 一人站立逼近，一人坐着后退，形成权力差 |

若情绪 / 心理描写不能服务以上任一功能，则视为无效累赘，必须删除或改写。

## 六、风格锁定编写规则

风格锁定不是把画面中已有的主体、场景、道具重新描述一遍，而是为本镜、本批镜头或全片建立可复用的整体呈现方式。风格提示词必须具备通用性，能够约束不同事物的渲染方式、媒介特征、线条逻辑、材质边界、光色基调和风格分离规则。

### 1. 生成前风格确认

在正式生成分镜脚本前，必须先确认风格来源：

1. 用户已给出明确风格：提炼为可执行的风格锁定提示词，并在分镜中精确引用。
2. 用户给出大段风格分析：压缩为“整体风格基调 / 场景风格 / 主体分类风格 / 材质与纹理规则 / 边界规则 / 缺漏提示”。
3. 用户未给风格：系统必须推荐一个适合故事与素材的风格，并给出可直接使用的风格提示词；若用户授权“你看着办”，则直接采用推荐风格。
4. 若风格信息存在缺口，必须在分镜脚本外部提示“风格缺漏”，说明缺的是场景风格、主体风格、材质规则、边界规则还是色彩策略。

### 2. 风格锁定字段职责

| 字段 | 职责 |
|---|---|
| 整体风格基调 | 定义媒介、渲染方式、时代感、整体视觉语言 |
| 场景风格 | 定义背景、空间、环境的绘制方式、纹理、光色倾向 |
| 主体风格 | 定义不同主体类别的造型语言、材质逻辑、线条/渲染边界 |
| 材质与纹理规则 | 定义哪些材质如何呈现，哪些纹理进入或禁止进入哪些区域 |
| 风格隔离规则 | 定义背景、角色、机械、路人、UI、道具等不同类别之间哪些风格可共享，哪些必须隔离 |
| 局部边界规则 | 定义本镜特有的不可破坏风格锚点与例外条件 |
| 风格缺漏提示 | 仅在风格信息不足时出现，且必须位于分镜脚本外部或作为可删除提示行 |

### 2.1 风格层级：全局风格 / 分类风格 / 局部边界

风格锁定优先采用三层结构，避免每个镜头重复粘贴完整风格提示词。

1. **全局风格**：定义全片或本批镜头的共同媒介、渲染方式、整体光色和质感基调。只在【风格确认区】完整写一次。
2. **分类风格**：定义不同对象类别的独立呈现方式，例如背景、成年主角、儿童路人、机械角色、怪物、UI屏幕、道具、光束。分类风格可以互相不同。
3. **局部边界**：只写本镜新增或特别需要强调的风格边界，例如“HUD为画内真实屏幕”“屏幕熄灭期间为绝对黑暗”“铅笔纹理不进入车灯光束”。

单镜头内部原则上只写引用式最小风格锁；若参考素材已确认，必须同时引用风格素材与色板：

```text
风格锁定：
引用全局风格：[风格名称]
引用风格素材：[@图_主体] [@图_场景]
引用色板：[@色板_段落]
本镜分类风格：[如本镜出现特殊主体，写清该主体沿用哪一类风格]
本镜局部边界：[只写本镜新增或容易混淆的风格/色彩/UI边界]
```

除非本镜风格发生变化，否则不得在每个镜头重复完整全局风格提示词。若无已确认风格参考图或色板，则使用 80–120 字风格胶囊，不得伪造 `@图_` 或 `@色板_` 引用。

### 2.2 风格锁长度原则

风格锁定不是越短越好，也不是全文复制；原则是：**写够用的，不写多余的。**

1. 没有新增风格边界时，只写引用式最小风格锁：全局风格名、风格素材 nodeKey、色板 nodeKey。
2. 出现新的光线、材质或空间约束时，写“参考风格 + 本镜局部边界”，局部边界控制在 1–3 句。
3. 出现新主体类型或明显风格偏移风险时，写“参考风格 + 分类风格 + 本镜局部边界”，明确该主体与其他类别的风格隔离。
4. 不得把完整视觉控制包逐镜复制，也不得把风格锁压缩到无法约束生成的空标签。

### 3. 允许内容

允许写入风格锁定：

- 媒介与渲染方式：photorealistic、modern Japanese anime background、semi-realistic 2D painted、cel-shaded、ink lineart。
- 线条与轮廓：subtle outlines、clean black ink lineart、rough crayon outlines、no sketch lines on machine。
- 场景光色基调：cool blue-grey ambient light、warm yellow interior light as the only emotional color accent。
- 主体分类呈现：机械角色、成年男主、路人、怪物、UI屏幕、HUD等不同类别的风格分离。
- 材质逻辑：worn rubber textures、faded moss-green paint、rust spots、clean specular reflections。
- 边界规则：划痕是否进入金属、铅笔纹理是否进入光束、HUD是否为画内真实屏幕、屏幕熄灭是否绝对黑暗。

### 3.1 多主体不同风格与材质隔离

当同一镜头或同一批镜头中存在多主体不同风格、背景与角色风格不一致、写实主体与插画主体并置、机械与人物材质逻辑不同、UI与真实屏幕并存时，必须显式写出风格隔离规则。

必须回答四个问题：

1. **谁使用哪种风格？** 例如：背景为 semi-realistic 2D painted，成年男主为普通日式动画人物，路人为儿童绘本蜡笔黑影。
2. **哪些风格不得互相污染？** 例如：儿童绘本蜡笔笔触不得进入成年男主、背景建筑和真实道具；背景的半写实渐变不得进入路人黑影。
3. **哪些材质规则只属于某一类主体？** 例如：机械角色有金属剥落、银色基体、雨痕和锈点；这些划痕规则不得进入人物皮肤和背景墙体。
4. **哪些画面元素是画内真实显示？** 例如：HUD、PARTIAL MATCH、屏幕文字、招牌、纸张文字只能作为画内真实物体存在，不得变成后期字幕或悬浮UI。

### 3.2 风格隔离模板

```text
风格隔离规则：
背景：[背景使用的媒介、渲染方式、线条/纹理/光色规则]
主体A：[主体A使用的风格、材质和渲染规则]
主体B：[主体B使用的风格、材质和渲染规则]
道具/UI/屏幕：[是否为画内真实显示，哪些文字允许出现]
禁止混用：[A风格不得进入B；背景纹理不得进入主体；某类划痕/线稿/蜡笔纹理不得进入哪些区域]
共享规则：[全片共同色彩、光影、颗粒、镜头质感；若无则删除]
```

### 4. 禁止内容

禁止把以下内容当作风格锁定：

- 只复述画面内物件：旧木桌、窗台、录音机、钥匙、门、花盆等。
- 只复述剧情状态：他回家、她等待、他们对峙、拆迁队敲门。
- 只复述构图或动作：位于画面左侧、走向门口、抱起花盆。
- 与风格无关的零件清单。
- 已由主体定义、空间与朝向、动作层、光影、色彩脚本承担的内容。

### 5. 大段风格提示词提炼规则

当用户提供大段风格分析时，不得原样塞入每个镜头。必须提炼为：

```text
风格锁定：
整体风格基调：[一句话概括整体媒介、类型、氛围]
场景风格：[背景/空间的通用呈现方式]
主体风格：[按主体类别分别定义：人物/机械/怪物/路人/UI/道具]
线条与上色：[线条、轮廓、阴影、上色方式]
材质与纹理规则：[皮肤/金属/玻璃/布料/屏幕等]
边界规则：[哪些风格只作用于哪些对象，哪些区域禁止混入]
```

### 6. 原有边界

**允许**：材质逻辑、表面处理、渲染方式、光影倾向、色彩倾向、媒介特征、主体类别风格分离、材质边界规则。

**禁止**：物理尺寸（应放在体型参数）、剧情状态、跨镜头记忆、与风格无关的零件清单、把主体/空间/动作字段内容重复写入风格锁定。

## 十五、分镜脚本 → generate_video_v3 工具转译规则（硬规则）

### v4.7 深度故事板覆盖规则

本节旧有的逐字段直转视频规则由 `references/prompt-assembly.md` 的深度故事板流程覆盖。范围闭合、深度故事板和视频 Prompt 的字段、参数、审核与引用规则均以该文件为唯一准则；本节只保留分镜文档到工具参数的转译职责。

任何分镜正文、资产、位置朝向或连续性变更，先使故事板失效并重编译；不得以旧故事板继续视频 Promote。

正式分镜脚本是人类可读制作文档，不可直接作为 `prompt` 原样传入 `generate_video_v3`。视频生成的 Promote 输入=先由正式分镜生成并审核深度故事板，再按 `references/prompt-assembly.md` 组装工具参数：

1. `prompt`：严格按 `references/prompt-assembly.md` 的固定顺序组装成自然语言；不得填表格或跨镜头管理字段，也不得自由改写其约束。
2. `reference_nodes`：传本镜实际引用的普通参考图/视频/参考音频 node_key。所有实际使用节点均须在 Prompt 紧邻其定义插入；旁白、角色台词、音色参考只要被本镜使用，对应 audio nodeKey 必须进入 `reference_nodes`。当前生成节点左侧上游入边必须来自本镜参考素材引用区；工具层已把 {{Node <nodeKey>}} 转换为 {{nodeKey}}。
3. `start_frame_image_node` / `end_frame_image_node`：首帧或尾帧锁定 node_key 只进对应字段，不得重复进入普通参考节点参数；尾帧锁定状态必须与故事板 P9 一致。尾部 2 秒视频只进本次连续延长镜的 `reference_nodes`。
4. 连续延长镜：Prompt 必须写明前 2 秒完整继承本次传入的尾部视频；该要求在 0.0–2.0 秒优先于故事板的整条时间线约束，故事板自第 2 秒起主控。第 2 秒后的剩余时长按正式分镜的动作节奏从 P1→P9 推进；不得填写或依赖未传入的前镜、项目或链路信息。
5. `sound`：文档层 `enableSound=on` → 工具层 `sound: "on"`；`enableSound=off` → `sound: "off"`。
6. 其余参数：分镜时长 → `duration_sec`；项目比例 → `aspect_ratio`；默认清晰度 → `resolution: 720p`。

### prompt 字段组装顺序硬规则

详见 `references/prompt-assembly.md`。禁止自由重写、英文翻译、过度精简、原样搬运整份文档。

### 分镜→视频转化校验清单

```text
□ 已从分镜文档转译为 generate_video_v3 参数，没有原样粘贴整份分镜文档
□ prompt 以一句话总结开头，含通过的深度故事板 nodeKey、色板 nodeKey、实际引用资产的定义/位置/朝向和必要台词音色节点
□ 分镜脚本层已建立角色/旁白与参考音色音频对应，并在对应台词/旁白处插桩
□ 连续延长镜只使用本次传入的尾部 2 秒视频：前 2 秒完整继承并优先于故事板时间线，之后按动作节奏从故事板 P1→P9 推进；故事板只使用已审核尾帧图像且 P1 与其相符
□ prompt 不含表格、项目/父镜头/验收状态等跨镜头字段、@BLOCKING、@COLOR_PALETTE、enableSound 等文档字段
□ 工具层已创建并命名参考音频节点，生成视频时正确连线并传入 reference_nodes
□ sound、duration_sec、aspect_ratio、resolution 已从文档字段转为工具参数
```

## 十六、分镜脚本维护能力：增、删、修、改、查、重编译

用户可以在任意阶段要求修改分镜脚本，修改可以涉及任何镜头、字段、模块和层面。

### 增

在现有分镜前、中、后插入新镜头、新段落或新模块调用。

### 删

删除某个镜头、字段、参考素材或模块调用。删除后必须检查编号、衔接、主体一致性和画面目标是否断裂。

### 修

修正镜头时长、主体动作、运镜、光影、声画关系、参考素材、负面提示词或执行边界。

### 改

重构路径A / 路径B，替换 BLOCKING 模板，改写对白，改成更适合 Seedance2.0 的执行文本。

### 查

检查是否超出时长、素材数量、参考音视频总时长、动作复杂度、主体一致性、调度可执行性和声画关系。

### 重编译

当修改影响多个镜头时，重新生成独立可用的最终分镜提示词，而不是只给局部建议。
