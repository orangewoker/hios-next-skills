# 参考音频处理模块

本模块负责角色音色锚点、台词音频规划、视频生成声音参数和后期合成时间轴规划。用户要求生成音频时，可按 `generate_audio_v3` 的 `type` 与 `ai_model` 规则调用工具；复杂后期合成仍交给后期流程。

---

## 一、参考音频节点创建与引用门禁

含台词、画内系统声、机器声、环境声或上传音频参考时，必须先建立参考音频节点清单，再进入正式分镜或视频生成。每个条目必须记录：引用名、来源类型、用途、源文件或生成方式、时长、audio nodeKey、可否作为音色参考、使用镜头。

节点创建规则：参考音频与 P1 角色图同批创建；音色参考音频时长必须控制在 3–4 秒；用户上传音频先登记为 `@音_角色名_音色参考 → audio nodeKey` 或按用途切分；Agent 生成音频必须用 `generate_audio_v3` 并同时写清 `type` 与 `ai_model`；纯文字音色只可记录为待生成/待确认，不得伪造成已有 audio nodeKey。

两层硬规则：①分镜脚本层必须做好角色/旁白与参考音色音频的对应，在旁白、角色台词或音色描述处插入 `{{Node <音频nodeKey>}}`；每个有声角色/旁白都要标明所用音色锚点。②资产/工具层必须先创建并命名参考音频节点，生成视频时把对应 audio nodeKey 连到视频节点左侧并传入 `reference_nodes`；执行前转换为 `{{nodeKey}}`。缺节点、命名、角色对应、插桩、连线或 `reference_nodes` 任一项，均阻断。

---

## 二、音色参考能力边界

音频参考节点默认只能视为“内容 / 风格 / 声音质感参考”，不得自动承诺等同于音色克隆。

只有当前工具明确支持 voice clone / 音色克隆 / speaker embedding，并且用户已授权使用对应参考音频时，才可以写“稳定复刻音色”。否则必须使用“参考音色方向 / 尽量贴近 / 声音质感参考”等表述，并在待确认项中提示一致性风险。

---

## 三、视频声音参数规则

声音参数必须分层记录：

1. **LibTV CLI / 文档层**：记录 `enableSound=off` 或 `enableSound=on`。
2. **Agent `generate_video_v3` 工具层**：实际调用时转换为 `sound: "off"` 或 `sound: "on"`。

策略：

- 声音全部默认开启：所有视频镜头默认文档层 `enableSound=on`，Agent 工具层 `sound: "on"`。
- 只有用户明确要求静音、关闭原生声音或指定某镜必须后期配音对齐时，才可改为 `enableSound=off` / `sound: "off"`。
- 台词镜头也默认开启声音；不得因含台词而自动关闭。若用户后续要求精确配音对齐，再单独关闭对应镜头原生声音并规划音频节点。

---

## 四、台词音频规划

每条台词应独立规划为一个 audio 节点或可识别音频片段。若通过 `generate_audio_v3` 指定模型，必须同时写清 `type` 与 `ai_model`：配音/旁白使用 `type: tts, ai_model: Seed Audio`；音乐/BGM 使用 `type: music, ai_model: Mureka V8`。`ai_model` 与 `type` 不匹配会报错。

台词音频规划必须记录：角色名、台词原文、音色锚点、镜头内开始时间、镜头累计起点、成片 startTime、生成后的台词音频 nodeKey。

对白字段建议写法：

```text
· 角色名 {{Node <音色nodeKey>}}：[音色描述]（画内/画外/通讯/旁白）
  - 台词：{"台词原文(短停) 后续台词。"}
```

Agent 工具层执行前把 `{{Node <音色nodeKey>}}` 转换为 `{{音色nodeKey}}`。

---

## 五、分段音色控制

同一角色可按叙事阶段使用多个音色锚点，例如建立期、危机期、受伤期、觉醒后、黑化后、老年期。若年龄显著变化、喉咙受伤、性格转变等导致音色变化，必须与角色图同批一次性生成多个音色锚点。每个含台词镜头必须记录使用哪个音色锚点。

分段音色表字段：分镜、视频节点、台词音频节点、音色锚点、台词镜内开始时间、镜头累计起点、成片 startTime。

---

## 六、后期合成规划与累计时间轴

若需要后期合成，输出概念层 audioList 规划即可；除非当前 LibTV CLI 或 Agent 明确支持对应合成命令，否则不得把任何未确认的合成命令写成强制执行命令。

`audioList.startTime` 必须按成片输出时间轴计算：

```text
镜头累计起点 = 前面所有已拼接视频片段实际时长之和
成片 startTime = 镜头累计起点 + 台词在镜头内的开始时间
```

硬规则：合成前必须建立“镜头累计时间轴表”，逐镜记录视频实际时长和累计起点；不得只用分镜标称时长估算。若实际视频时长未知，必须先测量或由合成工具返回后再计算音频 startTime。

所有台词音频应按成片 startTime 升序排列。合成执行方式由当前 LibTV 支持的 video-clip / 合成节点 / Agent composite 工具 / 外部剪辑流程决定。

---

## 七、三种音色控制方式

纯文字描述音色：一致性低、控制精度低、工作量最小，适合草案。

单一音色样本参考：一致性中等、控制精度中等，适合常规角色对白；不等于稳定克隆。

上传音频 + 分段控制：一致性高、控制精度最高、工作量最大，适合主角、多阶段情绪变化或长片项目；是否能稳定复刻取决于当前工具是否支持音色克隆。

---

## 八、音频闭合检查

视频实际引用的环境音、动作音或系统声音频也必须闭合：该 audio nodeKey 进入本次 `reference_nodes`，并在视频 Prompt 的音效层紧邻其作用写入 `{{音效参考音频nodeKey}}`。该节点只说明其声音角色，不得借此改变人物身份、画面、动作或摄影机。没有音频参考时，不得保留空占位。

## 九、深度故事板视频层台词门禁

深度故事板不得引用任何音频节点。视频 Prompt 出现台词时，实际发声角色必须各自引用 3–4 秒音色参考节点：该 nodeKey 进入本次视频 reference_nodes，并紧邻对应台词行前插入音色 nodeKey。连续延长镜的尾部 2 秒视频若含台词，前 2 秒的发声角色、语言与原文必须对应同一角色的音色节点；尾部视频中的原声、环境声或对白不得替代角色音色参考。缺少任一实际发声角色音色、音色时长不在 3–4 秒、尾部台词映射不一致或单镜音色节点超过 3 个时，阻断视频 Promote。

凡作为音色、系统声、机器声、环境声、台词片段或后期 audioList 输入的 audio nodeKey，必须满足：已列入参考音频节点清单；文档层已连线到相关 audio/video 节点左侧；prompt 正文有 `{{Node <nodeKey>}}`；Agent 层已转换为 `{{nodeKey}}`。缺任一项均为阻断错误。
