# 成片确认与工程管理详细规则

本文档为 Skill 第十阶段「成片确认 + 工程管理」的详细执行规则，SKILL.md 通过引用链接使用本文档。

---

## 一、成片确认流程

### 1.1 用户观看成片

成片预览（第九阶段末尾）展示后，进入成片确认环节。

展示内容回顾：
- 完整视频（画面 + 配音 + 音效 + BGM + 字幕）
- 视频参数信息（分辨率/时长/文件大小/配音/BGM/合规状态）
- 项目画布链接

### 1.2 满意 → 版本导出

用户确认满意后，执行版本导出：

**版本命名规则**：
```
默认：{商品名}_{风格}_{画面比例}_{时长}秒_v{版本号}_{时间戳}
用户自定义：用户输入的别名
```

**版本号规则**：
- 首次导出：v1.0
- 修改后重新导出：v1.1 / v1.2 / ...（小修改）或 v2.0（大幅修改）
- 不同风格/渠道派生：使用不同版本号分支

**导出内容**：

| 导出项 | 说明 | 默认包含 |
|--------|------|----------|
| 成片视频文件 | MP4/MOV（按确认的格式） | ✅ |
| 视频播放链接 | 在线预览 URL | ✅ |
| 项目画布链接 | LibTV 画布地址 | ✅ |
| 中间素材包 | 场景图/视频片段/音频文件 | ❌（用户可选择导出） |
| 工程配置文件 | 项目状态 JSON（用于后续恢复/修改） | ✅ |
| 合规检查报告 | 两轮合规检查的记录 | ❌（用户可查阅） |

**多版本导出**：
- 支持同时保存多个版本
- 版本列表：按时间倒序展示所有版本
- 用户可随时导出任一历史版本

### 1.2-A 素材单独导出

用户可在任意阶段完成后，单独导出已生成的素材，无需等到成片完成：

**可导出的素材类型**：

| 素材类型 | 来源阶段 | 存放路径 | 导出条件 |
|----------|----------|----------|----------|
| 商品三视图 | 第三阶段 | 商品图/ | 第三阶段完成后 |
| 人物形象图 | 第二阶段 | 人物设定/ | 人物形象图确认后（仅当人物出镜=是） |
| 人物三视图 | 第二阶段 | 人物设定/ | 人物形象图确认后生成（仅当人物出镜=是） |
| 人物描述卡 | 第二阶段 | 人物设定/ | 人物设定完成后（仅当人物出镜=是） |
| 全部场景图 | 第七阶段 | 场景图/ | 第七阶段完成后 |
| 分镜脚本文档 | 第六阶段 | 分镜脚本/ | 第六阶段完成后 |
| 剧本文档 | 第五阶段 | 剧本/ | 第五阶段完成后 |
| 品牌元素（Logo/Slogan） | 第四阶段 | 品牌元素/ | 第四阶段完成后 |
| 音频文件（配音/BGM/音效） | 第九阶段 | 音频/ | 第九阶段完成后 |

**导出方式**：
- 用户可随时要求导出某类或全部素材
- 导出时打包为 zip 文件供下载
- 素材包命名格式：`{商品名}_{素材类型}_{时间戳}.zip`

**使用场景**：
- 用户只需要商品三视图用于电商详情页
- 用户需要人物形象图或人物三视图用于其他创作项目
- 用户需要场景图用于其他设计用途
- 用户希望备份中间素材

### 1.3 不满意 → 修改

用户不满意时，提供 4 种修改方式：

| 方式 | 说明 | 影响范围 | 适用场景 |
|------|------|----------|----------|
| **精确到镜头** | 指定某个镜头单独重新生成 | 仅该镜头 → 重新拼接 | 某个镜头画面/运镜不满意 |
| **回到具体环节** | 回到某个阶段修改后级联重生成 | 该阶段及所有下游 | 需要修改上游参数（风格/剧本/分镜） |
| **调整参数** | 仅调整第八阶段的参数 | 仅音频/文字层 | 配音/BGM/字幕/音效不满意 |
| **整体重新生成** | 使用当前参数全部重新生成 | 全链路 | 整体质量不满意 |

## 二、精确到镜头修改

### 2.1 修改流程

```
用户指定镜头编号 + 修改描述
    ↓
定位对应场景图和视频片段
    ↓
根据修改描述调整 prompt
    ↓
重新生成该镜头场景图
    ↓
用户确认新场景图
    ↓
重新生成该镜头视频片段
    ↓
重新拼接（仅影响该镜头及相邻转场）
    ↓
重新合成音频（如有台词变化）
    ↓
合规检查（第二轮）重新审查修改部分
    ↓
成片预览
```

### 2.2 修改约束

- 单镜头修改上限：3 轮（与其他环节一致）
- 修改后必须重过合规检查
- 修改单个镜头不影响其他已确认镜头
- 若修改涉及光照/色调变化 → 提醒用户检查相邻镜头的连贯性

### 2.3 批量镜头修改

用户可同时指定多个镜头修改：
- 按镜号排列修改需求
- 逐镜头执行修改
- 全部修改完成后统一拼接和预览

## 三、回溯修改（级联依赖链）

### 3.1 级联规则

成片后仍可回溯到任意阶段修改，修改触发级联依赖链：

| 回溯到的阶段 | 需要重新执行的下游阶段 |
|-------------|----------------------|
| 第一阶段（商品图） | 三视图 → 场景图 → 视频片段 → 拼接 → 音频 → 成片 |
| 第二阶段（基础定义+人物设定） | 人物设定 → 三视图 → 场景图 → 视频片段 → 拼接 → 音频 → 成片 |
| 第三阶段（三视图） | 场景图 → 视频片段 → 拼接 → 音频 → 成片 |
| 第四阶段（品牌元素） | 场景图（品牌露出镜头）→ 视频片段 → 拼接 → 音频 → 成片 |
| 第五阶段（剧本） | 分镜 → 场景图 → 视频片段 → 拼接 → 音频 → 成片 |
| 第六阶段（分镜） | 场景图 → 视频片段 → 拼接 → 音频 → 成片 |
| 第七阶段（场景图） | 视频片段 → 拼接 → 音频 → 成片 |
| 第八阶段（参数） | 音频合成 → 成片 |

### 3.2 回溯确认

回溯修改前，Skill 向用户说明影响范围：

> "回到第 X 阶段第 X.X 步（步骤名称）修改 [参数/内容]，将影响以下下游产物：
> - [受影响产物列表]
> 需要重新生成，预计耗时 [预估时间]。是否继续？"

用户确认后执行回溯。

**步骤级回退的特殊规则**：
- 同一阶段内的子步骤回退（如从 2.7 回到 2.5），只影响当前阶段内该步骤之后的子步骤，不影响上游阶段
- 跨阶段回退时，按上方级联规则处理下游影响
- 用户可以说"回到上一步"快速回退到上一个子步骤

### 3.3 回溯后的合规检查

- 回溯修改后重新生成的版本，必须再过一次对应轮次的合规检查
- 修改剧本/分镜 → 过第一轮合规检查
- 修改成片 → 过第二轮合规检查

### 3.4 回溯版本管理

- 回溯修改后生成新版本（版本号递增）
- 旧版本保留，不删除
- 用户可随时回退到任一历史版本

## 四、工程管理

### 4.1 工程存储

每个项目的完整工程数据存储在：

```
./{项目名}/
├── .project_state.json          ← 项目状态文件（project_manager.py 管理）
├── 商品图/                      ← 第一阶段产物
├── 人物设定/                    ← 第二阶段人物设定产物（仅人物出镜=是时）
│   ├── 人物描述卡.md
│   ├── 人物形象图.png
│   ├── 人物正面图.png
│   ├── 人物正侧面图.png
│   └── 人物背面图.png
├── 三视图/                      ← 第三阶段产物
├── 品牌元素/                    ← 第四阶段产物
├── 剧本/                        ← 第五阶段产物
├── 分镜/                        ← 第六阶段产物
├── 素材/
│   ├── 场景图/                  ← 第七阶段产物
│   ├── 视频片段/                ← 第九阶段中间产物
│   └── 音频/                    ← 第九阶段中间产物
├── 成片/                        ← 最终成片（多版本）
└── 导出/                        ← 用户导出记录
```

### 4.2 断点续做

**触发场景**：
- 用户中途说"暂停"
- 生成过程中断（网络/超时/系统异常）
- 用户关闭对话后再次进入

**恢复流程**：
1. Skill 读取项目状态文件（`.project_state.json`）
2. 识别当前阶段、子步骤和进度
3. 向用户展示恢复选项（精确到子步骤）：

> "检测到未完成的工程：[项目名]
> 当前进度：第 X 阶段第 X.X 步 - [子步骤名称]
> 
> 已完成步骤：
>   ✅ X.1-X.N（列出已完成的子步骤）
>   ⏳ X.N+1（当前子步骤，进行中）
>   ⬜ X.N+2...（后续子步骤）
> 
> 请选择：
> A. 从断点继续
> B. 回到某个已完成步骤重新做（告诉我到哪步，或从列表选）
> C. 从头开始新工程"

4. 用户选择后恢复执行

**断点数据保留规则**：
- 已确认的产物保留，不重复生成
- 中间产物（未确认的）可选择保留或重新生成
- 项目状态文件保留最近 30 天

### 4.3 素材归档复用

**归档规则**：
- 项目完成（成片确认后）自动归档
- 归档内容包括所有已确认的素材
- 归档后素材可被其他项目引用

**复用流程**：
1. 用户创建新工程时，选择"复用已有素材"
2. Skill 展示已归档的素材列表（按品类/风格/商品名筛选）
3. 用户选择要复用的素材
4. 复用素材直接进入对应阶段，跳过已完成的环节

**复用约束**：
- 复用的素材须通过质检（分辨率/清晰度/比例）
- 复用的素材若与当前项目参数冲突（如比例不一致）→ 提醒用户重新生成
- 品牌元素不可跨项目复用（除非同一品牌）

### 4.4 线路 A/B 切换

**触发场景**：
- 项目已走完线路 A（上传商品图），但用户想换成线路 B（文字生成）
- 或反之

**切换规则**：
- 任意阶段均可切换
- 切换后触发级联依赖链（等同于回溯到第一阶段）
- 原线路的素材保留，不删除（可随时切回）
- 切换时提醒用户影响范围

**切换流程**：
```
用户要求切换线路
    ↓
提醒影响范围："切换线路将重新生成第一阶段及所有下游产物，是否继续？"
    ↓
用户确认
    ↓
保存当前线路状态
    ↓
切换到目标线路，从第一阶段重新开始
```

### 4.5 多项目管理

**项目隔离规则**：
- 每个项目独立存储，互不干扰
- 每个项目有独立的项目 ID 和状态文件
- 不同项目的素材/成片/配置完全隔离

**项目列表**：
- 支持查看所有项目列表
- 展示信息：项目名称 / 创建时间 / 最后修改时间 / 当前状态 / 进度
- 排序方式：按创建时间 / 最后修改时间（用户选择）

**项目操作**：

| 操作 | 说明 |
|------|------|
| 查看列表 | 展示所有项目概况 |
| 进入项目 | 切换到指定项目，查看状态/继续执行 |
| 暂停项目 | 保存当前进度，退出 |
| 删除项目 | 归档后删除（保留 30 天回收站） |
| 复制项目 | 基于当前项目创建副本（用于多版本派生） |

### 4.6 多版本派生

**定义**：同一商品从任意阶段派生新分支，用于制作不同风格/不同渠道/不同时长的版本。

**派生规则**：
- 可从任意已确认阶段派生
- 派生版本继承上游所有已确认产物
- 派生版本有独立的下游产物（不影响原版本）
- 派生版本有独立的版本号

**派生场景示例**：

| 场景 | 派生起点 | 差异点 |
|------|----------|--------|
| 同一商品做抖音版和小红书版 | 第二阶段（换画面比例） | 比例 → 场景图 → 视频 |
| 同一商品做实拍版和动画版 | 第二阶段（换视觉路线） | 路线 → 三视图 → 场景图 → 视频 |
| 同一商品做 15 秒和 30 秒版 | 第二阶段（换时长） | 时长 → 剧本 → 分镜 → 场景图 → 视频 |
| 同一商品做促销版和品牌版 | 第二阶段（换广告目标） | 目标 → 剧本 → 分镜 → 场景图 → 视频 |
| 同一商品换配音语言 | 第八阶段（换语言） | 语言 → 音频 → 成片 |

**派生流程**：
```
用户要求派生新版本
    ↓
选择派生起点（从哪个阶段开始不同）
    ↓
确认差异参数
    ↓
继承上游已确认产物
    ↓
从派生起点开始，独立执行下游流程
    ↓
生成独立的新版本成片
```

**版本命名**：
```
原版本：商品名_风格_v1.0
派生版本：商品名_风格_v1.0_派生{渠道/时长/目标}_{时间戳}
```

示例：
- `精华液_高端摄影_v1.0`（抖音 9:16 版）
- `精华液_高端摄影_v1.0_派生小红书1x1_20260810`（小红书方形版）
- `精华液_高端摄影_v1.0_派生30秒_20260810`（30秒长版）

## 六、异常处理

### 6.1 项目文件损坏

- 项目状态文件损坏 → 尝试从备份恢复
- 无备份 → 重建状态文件（从目录中的素材推断状态）
- 无法恢复 → 告知用户，建议重新创建项目

### 6.2 素材丢失

- 某阶段素材文件丢失 → 提醒用户该素材缺失
- 选项：
  - A. 重新生成该素材
  - B. 用户手动上传替代素材
  - C. 从归档中恢复（如有）

### 6.3 存储空间不足

- 项目素材过多导致存储不足 → 提醒用户
- 建议：
  - A. 清理历史版本（保留最近 3 个）
  - B. 归档旧项目
  - C. 删除中间素材（仅保留成片）

### 6.4 并发操作

- 同一项目不允许多个会话同时修改
- 检测到并发冲突 → 提醒用户"该项目在其他会话中有操作，请稍后再试或确认是否继续"

## 七、快速模式工程管理

快速模式下的工程管理简化：

- 成片确认后直接导出，不逐镜头确认
- 修改统一回到对应阶段，触发级联
- 不支持精确到镜头修改（快速模式定位为"先出后调"）
- 多版本派生规则与精细模式一致
- 断点续做：快速模式中断后恢复时，询问用户是否切换到精细模式继续
