# 贯通演练：跨集伤势与知情变更

**本例是原创离线假设。** 没有生成、提交、真实素材或计费。它在[修理店文戏](01-dialogue-scene.md)后虚构扩展连续剧，用于演练跨集变更；这些新增情节不是原场文本已建立的事实。所有 ID/版本、回执情形和金额仅为逻辑输入，不证明真实平台能力。

触发是用户已明确要求：“第二集的伤改到林舟右手腕；父亲替人垫钱的真相延到第三集，第二集林舟还不知道。”变更意图足够明确，先按已授权范围做影响分析；平台执行仍需要真实能力/预算。输入为原季/集/场版本、故事时间与知情账、伤势 Asset 及实际引用、未决 Attempt、剪辑/声音版本。

## 1. 建立原版本，才能知道改了什么

| 原节点 | 故事时间 | 原 v1 内容 | 观众/人物知情 |
|---|---|---|---|
| Ep1 / S-repair | D0夜 | 姐弟开始共同清点，尚未和解 | 只知账未清，不知垫钱真相 |
| Ep2 / S-injury | D1下午 | 林舟搬旧机件时伤到左手腕，随后包扎 | 林岚看见受伤；知情与伤势是独立维度 |
| Ep2 / S-envelope | D1夜 | 林舟打开信封得知父亲替人垫钱 | 原版此后林舟/观众知道，林岚尚未必知道 |
| Ep3 / S-ledger | D2早 | 林舟根据已知真相向林岚解释账目 | 原版行为依赖前一晚的信息来源 |

Change C-wrist-reveal v1 把伤势侧别改为右，信息揭示移到 Ep3。身份、性别、基本相貌无需变化；Ep1 的钥匙交还与有限共同承担保持原意。新场版本要定义右腕具体伤情与包扎可见范围，不能只在全局提示词里把“左”替换成“右”。

## 2. 先回场功能，再修改动作与覆盖

Ep2 / S-envelope v2 不能继续让林舟打开并读懂关键文字，否则对白虽删，观众仍已得到真相。可保留“找到封口未开的信封，因右腕不便暂搁在账本里”，本场功能改为发现待处理材料；不替用户新增他故意隐瞒的动机。

Ep3 / S-ledger v2 需要承担首次获知：林舟以未伤的左手稳住账本，林岚协助开启材料；读到关键处后，他才改变对父亲账目的判断。具体帮助行为是本例的创作方案，若这会使关系比原规划推进太快，应比较“借镇纸固定纸张”的替代，不用换手细节偷偷推进和解。

| 必要事件 | 动作/空间决定 | 所需覆盖 | 缺失后果 |
|---|---|---|---|
| 右腕受伤 | 机件与接触位置可见，受伤后保护同一侧 | Sh-injury：关键接触与反应 | 只补右腕包扎近景会与原左手受伤动作冲突 |
| 次日仍有伤势 | 右腕状态按故事经过，左手承担允许动作 | Sh-ledger：手、账本、道具接触 | 不能因换镜突然痊愈或双手负重 |
| Ep2 尚未知情 | 信封不展示关键内容，台词不泄漏 | Sh-envelope：发现、暂存及离开状态 | 删解释台词仍可能因可读插入镜泄密 |
| Ep3 才知情并反应 | 信息先到达，再有表情/行动变化 | Sh-reveal：证据、阅读/获取、反应 | 反应在信息之前会制造提前知情 |

这里的要求可以由一个镜头或多个选段承担，不固定镜头数量。若读字特写能力不可靠，比较允许的对白/道具表现方案，保留“信息如何到达”的实质，不能直接假定模型能生成精确可读文字。

## 3. 资产、Binding 与内容影响

| 项目 | 新版决定 | 原版保留/检查范围 |
|---|---|---|
| A-Zhou-identity v1 | 保留基本身份 | 不因伤势变化重建无关身份母版 |
| A-Zhou-wrist v2 | 右腕受伤/包扎，生效D1受伤之后；伤情进展分时段记录 | 左腕版本保留历史，不能继续用于暴露双手的新版镜头 |
| A-envelope v2 | Ep2封口未开；Ep3开启后内容才出现 | 原开封图不能做Ep2状态参考，可评估Ep3用途 |
| A-shop v1 | 布局保留 | 只检查动作是否需额外稳定纸张的道具，不全场推倒 |
| Binding 各自新版本 | 指向确切状态资产，注明消费身份/伤势/手部/内容的职责 | 不用“同一个人”覆盖实际伤势冲突 |

向实际使用者追踪：源场/Shot → Asset/Binding → Job/Attempt → Take/Clip/Timeline → 声音/字幕/调色/输出。知情同时追踪台词、行为、可见文字和反应；不能只搜人物姓名或“左手”两个字。

## 4. 计划工作、在制旧版和晚到结果

| 当时工作状态（假设） | 新决定 |
|---|---|
| J-injury v1 尚未提交 | 原目标被取代，不再提交；建立新版右腕任务 |
| J-envelope v1 的 A-env-1 已发出、结果未决 | 保留它的输入版本、真实状态与预留；不假称已取消。新目标等待相应新版条件 |
| Ep3 正脸近景已返回，画面不见手也无泄密台词 | 按新版用途重新观察；若时间/反应起点仍合适，可记录复用理由，不因上游变更全盘废弃 |
| Ep3 正脸近景表情已表现“早知道了” | 即使不露手也可能被知情改变影响；回表演或换段 |
| A-env-1 晚到，仍为Ep2开封并读出真相 | 追加真实终态/费用证据；不能覆盖当前S-envelope v2或被自动选进新版 |

晚到旧片若有一段不含泄密、也符合封口状态的可用内容，可单独审查其用途/区间后复用。来源仍指旧 Job/Attempt，不能改写成新任务生成。当前版本由已核对的索引决定，不能由回调到达顺序决定。

## 5. 哪些工作可以继续，哪些需要等

J-injury v2 和 Ep3 的 J-reveal v2 可以使用各自已验收状态资产；同属连续故事不意味着后者必须等前者视频。它们之间有内容连续性，但未必有执行依赖。

如果另选 J-wrap v2，要延续某段实际包扎视频的手部末态，则必须等待该 Take 和所需末态观察，不能消费计划描述。若读信动作改剪能完全使用已有可用片段，则先做纸上装配，不追加生成。

unknown 旧请求只拦消费其产物的链及受预留影响的预算。已有可信索引/授权，且独立工作有足够余额时可继续；同步写入/并发提交仍按[调度](../generation/04-scheduling.md)和[状态恢复](../core/04-state-recovery.md)办理，不能把逻辑独立当成平台无限并发。

## 6. 虚构预算演算

以下人民币数值全为**虚构，不是报价或实际授权**。假设总额1200元，已有可信消费350元，旧未决 A-env-1 最大预留60元，则可核实剩余允许提交量是790元。预留不因改稿、查无结果或晚到而自动释放。

| 新范围候选 | 假设费用上界 | 假设可能计费调用 |
|---|---|---|
| 右腕状态与封口信封两项资产 | 20＋30＝50元 | 2 |
| 受伤、Ep2暂存、Ep3揭示三个目标片段 | 50＋40＋60＝150元 | 3 |
| 受支持的后期修订批次 | 40元 | 1，只有实际契约确认为单一计费任务才成立 |
| 剩余必做工作完成成本 | 300元 | 尚需展开，不得从总额反推调用数 |

有界新版工作240元，加剩余必做300元，共540元，在790元内尚余250元；这只说明给定数字下预算可容纳，并未证明实际成本。如果原授权总调用上限20次、此前已发起9次（含旧unknown），则新版6次后累计15次，余5次；剩余必做项还必须在这5次内有可信调用计划。若需要8次，金额够也不能宣称可完成，要调整具体方案或获得新边界。

若旧请求后来有可信账单证实消费54元，且不存在其他未决费用，才把已知消费改为404元、释放该项余下6元；在上述新版尚未实际支出这一时点，可核实余额为796元。真实执行一律按[项目契约](../core/01-project-contract.md)与[提交核对](../generation/05-submit-reconcile.md)累计，不能靠新 Job 版本重置尝试。

## 7. 观察、剪辑与返修闭环

素材层要看右腕确实在正确故事时段变化，左手动作与空间可行。场层要看Ep2信息仍未泄漏、Ep3信息先到达再反应。集层要复看转场、对白、字幕及声音桥是否无意提前泄密。季层检查延后的真相是否破坏后续选择与伏笔；Ep1的共同承担不因这一变更自动变成彻底和解。

若新右腕素材合格但旧剪辑仍从左手受伤起步，最小修复是修改对应动作覆盖与选段，不能宣布资产验收通过就关闭问题。若预算只够改台词、不够删除可见信封内容，当前方案仍不充分；应提出保留封口镜头等替代，不静默降低知情要求。

可浏览结果是 Change 的影响表、保留/修订列表、新版覆盖与任务包、仍未决请求及余额、逐层复查条件。本例未产生真实素材或通过记录。执行细节统一见[变更影响](../core/05-change-impact.md)和[返修](../quality/02-repair.md)。
