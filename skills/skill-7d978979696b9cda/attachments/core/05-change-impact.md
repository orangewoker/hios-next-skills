# 变更、版本影响与迟到结果

用户改剧情/人物/造型/风格/交付，或实际证据推翻旧验收时使用。先读变更原话、当前目标和相关源版本、实际引用关系、在制Attempt与已选片段。不能只凭“同角色”将全片作废，也不能只改一张母版而放任旧引用继续扩散。

## 先确定生效范围

| 变更类型 | 必须问清或从原话识别的范围 | 实际处理 |
|---|---|---|
| 追溯纠错/改设定 | 哪个属性从全片/全季何处起都应如此 | 沿该属性的真实引用检查，含已交付版本；无关属性/看不见处不自动返修 |
| 新故事状态 | 哪个事件/故事日期起变化，谁知道 | 只更新该时点起的状态与知情链，保留此前正确版本 |
| 局部表达/输出用途 | 哪场/哪镜/哪个画幅或剪辑版本改变 | 只审该用途及其相邻影响，不把输出变化当人物世界事实 |

“全季疤改右脸”与“第四集才受右脸伤”不是同一种范围。信息已明确就执行，不重复问；真正不清楚且会改变很多成果时，先做影响清单与可选方案，再询问这个具体差别。创作假设可以形成草案，但不能假装获得追溯重拍授权。

## 影响扫描与状态处理

建立Change记录：原目标→新目标、生效范围、改变属性、理由/批准来源、受影响源工件与引用。维护原版本，新增当前版本；状态枚举以[核心记录](03-records.md)为准。

1. 先检查故事日期、人物经历/知情、场功能与必要事件。若改变的是人物动机或关系进度，先修创作依据，不能靠替换脸或补一句话掩盖结构问题。
2. 扫描引用该版本/属性的Asset、Binding、Shot、Job、Attempt、Take、Clip/Timeline与导出。清单每项记“需重审的原因、已核对的结果、可保留依据”；未取得真实列表就说待查，不编具体镜头ID。
3. 未提交旧Job退出ready，标其目标已替代或等待重定；不能继续按旧输入提交。若新请求改变提示词/参数/参考，建立新Job版本。
4. 在制Attempt保持原请求和实际执行状态、回执及费用预留。只有平台存在取消能力且授权涵盖时才请求取消，并核对真实结果；不能把意图中的取消写成cancelled或自动退款。
5. 已返回/晚到Take先归属原Attempt与旧Job，检查它在新目标下的用途、区间和维度。不能因为最后到达或旧标准合格，就覆盖当前母版/绑定/索引。确实不涉及变化属性的空景等用途可有据复用；有冲突用途仍需返修。
6. 更新Binding、选段和时间线所引用的确切版本。新结果晋升为当前可消费成果时再次核对目标版本，防止在审查期间又发生上游变化。保存影响结论后按[恢复协议](04-state-recovery.md)提交索引。

沿资产索引中的依赖用途检查：身份影响对应角色图/表演，布局影响方向/调度/镜头设计，外观影响材质光照，道具设计影响角色持物/交互，故事状态影响适用快照，实际引用影响目标Job。是否受影响须结合入画、遮挡、反射、光照与行动路径；改B墙窗位可能改变A墙视角受光，不能仅按墙名豁免。变更后的故事快照另建修订，生产Checkpoint更新真实索引，不按最后生成覆盖闪回/过去状态。格式修订本身不等于人物身份或故事事件变化。

## 保留还是返修

新目标确实不影响某个远景、空镜或声音用途，可以保留并写理由；但“脸很小”不是未经观看就判断不影响的证据。相反，伤势改动可能影响人物反应、他人知情和后续对白，即使那镜没拍脸也须检查剧情。

先比较改剪、换已合格Take、调整Binding、局部声画处理、补覆盖镜、重做场景等[返修方案](../quality/02-repair.md)。最小是足以解决原因的最小范围，不是改最少提示词。每次变更都重新评估[预算](01-project-contract.md)，总尝试和费用跨新旧Job累计。

产出是可浏览影响表：对象/版本、相关属性、在制或已用、决定、依据、下一步与成本范围；加一段用户摘要。复查局部、相邻接缝及受影响故事节点，再决定是否扩大范围。[跨集示例](../examples/02-series-change.md)用于演练，不能当真实项目清单。

本流程借鉴逐场连续性、跨集协作和变换跟随素材的记录思想；版本传播和资格重判为本项目设计推论，见[方法边界](../evidence/01-sources.md#method-boundaries)。
