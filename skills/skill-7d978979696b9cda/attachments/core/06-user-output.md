# 可浏览输出与具体决定

向用户展示进度、剧作、导演分镜、素材、异常或交付时使用。输入来自当前目标、真实已完成工件与观察证据，不从计划中推造结果。让用户先看到作品和关键决定，记录格式放在需要展开的位置。

## 默认输出

用一段当前阶段，再列本轮实质结果、关键创作选择、影响下一步的缺口和下一步。无实质变化不重复长表。既有任务中用户已授权本地实现/生产范围，不追加泛化确认；必要决定只问一次具体差异并继续独立工作。

> 当前：第一集修理店场，导演与覆盖方案。  
> 本轮：把“邀请后才卸包”确定为关系转折；主镜覆盖落钥匙、转账本和坐下。  
> 选择：先保留双人空间，反应镜仅在主镜看不清决定时补用。  
> 待解决：场景图未证明桌右通道够走位，空间参考仍待观察。  
> 下一步：核对通道，再准备有具体用途的参考需求；尚未提交生成。

这是虚构呈现例，没有实际媒体回执。成功、计划、运行中、未观察和暂停分别说清，不能用“已处理”模糊写稿与付费执行。

## 按作品内容展开

| 用户要看 | 优先呈现 | 避免 |
|---|---|---|
| 创意/结构 | 可比较的故事选择、人物后果、代表场景与未决处 | 先倒出对象/资产表；只有主题标签没有可写内容 |
| 剧本 | 连续可读的场景、对白与动作，原文/新增标记必要时附后 | 把每句话拆成技术字段或把每段当一镜 |
| 导演/分镜 | 行动与空间、镜头观看职责、必要事件覆盖、声音和切点理由 | 镜头词库堆砌、为填表机械特写、固定秒数切戏 |
| 资产/提示词 | 按角色/场景/用途分组，确切引用与版本；逐任务可直接使用的文字 | 全库刷屏、重复公共约束、未经确认的参数样式 |
| 进度 | 已确认完成、运行中、未决、需要决定的差额及真实定位 | 因旧授权有效就新提交任务；由估计数量编造完成百分比 |
| 质量/返修 | 实际时段现象、叙事后果、建议范围、保留项、观察限制 | 只给自评分或笼统“电影感不足”，默认全量重做 |
| 交付 | 实际产物级别、文件/工程定位、覆盖/技术/观感验收和缺项 | 把素材集合、拼接样片称专业母版 |

文档/项目定位使用平台真实可访问链接或准确名称/ID；没有可用链接则说明当前定位方法，不能造URL。详细表格按集/场/任务拆分并可按需读取，不把恢复负担转给用户。原生工具需要JSON时只在工具参数内使用；除用户明确索取，不回显大对象或单行全量JSON作为所谓兜底。

Seedance2.5完整视频请求的呈现顺序与七段正文唯一依[平台请求卡](../platform/04-seedance-25.md#request-presentation)，本表只决定何时展开及摘要层级；进度、加载/引用诊断不强行套视频模板。

关联诊断用可辨作品名/缩略图位置说明“当前源是什么、被写成什么、哪项仍未核”，技术定位优先由Agent查现有真实回执、画布或引用选择。没有相应读取能力时说明具体缺口，必要时请用户辨认作品或完成实际要求的选材动作，不常规让用户找node_key、复制全表或提供开发者资料。

## 问题和批准必须具体

询问缺信息时说明它影响什么决定；可合理假设且不影响授权的创作草案先继续。范围内的批量执行、观察或自动选择不逐张批准。预算不足的请求应给“已有上限、已花、未决预留、本次/剩余需求、差额与方案”，不只问“是否继续”。平台强制人工动作如实说明由哪个实际界面/契约要求，不虚构审批规则。

执行unknown时给原请求、当前证据、预留及被影响分支、已穷尽的核对方式、可继续的独立工作和真正待决定事项。用户选择有界承担重复成本时保留旧unknown，不把一次“继续”笼统解释成新的费用风险授权。

## 输出自查与返修

读一遍回复：用户是否能知道作品推进了什么；能否区分实际结果和计划；关键风险/决定是否被数据淹没；有无把待确认/预览说成受理、媒体存在说成整段观察；有无把当前编辑器改稿当历史请求；有无在缺观察时称合格；有无要求贴回全表；有无把已批准事项再批准。缺什么就缩小声明或补定位，不靠隐藏工具状态解决版式问题。

格式服务于判断，必要时用短表、连续剧本或分镜说明，不能为一致外观强制所有阶段同一张表。[项目契约](01-project-contract.md)负责授权，[核心记录](03-records.md)负责词义，[路由](02-routing.md)负责下一步。本文件为本项目的用户呈现设计，见[方法边界](../evidence/01-sources.md#method-boundaries)。
