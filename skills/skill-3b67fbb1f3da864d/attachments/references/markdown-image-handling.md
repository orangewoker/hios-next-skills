# Markdown 图片处理

仅在用户上传 Markdown 文章时读取本文件。目标是完整识别文章图片，并把内容图片分配到视频镜头中。

## 识别图片

识别以下来源：

- 标准 Markdown：`![替代文字](图片地址)`；
- 带标题 Markdown：`![替代文字](图片地址 "标题")`；
- 引用式 Markdown：`![替代文字][标识]` 与对应的 `[标识]: 图片地址`；
- HTML：`<img src="图片地址" alt="说明">`；
- 用户随 Markdown 一起上传的本地或附件图片；
- `http://` 或 `https://` 开头的普通远程图片和 CDN 图片。

对 CDN 地址保留完整原文，包括协议、域名、路径、大小写、扩展名、查询参数和签名参数，不自行删改、转义或拼接。

## 建立素材清单

按文章出现顺序记录每张图片的：

1. 图片来源或完整地址；
2. 本地、附件、远程或 CDN 类型；
3. 替代文字、标题或图注；
4. 前后段落和对应信息点；
5. 图片作用：人物、场景、产品、步骤、数据、案例或装饰；
6. 计划使用的镜头与处理方式；
7. 是否可以访问。

不要因为图片没有替代文字就跳过。没有说明时，结合图片内容与前后段落判断用途。

## 选择与使用

- 优先使用能直接证明、展示或解释正文的图片，包括产品图、步骤截图、数据图、案例图、人物或场景照片。
- CDN 图片与本地图片使用同一判断标准；不得仅因远程来源而忽略或替换。
- 同一图片只在确有叙事需要时重复出现；重复使用时改变裁切、运动或标注重点。
- 使用横图或长图时为竖屏重新构图，可采用主体裁切、背景延展、分屏、局部放大和缓慢移动。
- 截图和图表要保留关键区域并保证手机端可读；必要时按信息顺序分段呈现。
- 图片含有准确文字、界面或数据时，不使用生成模型重绘，以免产生乱码或事实变化。
- 头像、二维码、赞赏码、关注引导、广告、装饰分隔图和无关表情默认不进入成片，除非它们是正文论证的一部分。
- 原图无法覆盖全部口播时，只为缺少的镜头生成原创素材，不替换已经可用的原文图片。

## 访问失败

- 先按原始 CDN 地址直接载入，不擅自修改查询参数或换域名。
- 访问失败时明确指出具体图片及失败原因，例如链接过期、防盗链、需要鉴权或文件缺失。
- 仅对影响叙事的关键图片请用户重新上传；装饰图片失败不阻塞成片。
- 用户补传后，将补传图片放回原来的文章语境和镜头，不改变文章结构。

## 使用后检查

- 每张与正文相关且可访问的图片都已分配到合适镜头，或有明确的不使用理由。
- CDN 图片没有因远程来源被遗漏。
- 图片顺序、图注和文章语义没有错配。
- 裁切、动画和标注没有改变事实或遮挡关键信息。
