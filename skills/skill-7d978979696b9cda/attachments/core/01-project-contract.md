# 项目范围、自动推进与完片预算

新项目、范围改变、准备付费或更新里程碑时读取。输入是用户要求、已有原文/项目、当前授权和确切执行能力；已知信息直接复用，缺信息只在改变当前决定时询问。已有授权在范围内持续有效。

## 建立足够工作的契约

先用短段落说明本轮要完成什么、哪些信息足够、哪些仍是假设，然后继续已授权的工作。Project至少能回答：作品形态与体量、观众与体验、故事/改编权限、审美目标、目标交付、自动执行范围、预算与停止条件、存储入口。记录身份与枚举见[核心记录](03-records.md)。

| 当前情况 | 工作决定 |
|---|---|
| 从创意起步、预算未定 | 可以比较前提、结局、人物和制作表达；注明假设，不先建大资产库或付费试抽 |
| 只做一场/一段返修 | 取得该范围的原文、前后状态及目标即可推进；不要求先补齐全片 |
| 忠实改编 | 原文事实、推断和新增表达分开；改变因果/人物关系/关键事件先有相应创作授权 |
| 允许原创发展 | 在授权探索范围内形成可比较草案；候选不必逐项批准或先做正式生产登记 |
| 已有剧本或素材 | 先读取真实内容/版本和现有成果，再补必要缺口；不因换Skill全量重做 |
| 审美参照尚无答案 | 用有标签的方向和反例形成讨论稿；不得报“已达到用户的专业审美标准” |
| 网页内某项能力不足 | 唯一执行面仍是LibTV网页内置Agent；记录具体缺口并继续可做部分，不把CLI、外部API或外部剪辑列为替代方案或待用户选择的执行路线 |

已确认格式约束保存在Project，并注明用户或目标平台的真实要求来源：总片/集长与容差、片头片尾是否计入、画幅、字幕/声音等交付条件。规划正文时先扣除固定占用，实际时长仍要在读演、预演或剪辑后核回。片头钩子、固定反转频率或集尾悬念仅在确有要求时登记，不从“平台剧”自行推定。

审美目标要能指导取舍：例如“人物关系通过动作与停顿变化；不靠解释对白提前和解”。参考作品用于定位光、节奏、空间、表演等具体属性，不能一句“某导演风”代替设计。区分需要保持的原则和可探索部分。没有统一适合所有长片的镜数、反转频率或比例。

创作所需的作品目标、原文和预算由用户表达；当前工具能力由Agent从自身可见工具说明、网页选项和实际结果中按需核对。不要把提供API key、schema、完整工具清单或开发者资料列为用户开始创作的必填项。未暴露底层字段不等于所有网页制作能力不可用；只判断本次实际需要的操作是否可执行。

## 项目/批次授权

记录谁在何处批准了哪些动作、模型、资源、范围和总尝试/费用上界。创作批准、平台写入、媒体生成、观察、合成/导出可能是不同动作；“写分镜”不自动批准生成分镜图。工具叫查询、没有run或只建节点，也不能据名字推断无副作用。

用户已经授权批量制作和自动审查时，在约定范围内推进，不逐表、逐镜、逐图再问。超范围、越预算、改变锁定模型/故事核心、平台强制人工操作时，呈现具体差额或动作。对新预算的明确确认是费用授权；对剧本的满意不等于费用授权。真实工具未暴露或副作用未核清时，授权不能创造能力。

自动接受范围与审片可靠性分开：用户可授权自动选择候选和推进，但Agent评估须注明实际观察范围、未校准的可靠性以及最终人工验收约定。不能把未观察维度判acceptable，也不把“未校准”变成每张图都询问的固定路径。[审片方法](../quality/01-review-rubrics.md)负责质量判断。

## 受限小样模式：只用于验证，不替代正式生产

正式长篇生产仍要求已验证的持久记录/读回、可靠引用核对和本批所需的空间/调度图。若这些能力在网页中仍为unknown，可以在本项目契约中登记一个**受限小样模式**，但必须同时写明：本次会话、限定的图像/视频/观察/装配数量与费用上限、用户已接受的不可跨会话恢复和重复扣费风险、停止条件，以及实际请求参数和回执保存在哪里。没有这些具体边界时，不能把“继续”解释为接受任意降级。

受限小样只允许消费已知来源和可核的实际选材；不得消费unknown结果，不得把规划ID、显示标签或猜测槽位当作引用。每次真实调用仍建立独立 `Attempt`，范围/模式记为 `limited-sample`，按实际状态、费用预留、确认消费和尝试次数进入同一授权链；不能因为 Job 保持 `planned` 或请求账本未持久化就把调用排除在预算之外。它可以在同一会话用可见对话账本保存请求与回执，但必须标为“未持久化、不可自动恢复”。小样结果不作为持久性、引用回显或正式调度图能力的证据；按探索规则，补齐用途设计、实际观察和适用级别的 Director Pack 后可晋升适用资产/Take，但正式Job仍按缺口保持planned，同一会话的有限执行并不创建跨会话后端。

## 每次提交之前的额度判断

按授权链跨Job版本累计。不同币种、积分、秒数、张数不擅自换算相加；只在可靠报价提供对应关系时换算。数量上限和费用上限分别满足。先明确授权中的“一次”指提交尝试、视频生成子任务、产物数量还是其他业务单位；复合工具内部任务逐个登记，按对应单位占用额度，不能只数外层调用，也不能把外层与内层混为同一单位重复相加。

| 预算项 | 记录与使用 |
|---|---|
| 已确认消费 | 有真实扣费/账单等证据的数值与归属；不把预计耗时当计费 |
| 未结算预留 | 已登记提交意图或已发起但费用尚未确定的最大已授权可能费用；含prepared预留、unknown及未核实收费的failed/cancelled |
| 当前可提交余额 | 同单位授权上限减已确认消费、减尚未被其包含的预留；结算时替换对应预留，避免双计或提前释放 |
| 尝试累计 | 每个已发起Attempt计一次真实提交；内部子任务另列关联、重试与计费事实，不暗中改变Attempt的单位；失败、unknown、改名和新Job版本不清零 |
| 业务数量占用 | 按授权约定单位另计视频、图像、计费子任务等；一个Attempt产生多个Take不等于只有一次业务占用，也不自动等于多次扣费，须按真实契约映射 |
| 剩余必做成本范围 | 尚未完成的资产、镜头、声音、观察、返修与后期交付需求；与当前已承诺项分开避免重复估计 |

<a id="attempt-reservation"></a>
当前可提交余额用于为新Attempt新增预留。发出已经prepared的同一Attempt时，核对它原有预留仍有效、足以覆盖此次请求，并继续占用；不是把同一笔金额当新请求再扣一次。例：授权100点、未消费、A已prepared并预留60，A可在其余条件满足时使用这60点提交，新增独立B80则不能挤入仅余40点。不能先释放A再抢占其额度。

旧Job被替代且有可靠证据确认旧prepared意图从未发出时，保存失效理由、未发出依据和原金额，将对应未发生执行的预留核销为0；旧Attempt及其归属/历史保留，已发起次数仍为0，不记成平台cancelled或退款。已经实际发生的存储等费用仍按账单保留。只有早期本地状态、提交中断或未知回执而不能确认未发出的，不能核销；相应不确定性按[恢复](04-state-recovery.md)处理。prepared旧快照、无submitting/回执/节点/扣费和普通读回相加仍非未发送证明。可靠依据可来自当前未中断、完整可核对的执行链，由唯一发送者确认未调用生成、未移交他人或队列，再保存旧意图失效并核对；仅有“制度要求先记账”不证明实际记录从未丢失。若平台另有可靠结算证据，按实际费用替换/释放相应预留，不把已发送Attempt倒改成从未发送，也不清零已发起次数。

新Attempt的最大可能成本须在可核实余额内，总尝试和其他适用数量额度也有余量。若授权“最多3次视频生成”，一次外层调用将明确创建2个视频生成子任务，则视频生成占用为2，外层另记1个Attempt，不把视频数计成1或3。若还有限定Attempt上限，两项分别核对；授权单位含混且影响是否越界时，只明确该计数口径，不重问已清楚的批准。价格未知、计费子任务数未知或只有展示estimatedTime时，不能核定金额承诺；保留请求草案，取得确切计费依据或由用户另行明确接受的有界费用/风险范围，仍不能越已有金额上限。当前没有付费预算时不试探性提交。

虚构算例：授权1000点，已确认900，A未知最多50，则可提交余额50；独立B需80仍不能提交。若B需40且其余条件可信，则可推进B并为其另预留40，A仍未决。不能因为Job已complete或图看起来可用就释放其他Attempt预留。

## 够不够完成作品

立项规划、主资产完成、典型场景验证、每集/大段落结束，以及返修率或范围发生实质变化时更新预测。列剩余必做工作、每类可得价格/成本范围、实际已发生返修、未知价格/能力和合理风险余量。少量样本只称当前观察，不推算成稳定成功率。声音、观察和导出不能一直被素材生产挤到无预算的末尾。

若剩余需求的有据下界已超预算，或未知价格无法支撑完片承诺，在继续高成本生产前展示具体方案：增预算、改变表达/制作方案、调整体量/范围。说明哪些事件、情绪、质量或交付会受影响，由用户决定超出原约定的改变。不默默丢场、降质、只做开头，或以“从未超支”宣称任务完成。

请求确认时只展示本次需要决定的内容：目的、工作范围/模型、素材数量和实际支持时长、总尝试上限、费用依据与未知项、停止条件、结果去向。已有批准不重复问；异常支路由[提交核对](../generation/05-submit-reconcile.md)和[恢复](04-state-recovery.md)处理，用户看[简明输出](06-user-output.md)。本协议是项目设计，价格、平台权限和可靠性需各自证据。[方法范围](../evidence/01-sources.md#method-boundaries)。
