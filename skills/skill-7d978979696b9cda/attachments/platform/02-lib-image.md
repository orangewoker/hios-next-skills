# Lib Image 适配

用户偏好Lib Image，或准备以它生成/编辑参考图时读取。输入为已确定的视觉用途、[图像意图](../generation/02-image-prompt.md)、实际Binding、目标入口配置及授权。

## 身份与证据

按用户给的Lib Image展示名登记偏好；当前没有平台证据证明它等同GPT Image 2。Agent从网页会话自己可用的模型选项和图像工具核对本次操作；不要求用户提供model key/schema或API key，未知底层映射不阻碍使用已经可用的Lib Image选项。不可填入猜测的OpenAI参数或借旧缓存“全能图片模型V2”替代；厂商API不是本Skill的执行路线。

2026-09-06既有Agent网页菜单已见准确名称Lib Image；页面宣传长文本能力，但未刷新配置或执行选择/生成。此项只确认界面展示，不证明底层型号、当前计费或输入参数。

## 按需求选择表达

| 当前用途 | 决定与核验 |
|---|---|
| 全新人物/场景探索 | 先给具体身份、材质/空间、观看用途和少量风格边界；未选定方案只做有标签的探索，不批量派生全季 |
| 已确定母版的服装/状态变化 | 当实际入口支持参考编辑时绑定确切母版，分清身份保持与衣服/伤势改变；不把文字提到母版当作已绑定 |
| 新视角/反向场景 | 先从布局和摄影覆盖说明哪些空间关系须保持，核查入口参考方式；不能承诺凭一张图精确重建不可见区域 |
| 道具结构或可读信息 | 明确叙事必须辨认的轮廓、接触面/文字与使用视角；输出后检查对应细节，不依“高质量”词验收 |
| 未证实编辑/多参考/批量 | 记录所需能力并核验；不能凭模型名添加模式、参考数量或并发参数 |

示例语义意图（未提交、不是参数）：以已绑定的林舟身份图保持脸部识别特征，改为修理店工作外套；采用便于核对服装和手部的中性观看条件；暂不加入夜戏复杂光影，以免把场景状态烘焙成身份。实际参考标签/尺寸由当前入口契约决定。

## 结果判断与返修

生成成功只建立Take。按[资产制作验收](../assets/02-asset-build-review.md)检查身份、衣服/故事状态、手与道具、视角、空间、风格各自用途。单一母版通过不保证跨图一致，局部修改也可能影响未要求改动处。若改变项失败但身份成立，先检查真实引用、改变范围与表达冲突；能够有界局部编辑才使用，否则比较重做或调整覆盖，保持原版。

输出为可读的请求意图及真实模型/引用映射（取得后），随后附实际产物位置、观察范围和可用于哪些镜头；无真实产物时只报规划。进入付费前按[项目契约](../core/01-project-contract.md)，执行按[提交核对](../generation/05-submit-reconcile.md)。[模型来源边界](../evidence/01-sources.md#models)：OpenAI图像资料只是可能的对照研究，不是Lib Image的平台证明。
