## 1. 门控通用循环

> ⚠️ **AI 内部备忘**
> ────────────────────────────────────────────
> 🔒 引用锁：本门控循环的决策依据以 `§0.1 创作决策锁定表` / `§0.2 分集决策锁定表` 为准——禁止从训练数据自由采样替代。
> 📐 公式重载：
>   - 「读取 references」= 以 `_routing.yaml` 命令节点的 must_read 列表为准 + 本命令对应的锁定表字段来源文件
>   - 「决策点」= 锁定表中对应字段的当前值——不是 AI 重新选一遍
>   - 自检 checklist 在落盘后必须逐条过——不是跳过
> 🚫 防呆标记：
>   - ⛔️ `/创作方案` 判定题材时 → 以 §0.1 锁定表「题材」为准，不从训练数据角色档案回推题材
>   - ⛔️ `/目录` 选情绪弧线时 → 以 §0.2 锁定表「全剧情绪弧线」为准，不重选
> ────────────────────────────────────────────

除 `/创意` 和 `/开始` 外，每个文件按 5 步门控执行：

```text
[1] 读取 references：以 references/_routing.yaml 为本命令加载必读和按需文件（单源真理）
[2] 写入产物文件
[3] 落盘 checkpoint：echo '[{...}]' | python scripts/sandbox_gate.py write \
      --command /<命令> --product <产物> --project-dir <dir> \
      --summary "<200-400字>" --decision-points-stdin --references-read <列表>
    → 在产物首部追加 Checkpoint-Source 引用（脚本返回 hash）
[4] 校验：python scripts/sandbox_gate.py verify --command /<命令> --project-dir <dir>
[5] 输出摘要 + 决策点 + 半结构化菜单 → 等待用户回复
```

**深度档位**：

| 命令 | 决策点数 |
|:---|:---:|
| `/创作方案` | 5-6 |
| `/角色开发` | 3-4 |
| `/物品档案` | 1-2 |
| `/场景档案` | 1-2 |
| `/资产提示词 all` | 3-4 |
| `/目录` | 5-6 |

**用户回复处理**：点头 / 修改决策点 / 修改文件段 / 重跑 / 回退 / 暂停保留。完整菜单与安全命令映射见 `references/gates/沙盒门控规范.md` §10。

## 4. 资产边界

> ⚠️ **AI 内部备忘**
> ────────────────────────────────────────────
> 🔒 引用锁：资产分类以 `references/storyboard/core/分镜_32_资产提示词.md` 判定规则为准——不以训练数据中「角色带道具」「场景含角色」的合体图习惯替代。
> 🚫 防呆标记：
>   - ⛔️ 角色设定卡不含场景描述和独立调度物 → 违者回到文件修正
>   - ⛔️ 物品三视图不含角色手持 → 违者回到文件修正
>   - ⛔️ 场景三视图不含角色站位 → 违者回到文件修正
> ────────────────────────────────────────────

资产提示词严格按三个档案生成——角色档案 → 角色设定卡、物品档案 → 物品三视图、场景档案 → 场景三视图。**一图一资产**。

分类判定（详见 `references/storyboard/core/分镜_32_资产提示词.md`）：

| 类型 | 写入 | 判定 |
|:---|:---|:---|
| 角色绑定内容 | `角色档案.md` / `角色设定卡.md` | 固定外观、配饰、身份标识、能力视觉 |
| 独立调度物 | `物品档案.md` / `物品三视图.md` | 可离开角色独立存在，被传递、交换、破坏 |
| 场景组成物 | `场景档案.md` / `场景三视图.md` | 固定属于空间结构或环境氛围 |

资产名和场景名保持短、稳定、全文一字不差。

## 6. `/目录`

> ⚠️ **AI 内部备忘**
> ────────────────────────────────────────────
> 🔒 引用锁：本阶段全部判断以 `§0.2 分集决策锁定表` 为准——禁止从训练数据重新分配集数/弧线/钩子。
> 📐 公式重载：
>   - 二阶段分配：冲击段 = 前80%集数，终结段 = 后20%
>   - 每集三标签：核心冲突事件（可视觉化）+ 情绪高点（情绪·段·强度/10）+ 钩子类型（悬念/反转/情绪/危机 四选一）
>   - 禁止标签清单：建立世界观、场景引入、角色出场、关系铺垫、背景交代、过渡集、缓冲集
>   - 钩子约束：同类型连续≤2段 / 终结段末集必须反转钩或危机钩(≥9/10) / 禁止信息钩
>   - 情绪弧线×题材兼容性 → 不兼容即阻断
> 🚫 防呆标记：
>   - ⛔️ 训练数据倾向「起承转合四阶段结构」→ 必须用 v2.0 二阶段冲击模型（砍掉起势/攀升/风暴/决战）
>   - ⛔️ 训练数据倾向「第1集建立世界观」→ §0.2 锁定表第1集必须直接入冲突核心
> ────────────────────────────────────────────

执行顺序：
1. 读取创意期全部产物 + `§0.1 锁定表`
2. **先填入 `§0.2 分集决策锁定表` 的 A.全局决策 + B.逐集锁定**（不可跳过）
3. 过锁定表自检 checklist（§0.2 底部，9条全过）
4. 再生成 `分集目录.md`、`.emotion-coupling-map.json`、`关键细节追踪表.md`
5. 按门控循环走完 checkpoint → 校验 → 摘要 → 菜单 → 等待

输出：`分集目录.md`、`.emotion-coupling-map.json`、`关键细节追踪表.md`。

`/分集 {N}` 启动时由 `pipeline_orchestrator.py` 自动检查前置产物。
