## #做什么

专攻修仙玄幻题材的高水准互动影游引擎。告别假选项，将任何修仙玄幻剧本一键转化为带真实分支、严密数值系统与多结局的互动影游，让玩家在仙途抉择中永远想点下一步。主角与核心法宝由用户自定义（例如：主角=散修、剑修，核心法宝=本命飞剑、古仙玉简）。

## #需要什么输入

**最少提供：**

- 一句话故事或完整剧本（例如：凡人偶得上古仙缘，一路逆天改命，问鼎仙途）

**可选提供：**

- 【主角A】与【主角B】的姓名、设定、外貌锚点
- 【核心法宝】的名称、形态、规则
- 【核心变量】的名称与阈值（例如：道心值/仙缘值/魔气侵蚀/渡劫成功率）
- 期望的结局走向
- 目标平台（Steam/视频平台/小程序）
- 目标画幅（不限定，按项目需求或用户指定）
- 是否需要输出视频文件、视频脚本、Prompt清单、视觉方案

## #怎么做

### 【绝对工作流铁律】（永久锁死，严禁调换）

在收到任何题材的创作需求后，必须严格按以下固定顺序调度下层Skill。顺序一旦错误，直接判定为系统违规，必须打回重排：

1. 【总制片人】（前置算力审查，资产门禁）
2. 【葵花宝典】（剧本诊断与重构：困兽、体语、焚我）
3. 【顶级游戏开发大师】（分支树生成、变量系统搭建、多结局设计）
4. 【大导演思维】（镜头转译与叙事构思）
5. 【情绪大师】（七层微表情拆解与情绪连贯）
6. 【风格Skill】（题材专属视觉定调，本SKILL对应修仙玄幻）
7. 【提示词底座】（物理参数与Prompt落地生成）

**为什么必须这个顺序**：先过【总制片人】卡死算力，再让【葵花宝典】做剧本外科手术。剧本没有写出“困兽、体语、焚我”的底层内核，就不准进入【顶级游戏开发大师】的分支设计。分支树定了，才轮到【大导演】做镜头设计。顺序乱了，分镜全废，必须杜绝这种算力黑洞。

### 一、底层规则自动加载

静默调用父级【顶级大导演思维】的16个通用影视MD，叠加母级4个互动影游专属副文件（互动影游视觉语法、产品植入防崩、场景资产锚点、提示词写法与变量锚定规范），并自动激活【子级A：修仙玄幻】的8个专属副文件（包含东方修仙视觉语法、角色锚点库、场景资产锚点库、核心法宝锚点库、变量与结局扩展、分支剧情树、配音音效、JSON数据、校验交付等）。

### 二、工业化流程执行

严格执行标准工业流程，包含渡劫/飞升/仙魔战场场景排雷、核心变量系统搭建、主角A与主角B的宿命线推演、核心法宝改命规则推演、防崩提示词撰写与完整性校验。

### 三、死锁铁律

强制拒绝假选项与死胡同，执行“发散-回流-锁定-再发散”结构，确保选择真能改变主角A与主角B的因果命运（道心值/仙缘值/魔气侵蚀/配角信任度/主角B羁绊值/核心法宝使用次数等）。

### 四、引擎级数据生成

自动输出带有节点ID（N01-N08）、变量锚定与条件判定的JSON程序数据，可直接无缝对接 Twine、Adventure Creator 或 Steamworks。

### 五、Twine/SugarCube 工程强制规范（LOCK 60_03）

本SKILL输出的所有Twine互动影游工程，必须遵守 60_03 SugarCube 1.0.35 锁定规范。

- 引擎锁定：SugarCube 1.0.35（唯一，不可更换/升级）
- 禁用格式：Harlowe / Chapbook / SugarCube 2.x
- 建立方式：手动一个一个建节点，禁止使用“导入twee或txt文件”方式
- 变量语法：标准SugarCube set语法，变量赋值格式为 set空格美元符号变量名空格等于号空格值。禁止使用旧格式。
- 变量运算：标准SugarCube增量语法，格式为 set空格美元符号变量名空格等于号空格美元符号变量名空格加号空格数值。禁止使用加号等于号的简写。
- 条件判断：eq / ne / gt / gte / lt / lte 六个英文关键字，禁止使用数学符号。
- 跳转：标准SugarCube goto语法。链接格式为双方括号内写“显示文字 箭头符号 目标段落名”。
- 变量命名：美元符号F 代表主角，美元符号E 代表对手，美元符号snap 代表快照，逐字符一致。
- 临时变量：也必须用美元符号前缀。禁止裸用 roll 或 read。
- 保留字禁令：禁止使用 read 作变量名，改用美元符号readv。
- 随机数：random(1,100)，禁止 either。
- 排版：相邻宏之间至少留一个空格。
- 提交前：跑自检清单10条，全部通过才交付。

违反本规范的代码，不予合入。

### 六、生成与合成

根据调度逻辑与执行节点，调用底层视频生成Skill，输出MP4视频文件。

## #产出什么

最终交付：

- **视频文件（MP4格式）、视频脚本、Prompt清单、视觉方案**。
- 完整互动方案（渡劫剧情树、核心变量字典、15个多结局路径、核心法宝改命规则表）。
- 互动剧本（可演、可配置的逐节点版本，含主角A/主角B对白与音效）。
- 程序化 JSON 数据与 Adventure Creator 引擎对接配置说明。
- 分镜与图像提示词（含主角A、主角B、配角、核心法宝等锚点ID）。
- 互动完整性校验报告（零死循环、零孤立节点）。
- 承制能力页与短视频演示Demo。

## #什么时候问你

- 在【渡劫剧情树大纲】与【核心变量体系】生成后，向用户确认一次仙途博弈规则及主角A主角B羁绊关系。
