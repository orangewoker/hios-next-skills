## 1. 目标与边界

AI 制片不是把每条提示词排队生成，而是把导演方案变成可追踪、可替换、可剪辑的生产系统。它负责：

- 找出会阻断全片的依赖；
- 提前验证高风险镜头；
- 给不同任务选择合适模型和工作流；
- 维护角色、场景、道具和镜头版本；
- 为失败准备 split、composite 与 fallback；
- 只把通过连续性和剪辑检查的素材标记为 ready-for-edit。

本模块不替代导演判断。若故事、表演或镜头设计有问题，回到上游修正，不以反复抽卡代替决策。

## 2. 从成片反推依赖图

### 2.1 dependency graph

先画 dependency graph，再开始生成：

```text
剧本定稿
  ├─角色身份资产 ─ 妆造/服装状态 ─ 人物参考帧
  ├─场景圣经 ─ 光色状态 ─ 空间参考帧/调度图
  ├─关键道具 ─ 状态变化版本
  └─分镜与剪辑接口
          ↓
      镜头首帧/尾帧
          ↓
      视频生成/分层生成
          ↓
      合成、修复、声音
          ↓
      ready-for-edit
```

每个节点记录：输入、负责人/工具、通过标准、输出版本、下游消费者。一个上游资产变化时，能立刻知道哪些镜头需要重做。

### 2.2 阻断型依赖

优先锁定：主角脸、核心妆造、主场景平面、关键道具、时间天气、画幅、主光方向、固定结局和关键转折镜头。它们一旦漂移，会连锁污染大量下游镜头。

## 3. 高风险优先

### 3.1 high-risk-first

生产顺序不按镜头号，而按 high-risk-first：先验证最可能失败、失败代价最大、会决定方案是否成立的镜头。

高风险通常包括：

- 多人接触、拥抱、打斗、摔倒、复杂手部动作；
- 长距离走位、转身、坐下起身与道具交互组合；
- 镜面、水面、透明材质、烟火和强风雨；
- 大范围机位运动与场景转换；
- 角色近景长表演、口型、哭戏和微表情；
- 需要固定 ending state 承接下一镜的动作；
- 固定结局、产品展示或核心证据不可出错的镜头。

先做 1–3 个“风险探针”，验证角色一致性、动作可行性和剪辑接口。失败时改设计仍便宜；全部普通镜头完成后才发现核心动作不可做，代价最大。

### 3.2 风险评分

可按 1–5 分评估：身份稳定、肢体/道具、空间连续、摄影机复杂、结尾状态、生成成本、下游依赖。总分越高越早测试。

## 4. 模型路由

### 4.1 model routing

model routing 按任务特性选择，不迷信单一模型：

| 任务 | 优先能力 | 常用路径 |
|---|---|---|
| 角色定妆 | 身份稳定、细节、参考一致 | 文生图探索 → 图生图锁定 |
| 场景资产 | 空间结构、材质、风格一致 | 文生图/结构参考 |
| 微表演特写 | 人脸稳定、细微运动 | 稳定首帧 → image-to-video |
| 无人物环境镜头 | 空间运动、天气、大气 | text-to-video 或 image-to-video |
| 复杂动作 | 运动理解、参考控制 | 分段生成/关键帧/动作参考 |
| 手与道具特写 | 局部控制、短动作 | 独立插入镜头/局部修复 |
| 大幅运镜 | 摄影机控制 | 简化主体动作，单一运镜模型 |
| 口型台词 | 音画同步、人脸稳定 | 先表演/口型，再合成或短句拆分 |

每次路由记录选择理由、限制、预期失败模式和 fallback，不仅写模型名称。

## 5. 资产与版本账本

### 5.1 version ledger

version ledger 是唯一真相源。建议字段：

| ID | 类型 | 版本 | 状态 | 锁定项 | 变化原因 | 下游镜头 | 文件/链接 |
|---|---|---|---|---|---|---|---|
| CH-A | 角色 | v03 | approved | 脸、发型、肤色 | 定妆确认 | 01–18 | … |
| SC-02 | 场景 | v02 | approved | 平面、门窗、主光 | 窗位修正 | 06–14 | … |
| PR-LTR | 道具 | v04 | active | 红蜡封、折痕 | 状态变脏 | 09–12 | … |

状态至少使用：draft、review、approved、deprecated。禁止在正式镜头中引用未批准或已废弃资产。

### 5.2 命名建议

`项目_集场_镜头_资产/角色_版本_状态`

例如：`FOX_E01S03_SH07_CH-A_v03_approved.png`。

镜头生成还需保存提示词版本、参考资产版本、模型/参数、种子（若有）、时长、画幅、生成日期和选择理由。

## 6. 镜头生产卡

每镜一张卡：

| 字段 | 内容 |
|---|---|
| 镜头号/戏剧目的 | 本镜改变什么 |
| 风险等级 | 高/中/低及原因 |
| 上游依赖 | 角色、场景、道具、首帧、尾帧 |
| model routing | 模型/流程及选择理由 |
| 生成合同 | opening state、动作、camera、ending state |
| 连续性锚点 | 轴线、视线、动作、光色、服化道 |
| 验收标准 | 表演、构图、动作、画质、可剪辑性 |
| split/composite | 预案 |
| fallback | 最低可交付方案 |
| 当前版本/状态 | draft/review/approved/ready-for-edit |

## 7. 拆分、合成与降级

### 7.1 split

出现以下任一情况优先 split：一镜超过一个主要动作、多人互相接触、动作与大运镜同时发生、首尾状态都必须精确、道具发生复杂变形、长台词伴随走位。

拆分方法：

- 动作拆：伸手 / 接触 / 结果；
- 景别拆：全景交代 / 中景动作 / 特写证据；
- 主体拆：A 表演 / B 反应 / 双人关系镜头；
- 时间拆：动作前压迫 / 瞬间 / 余波。

### 7.2 composite

composite 适合模型难以一次稳定完成但层间可分离的任务：人物 + 背景、手部/道具替换、屏幕内容、雨雪烟雾、镜面反射、群演、光效、口型。

合成前要确保机位、透视、光向、接触阴影、景深、运动模糊和颗粒一致。不要把合成当成“不用设计”的借口。

### 7.3 fallback

fallback 从保留戏剧功能出发：

1. 减少背景和次级动作；
2. 固定机位、缩短时长；
3. 用近景/插入替代复杂全身动作；
4. 用反应镜头和声音隐藏动作中段；
5. 分层生成后 composite；
6. 用静态帧、闪白、遮挡或剪辑点表达结果；
7. 重写调度，但不得破坏剧情因果和关键证据。

## 8. 失败诊断

失败后禁止只写“再生成一次”。按类别记录：

- **剧作失败**：镜头没有清楚的变化或信息目的；
- **表演失败**：动作缺刺激和目标，表情随机；
- **身份失败**：脸、体型、服装或年龄漂移；
- **空间失败**：轴线、门窗、视线、比例或背景改变；
- **动作失败**：肢体、接触、道具或物理路径错误；
- **摄影失败**：运镜、焦点、景别和构图失控；
- **光色失败**：光源方向、曝光、肤色或时间跳变；
- **画质失败**：闪烁、穿模、纹理呼吸、局部畸变；
- **剪辑失败**：没有可用入点/出点，ending state 无法承接。

每次修正只改变与根因相关的变量，保留其余已通过部分。连续三次同类失败，应切换 model routing 或采用 split/composite/fallback，不继续盲抽。

## 9. 可剪辑状态

### 9.1 ready-for-edit

素材只有满足以下条件才标记 ready-for-edit：

- 戏剧目的可读，表演动作有因果；
- 角色、服装、道具和空间连续；
- 主体动作完整，至少有可用入点与出点；
- ending state 能与计划的下一镜 handoff；
- 光向、肤色、曝光和色板在可调范围内；
- 无遮挡叙事信息的畸变或闪烁；
- 声音/口型需求有明确后续路径；
- 版本、提示词、参考资产和处理记录齐全。

“看起来不错”不等于可剪辑。孤立漂亮但无法承接的素材保持 review 状态。

### 9.2 剪辑隐藏策略

若瑕疵不破坏关键动作，可用：切反应、插入道具、动作匹配、声音先行/延续、遮挡点切换、速度微调、短帧替换。不可隐藏身份崩坏、因果错误、关键证据缺失或表演意思相反。

## 10. 生产排程

推荐顺序：

1. 锁剧本、固定结局与三道确认；
2. 建 dependency graph；
3. 锁角色/妆造、主场景、关键道具；
4. 复杂多人场景先批准 blocking diagram，再用 storyboard still 和首尾帧验证构图/连续性；
5. high-risk-first 做风险探针；
6. 冻结可行的 model routing；
7. 批量生产低风险主干镜头；
8. 生产反应、插入和转场镜头；
9. split/composite/修复失败镜头；
10. 检查 ready-for-edit，进入粗剪；
11. 粗剪暴露缺口后只补必要镜头；
12. 声音、调色、视效与最终质量门。

并行生产只用于依赖已经锁定的独立镜头。共享角色或场景仍在变化时，不要盲目并行扩大返工。

## 11. 常见失控与校正

### 失控：按镜头号从头生成

校正：建立风险表，先做会推翻方案的高风险动作和关键转折。

### 失控：模型失败就延长提示词

校正：诊断根因；在动作过载时 split，在身份/空间不稳时换参考控制，在层间冲突时 composite。

### 失控：文件多但没有版本关系

校正：建立 version ledger，镜头卡必须引用批准资产版本。

### 失控：漂亮素材全部进剪辑

校正：只有通过连续性、入出点和 handoff 检查的素材才标记 ready-for-edit。

### 失控：用后期救无法成立的戏

校正：剧作、表演和关键因果问题必须返回上游；后期只处理表现和技术缺陷。

## 12. 交付检查

- 是否有完整 dependency graph？
- 是否执行 high-risk-first，而非顺序抽卡？
- 每类任务是否有明确 model routing 与理由？
- version ledger 是否能追溯所有正式镜头？
- 每镜是否有 split、composite 或 fallback 预案？
- 连续失败是否触发了路径切换？
- ready-for-edit 是否依据可剪辑标准，而非主观漂亮？
- 关键失败是否在粗剪前暴露并处理？

## 13. 无限画布生产协议

无限画布不是把文件摊开，而是把资产复用、镜头试错和精修路径显式化。使用 **anchor hub → shot family → feedback loop → finishing chain** 四层结构，让任何成品镜头都能回溯到参考资产、提示词、模型参数和处理步骤。

### 13.1 节点角色

| 节点角色 | 内容 | 允许的下游 |
|---|---|---|
| source | 用户上传、勘景、原始参考、旧版素材 | anchor、分析或修复节点 |
| anchor | 已批准的角色、妆造、场景、道具、色卡、生物/机械设定 | 多个 image/video shot 节点 |
| attempt | 一次图片或视频生成结果 | review、截帧、变体、延长、修复 |
| feedback | 从可用视频提取的帧、局部修复图或重新裁切的构图参考 | 新一轮 image/video shot 节点 |
| utility | 截帧、裁剪、去字幕、图像/视频放大、稳定、局部修复 | review 或下一个 utility |
| deliverable | 通过验收的主镜、备选镜、插入镜或 ready-for-edit 版本 | 剪辑与声音 |

不要覆盖旧 attempt。保留失败与候选分支，用状态或命名区分 `rejected / alt / approved / ready-for-edit`，否则无法判断哪次变量变化真正改善了结果。

### 13.2 连接必须声明职责

每条参考连线写明其职责，不用一张图模糊承担所有控制：

- `identity anchor`：锁脸、体态、妆造与服装；
- `scene anchor`：锁空间几何、入口出口、时间天气与主光；
- `prop anchor`：锁道具外形、材质、握持侧和状态；
- `palette anchor`：只锁色域、对比与材质色响应，不替代场景图；
- `creature/mechanical anchor`：锁结构、比例、关节与表面材质；
- `composition/first-frame anchor`：锁机位、景别、主体位置和开场状态；
- `motion anchor`：锁动作节律、路径或表演强度；
- `last-frame anchor`：锁 ending state 与下一镜接口。

一个 anchor 可以分叉给多个镜头，但每个镜头只连接确实需要的参考。参考过多会产生控制冲突；若两个参考职责重叠或互相矛盾，先合并成一个批准版本再生成。

### 13.3 画布分区

按工作语义分组，不按文件类型堆放：

1. `Project Locks`：画幅、世界规则、STYLE LOCK、色板与禁项；
2. `Asset Anchors`：角色、场景、道具、生物、机械或产品资产；
3. `Shot Families`：每个 beat 或镜头一组，包含首帧、尾帧、视频尝试和备选；
4. `Feedback Loops`：成功视频截帧、延长、动作变体、构图修复；
5. `Finishing`：裁剪、去字幕、放大、稳定、修复与输出规格；
6. `Deliverables`：只放 approved 或 ready-for-edit 版本。

画布读向保持一致，例如左到右表示依赖推进、上到下表示同一镜头的迭代。资产 hub 放在镜头族上游；同一镜头的候选排成邻近分支，不要让连接线跨越整个画布形成无法审计的网。

### 13.4 单个视频节点的内部合同

每个视频生成节点按固定顺序写：

1. `[STYLE LOCK]`：项目级写实度、色调、材质、光线与禁用审美；
2. `Reference Roles`：逐一说明每个输入参考负责锁什么；
3. `Audio Policy`：明确只要环境/动作声、需要音乐、需要对白，或完全静音；
4. `Opening State`：人物、道具、空间、光线和摄影机的确定起点；
5. `One Main Action`：触发、动作路径、幅度、速度与停止点；
6. `Camera and Composition`：机位、景别、唯一主要运镜和构图变化；
7. `Physical Response`：衣料、尘土、烟、光、接触阴影和声音反馈；
8. `Ending State / Handoff`：可见结果和下一镜接力点；
9. `Shot-specific Prohibitions`：只写本镜高风险禁项；
10. `Generation Settings`：模型、画幅、分辨率、时长和模式。

STYLE LOCK 只保存跨镜不变量；镜头动作不要塞进项目级锁定层。参考角色说明应写成“作为角色视觉锚定”“作为色卡锚定”等可审计语句，而不是只列附件编号。

“One Main Action”是单一因果动作脊柱，不等于一次肢体动作。连续长镜头可包含 3–5 个有序微节拍，只要目标、方向与 ending state 统一。若平台/模式支持单节点多镜头，可在同一节点内使用 3–5 个显式 `HARD CUT` 子段；每段仍须有独立镜头契约，并共享同一 blocking diagram、角色/场景/道具/色卡/voice anchors。平台能力未知、空间复杂或风险探针发生漂移时，使用独立视频节点，不把单节点当成质量目标。

### 13.5 回流与精修链

遇到以下情况建立 feedback loop，而不是重写全部提示词：

- 某段视频的角色、构图或光线正确，但动作后半失败：从成功区间截帧，作为新 first frame 延长或重生成；
- 某个 attempt 只在一个动作或镜头运动上失败：保留原 anchor，只改变对应变量，生成并列分支；
- 已批准资产只有一个局部错误：建立 minimal-delta edit 分支，只遮罩/修改目标区域，显式冻结其余全部内容；批准后用修正版替换正式 anchor，不让新旧版同时服务下游；
- 一个视频结果提供了更可靠的角色角度、道具状态或环境状态：截帧后先审定为 feedback，不直接升级为项目 anchor；
- 连续镜头需要共享 ending state：把上镜批准尾帧连接到下镜 composition/first-frame anchor。

典型 finishing chain：

`video attempt → 截帧/挑选可用段 → 裁剪或延长 → 去字幕/水印（若来源允许且确有需要） → 稳定/局部修复 → upscale → ready-for-edit`

每个 utility 节点只做一种变换，并保留处理前版本。放大是最后的质量提升，不用于掩盖身份、动作、空间或叙事错误。

### 13.6 Attempt Delta Ledger（版本差分台账）

同一镜头的每次尝试都必须回答：**本版从哪个父版本分出，只测试了什么，以及是否破坏了已经通过的部分。** 不要用“v2 更好”代替可归因结论。

先给分支定类：

| 分支类型 | 允许变化 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| `sample branch` 抽样分支 | 提示词、模型、参考、参数全部不变，只换 seed 或同配置重抽 | 当前配置的随机分布、偶发成功或失败 | 某条提示词或控制方法已经修好问题 |
| `diagnostic branch` 诊断分支 | 相对父版只改一个主变量 | 该变量与目标问题的因果关系 | 多个同时变化的因素各自贡献了什么 |
| `fallback branch` 降级分支 | 在同类失败连续出现后，切模型路由、拆镜、合成、缩短或重写调度 | 原路线已不经济，替代路线能否保住戏剧功能 | 原路线中的单个提示词变量是否有效 |

分类优先级是硬规则：**只要唯一变化是 seed 或同配置重抽，就必须标为 `sample branch`，不得标成 diagnostic；baseline 是父节点状态，不是分支类型；同时改变两个及以上非机械耦合变量的结果标为 `confounded/exploratory`，不能进入因果结论。**

诊断分支执行 **one-primary-variable change budget**：每版只允许一个主变量。若技术上必须联动第二项，例如更换模型必须同步更换其专属采样器，要把它声明为“机械耦合项”，不得伪装成单变量实验。若提示词、模型、参考图、首帧、负面词和 seed 同时变化，该结果只能作为候选样本，不能用于归因。

每版使用以下台账：

| Attempt | 父版本 | 分支类型 | 失败假设 | 唯一主变量 | 冻结项 | 通过项 | 失败项 | 未知项 | 回归 | 决策 / 下一步 |
|---|---|---|---|---|---|---|---|---|---|---|
| SH07-A | — | baseline | — | — | — | identity | camera | ending | 无 | 从 A 建诊断分支 |
| SH07-B | SH07-A | diagnostic | 运镜指令含混 | camera clause | model、seed、anchors、first frame、其余 prompt | identity | camera | — | 无 | 否定该假设或改下一个单变量 |

执行规则：

1. **先冻结已通过项。** 父版的身份、空间、光向、道具或 ending state 已通过，就写进冻结项；子版的目标改善但任一冻结项退化，必须记录为 regression，不能只写“整体更好”。
2. **抽样成功不等于修复成功。** seed-only 的好结果可以作为剪辑备选，但只有同配置复抽或相邻样本达到预定通过率，才能提升对路线稳定性的信心。
3. **诊断成功需要双门。** 目标失败项改善，且所有冻结项无回归，才支持该假设；否则保留父版并继续隔离变量。
4. **回流帧先审后升。** 从视频截出的成功帧先标为 `feedback`，核查身份、几何、道具、光向和画质；通过后才可升级为新 anchor，并记录它来自哪个 attempt、替代哪个旧 anchor、影响哪些下游。
5. **三次同类失败切路线。** 连续三个可比诊断/抽样结果仍出现同类失败，不再增加同类措辞；建立 fallback branch，切换模型路由、缩短时长、固定机位、拆镜或 composite。
6. **不要删除反证。** rejected attempt 保留父子关系、配置和失败标签；没有失败样本，就无法判断后续改动是真改善还是随机波动。

失败类型到首选主变量的映射：

| 失败类型 | 下一诊断分支优先只改 | 若连续失败的 fallback |
|---|---|---|
| 身份漂移 | identity anchor 强度/角度，或降低主体运动（二选一） | 稳定首帧图生视频、近景拆镜、身份层合成 |
| 空间/左右漂移 | blocking/composition first frame，或单独空间约束（二选一） | 独立镜头节点、批准尾帧接下一首帧 |
| 动作拓扑失败 | 减少微节拍，或更换 motion anchor（二选一） | 动作拆段、插入/反应镜头遮蔽中段 |
| 运镜失败 | 按症状只改一项：运动轨迹/速度错 → camera clause；起幅构图错 → first-frame anchor；落幅错 → last-frame anchor；无动机漂移 → 锁机位 | 稳定主体后做后期运镜或换摄影机控制路线 |
| 手/道具交互失败 | 只改道具锚点或握持起始状态 | 独立插入镜头、局部修复或 composite |
| ending state 失败 | 只改 last-frame anchor 或缩短动作尾段 | 上一批准尾帧回流、拆成结果镜头 |
| 对白/声音归属失败 | voice anchor、短句长度或音画流程之一 | 分离口型/声音节点，后期配音与同步 |
| 纯画质失败 | 单一 utility 修复参数 | 稳定、局部修复、最后 upscale；不得掩盖叙事/身份/空间错误 |

### 13.7 画布验收

- 每个正式镜头是否能沿连线回溯到批准 anchor？
- 每条参考边是否有单一、明确的职责？
- 同一 anchor 是否被复用于镜头族，而不是重复生成相似资产？
- 失败 attempt 是否保留，且能看出下一分支只改了什么？
- 每个 attempt 是否有父版本、分支类型、失败假设、主变量和冻结项？
- 是否把 seed-only 抽样与真正的诊断分支分开，且检查了目标改善之外的回归？
- 诊断分支是否遵守一个主变量的变化预算；机械耦合的次变量是否被显式声明？
- 连续三次同类失败是否建立 fallback branch，而非继续堆提示词？
- 是否存在 `video → 截帧 → 新首帧/延长` 的可追溯回流？
- 裁剪、去字幕、放大和修复是否位于生成后，不污染原始版本？
- deliverable 区是否只包含通过连续性与剪辑检查的版本？
