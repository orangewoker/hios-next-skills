# 注意事项

- **构图约束的适用边界**：
  - 整图直出（路线 A）时，严禁改动底图构图，取景、人物大小与位置、场景元素一律不动。
  - 小脸走腰上像路径时，构图约束的对象转为「裁切后的腰上像内部」——腰上像内部的取景、人物姿态、服装、首饰、背景、光影仍须逐像素保真，不得在裁切基础上再擅自改变构图或增删内容；而「相对原整图改变了取景范围」这一项在此路径下是被允许的既定行为，不视为违规。
  - 若用户额外要求回贴原图或要求整图交付，则回到整图路径，此时构图约束全额生效；并须提前告知用户：小脸在整图上直接换脸会导致五官细节不足、相似度下降，回贴方案还需额外生成次数与接缝风险。
- **相似度优先**：冲突时按 SKILL.md「相似度优先级」的统一裁决句处理——骨相相似度第一，妆容/光感/色感第二，皮肤质感不参与排序（非验收项），表情与眼神始终最高不让位。注意：骨相优先仅作用于结构特征，不得覆盖情绪基调。
- **只迁骨相，不迁妆容**：妆容、肤色与质感以底图为准，绝不随参考脸迁移；在不牺牲骨相相似度的前提下尽量满足。
- **四项必锁**：锁妆容、锁光感、锁色感、锁眼神表情为强制骨架，缺一不可；与骨相相似度冲突时按统一裁决句让位。
- **分工声明**：必须使用禁令句式（如「禁止保留底图五官形状」）以防止身份信号被底图反扑。
- **画幅匹配**：不支持 Adaptive，必须换算为预设比例档位，防止取景漂移。
- **小脸必裁切**：人脸占比较小（原生宽度 &lt;250px，含 225–275px 临界区）时必须先裁切腰上像并放大再换脸，不得直接在整图上处理小脸；默认直接交付腰上像成品，不回贴原图。
- **裁切成本须提前提示**：与本条并列于「小脸必裁切」「像素回读实测」。凡确认要走裁切腰上像路径（含临界区按小脸处理、以及裁切放大后仍 &lt;250px 需追加超分前置的情形），必须在生成前向用户提示：需走裁切腰上像路径、本工作流内完成「裁切放大 + 换脸」大概率约 150~200 积分、建议先在其他方式／其他工作流中裁切放大好腰上像再交回本 Skill 换脸。这是提示义务而非阻断条件——用户知悉后仍要一步做完则照常执行，不得拒绝或反复劝阻；用户自备腰上像则不触发提示，直接以其为底图换脸。
- **神态锚点须先复核再下笔**：视线方向、头部朝向与偏转角、情绪基调三项，凡写入 prompt 前必须先复核，不得凭缩略图或第一印象直接下笔（详见 SKILL.md「神态锚点复核」）。**复核须量化到眼睑级**（上眼睑下盖量、眼裂开合度、视线夹角、眼球位置、眉部高度、上睫毛朝向、眼尾线条、笑意类型、失焦感），禁止用「平视略偏下」「眼神温柔」「眉眼低垂」等未量化的日常词作为锚点结论。这是「像素判断必须回读实测」在神态维度的延伸，二者同源同理。复核结果与第一印象不一致时以复核为准并在报告注明；仍无法确定时须请用户确认，不得猜测填入。
- **段落互相抵消须检查**：撰写完成后须交叉检查侧面结构类、骨相类、妆容类用词是否会抵消视线／低垂／表情／情绪这些最高级锚点。高风险词（居中、摆正、自然位置、不前置、立体、有神、睁亮、饱满、挺拔、清晰锐利）若落在眼球、眼睑、眉部、唇部附近，须在同句内写明优先级裁决句（如「本条不得被理解为把眼睛睁开摆正，低垂优先」）。
- **正面参考 × 侧脸底图须侧面转译**：严禁把正面照五官的表现强度等强度还原到侧面轮廓；须按 `references/profile-translation.md` 转译为侧面解剖下的自然形态，保证轮廓线平滑连贯。检测到该组合时须主动提示特征强度与自然度不可兼得的代价，并建议索取侧面参考图。
- **档位取 quality: high, resolution: 2K（写死英文枚举，禁用中文档位词）**：质量档一律 high、分辨率一律 2K；quality_spec 固定写 `quality: high, resolution: 2K`，不得写任何中文档位词（「高画质」「高质量」「超高画质」「超清」「极致」「最高」等一律禁用）。理由（事故记录）：v22 曾按中文「2K 高画质档」传入，实际落到 quality: xhigh、resolution: 2K（成品 i-cg8nk64wt878）；经查 xhigh 在平台界面的中文标签是「超高画质」而非「高画质」，用户所要的高画质对应枚举 high。同一「高」字开头的措辞映射结果随机（本会话累计：「4K 高质量档」曾分别落到 high、xhigh、max；「2K 高画质档」落到 xhigh），故不得再以中文档位词指定档位。批量交付档位必须一致；实际生效档位与分辨率须回读留痕，不得事后追认、不得凭措辞推断映射关系而宣称合规。
- **升级需留痕**：任何档位升级都必须在核对报告中写明命中条目；重绘档须先取得用户明确同意。
- **已知规律——发尾卷度偏移**：prompt 层面无法根除——发尾被带卷在同类底图上多次复发，即使写成与妆容锁定同级的禁令也只能减轻、未能消除。遇此情形不要反复在 prompt 上加码重试，应直接告知用户两条替代路径：① 交付后局部后期修直；② 改用换头档重做。并在核对报告中如实标注 ⚠️。
- **已知规律——皮肤质感美颜惯性**：为模型能力上限，已验证 7 张均无法完全压制；遇此情形不要加码 prompt 或重跑，改为交付后提示用户后期处理。与「发尾卷度 prompt 层面无法根除」并列，二者同属「不要再试图用 prompt 解决」类。
- **已知规律——情绪漂移（写实参考脸气质与底图差异大时高发）**：写实参考脸若自身气质与底图人物情绪差异较大（如冷艳参考 × 温婉底图），情绪漂移为高发问题。须在开工前提示用户该风险，并建议在 prompt 中把情绪项写得比骨相项更详尽。
- **已知规律——神态量化词缺失导致低垂丢失**：底图眉眼低垂、出神失焦类神态，若锚点只用日常词描述，模型会默认把眼睛睁大、上眼睑抬高、视线抬平；必须量化到眼睑级并单列失焦感。
- **待办记录——i-cg8nk64wt878 档位跑偏**：该成品（CT19 躺姿 v2）实际落到 xhigh，按新规则判为跑偏；其效果未受损（xhigh 不低于 high），跑偏的实质后果是成本高一档、以及与该批次其他成品的档位不一致。是否重跑降级以统一批次档位由用户另行决定，本条不作为自动重跑触发。
- **维护规则——版本标识**：落点为 SKILL.md 的 YAML frontmatter，两个字段同步刷新。`version`：整数，每次更新递增 1，供机器读取。`updated_at`：展示字段，格式「v{版本号} · {YYYY-MM-DD}」，须与 version 的数值一致，不得出现 version: 25 而 updated_at 写 v24 的错位。时间精度两级：用户提供精确时刻时，updated_at 用「v{版本号} · {YYYY-MM-DD HH:MM:SS}」；未提供时用日期粒度，禁止编造时分秒、禁止填占位 00:00:00。只保留最新一条，不累加历史版本记录。禁令：不得把版本信息写入 description（30 字符上限）、use_scenario、正文任何段落或 references/ 子文件；版本信息只存在于 frontmatter 这两个字段。理由：平台实际展示的是 updated_at，故版本序号必须并入该字段才能在版面上被看到；此前只写日期导致用户看不出第几版，本次即为此修正。落点沿革（避免后续再反复）：落点曾依次试过正文首段、use_scenario、正文「如何使用」段，最终由用户定为 frontmatter。
