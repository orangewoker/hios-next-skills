# Seedance 2.5 适配与七段视频提示词

准备Seedance 2.5提示词、生成、反打、接续、编辑或关键帧方案时读取。输入来自[任务包装](../generation/01-shot-task-packaging.md)：当前Shot/事件、导演覆盖、空间/声音、状态与接缝、Binding及入口能力。已有有效决定按版本复用，只有缺失/失效项才回上游，补足后返回当前编译步骤；文档互链不是重跑流程。仅写草案可保留明示缺口，不以预算或不存在的母板阻塞文字探索。

## 厂商说明与执行边界

[厂商发布与已核中文指南](../evidence/01-sources.md#seedance)介绍单次最长30秒、多模态参考、编辑和延长；产品页的两次延长与发布文的多轮表述分别保留，不解释为无限接续。2026-09-06已读中文主指南及官方直链详细指南的有关章节，不声称通读全部案例；旧BytePlus英文页未得完整正文的历史状态不覆盖成已读。七段是用户选定的本Skill组织格式，不是官方强制七栏。

这些不是LibTV网页当前契约。按当前工具核模式、时长/数量、输入角色、分辨率、声音、计费与可观察方式。菜单的全能参考/30s/720P宣传不证明每个值均可提交；不固定mixed2video或旧Beta范围，不静默换模型。首尾图文字指定与真实首尾角色是否锁画幅，官方资料存在[入口/版本待核冲突](../evidence/01-sources.md#seedance-frame-conflict)，不能由一句文字推定底层角色已设置。

### 方舟 API 指南中的已记录限制：LibTV 网页仍待验证

以下只标记为 `documented（火山方舟 API，2026-08-11 指南）`，不写成 LibTV 网页字段或本项目已验证能力。正式提交前，Agent仍须读取当前网页入口的实际选项、回执和费用契约：

| 指南记录 | 编译时的保守用法 |
|---|---|
| 单次视频请求最长30秒；参考素材合计上限50，指南按类型给出图片、视频、音频的数量/时长范围 | 将其作为 API 侧容量提示；LibTV网页未核前不得自动把50或30秒当可提交值，超出当前网页可核范围就拆成受限请求或保留缺口 |
| 图片、视频、音频参考按上传顺序和媒体类型编号，正文逐一说明素材职责 | 先建立本次实际附件顺序与职责表；不把项目逻辑ID、Mixed显示名或猜测槽位直接编成 `@ImageN` |
| 时间段用于指导顺序与节奏，API指南建议连续的整数秒区间，不是帧级剪辑指令 | 用连续整数秒表达阶段；0.1秒闪白、精确帧点和细粒度剪切留为创作意图，交真实网页后期或观察核验 |
| 编辑、延长、首帧/尾帧和参考图路径可能有画幅/时长锁定差异；`duration`、`ratio` 等字段属于相应 API 入口 | 只有网页实际暴露并回读这些参数时才使用；否则写明待验证，不把 API 参数复制为网页请求字段 |
| 主体多图、首尾帧、多宫格和关键帧各有不同的参考稳定性与对齐行为；“1–8张较稳定”等是指南经验或建议，不是本Skill的硬质量保证 | 按本镜生效阶段最小化上传并逐图声明同一人物/用途；返回后按实际视听观察授予用途资格，不以数量推定一致性 |

七段是本Skill的编译排版，不是方舟指南要求的固定七栏；指南中的主体/运动/环境/美学/镜头/音频概念由本地七段映射表达。

## 唯一七段规范

本规范只用于Seedance 2.5视频提示词；图像请求、其他模型和状态诊断不套七段。下列段内说明是Agent的填写责任，不是直接照抄的模型文案。每份即将使用的完整视频提示词按下列顺序保留七个标题，声音放Action及有关Constraints，不另加第八段。仅讨论/修改局部时可先展示差异；形成完整新请求时再编译七段。其他文件可展示填写实例，只引用本处规范，不另维护模板规则。

【Subject 主体】
参与主体及身份/衣着/道具特征；实际参考各负责什么、适用哪个故事阶段、允许继承哪些维度。同一角色有多张状态图时，正文逐图声明“同一人物＋故事阶段＋本镜用途/复用维度”；默认只上传本镜生效阶段的源，未生效状态图除非入口能隔离职责且本次确有用途，否则不上传。一段戏跨越多个状态（如正常→受伤→觉醒）时必须按状态转折拆成多个 Job，不得把多张状态图同时挂进一个请求靠职责句隔离（根 SKILL.md 路由表后的拆 Job 规则）。纯文本首次探索可定义新主体；未核素材标为草案意图，不造已绑定身份。

【Action 动作】
本Job承担的事件、起始状态、主要动作/反应和结束可观察状态。按叙事阶段组织；必要节拍再标时间。对白写说话者和词句，动作声/系统音写声源、内容与触发；有可见文字需求时另写出现位置、内容和可读职责。多镜任务按同组镜头标签逐项对应Camera；不要把整场重复塞入每个Job。

【Setting 场景】
本时段地点、空间/道具状态、行动涉及的地标与路径、实际场景来源用途。内部坐标/图内编号只有在本次实际送给模型的文字或媒体中带有清楚映射时才使用；仅Agent内部卡有图例不够。可用正文地标解释，不强制每次上传布局图；必要设计图本身仍须完成设计核对。

【Camera 运镜】
连续镜头还是多个视点，各镜标签、景别、机位、运动/停点与观看职责。以可观察的取景范围、人物/地标关系、运动路径和停点替换未定义的内部控制词；导演的观看意图必须落成模型可执行的画面描述，不能只写“让观众感到犹豫”。停顿的Camera读取点只写同一Shot标签下的取景关系、运动和停点；触发与可见动作留在Action，避免重复或改写剧本事实。固定机位不自动等于禁止切镜；用户锁定形式优先，动作容不下先回覆盖设计。

停顿的完整编译句式由同一Shot标签的Action与Camera共同组成：Action写“剧本/行动谱中的触发 → 可见动作或静止”，Camera写“读取点 → 取景关系/运动/停点”。例如本场可写“听完‘爸的字，你认得’句尾 → 握肩带的手停住并看向门，随后才取下包 → 宽景同时保留手、脸和门的关系”。不要把心理词直接当成运镜指令，也不要在模型请求里留下“自行判断停顿怎么拍”。

【Lighting 光影】
实际光源、方向、时段和剧情引发的变化，与空间状态一致；若本场空间卡有关键光区／层次记录，按前／中／后景承载物、光源覆盖、注意力转移和遮挡／反光代价消费；标为“不适用”时不强行补陈设。来源图的月夜或戏剧光不自动变成人物身份。

【Style 风格】
经确认的视觉语言与质感，引用只继承被指定的处理；色值可表达意图，不承诺像素级锁色。

【Constraints 约束】
贯穿本任务的稳定条件、允许变化与少量相关排除。无配乐、无字幕或面板无文字仅在当前项目确有此约束时写；不得移植别案而删掉本案系统音/可见文字。不用通用否定词长串代替动作设计或效果保证。

模型正文只保留本任务可执行的参考用途和画面/声音描述；项目记录、预算、提交、保存版本、读取缺项、回看验收或“返回覆盖设计”等Agent流程放在七段外的参数与验收说明。缺事实时在正文外标草案缺口，先读现有依据或补设计，不能用“提交前自行查询后填写”填充模型段落。参考用途、可观察的保持/改变项属于正文内容，不因这个边界删掉它们。

同一事实放最合适的段落，不逐段重复。阶段数与秒数不固定；若当前入口采用指南所述时间段，优先使用连续整数秒区间。时间戳是节奏意图，不是精确成片切点，0.1秒闪白等需由实际可用网页后期验证，否则明确未实现精度。

<a id="request-presentation"></a>
## 请求卡与适用核对

可读请求顺序：本次目的短句 → 素材用途及必要镜头对应 → 七段正文 → 必要参数/验收说明。[用户输出](../core/06-user-output.md)沿用此顺序，不增加另一套五行模板。内部记录保留“正文镜头标签↔Shot ID/版本↔本Job事件”，单镜一行即可；不强塞审计ID或整屏JSON进模型正文。

素材从[绑定映射](../assets/03-reference-binding.md#reference-map)取得：本项目实际对象/版本、故事状态、媒体、用途与当前入口引用。正文标记、附件槽位以及混合媒体的编号规则按本次入口核验，不按名称外形猜键；无正文标记但槽位可靠时照常编译。添加/删除/重排后更新对应，实际参数也与正文一致。只写草案可用明确的未核占位，示例编号不变成平台引用。

新提交前检查：七段齐且作用域正确，段内是模型可执行内容，Agent流程与未定项位于正文外；事件、视听职责与Action/Camera镜头标签一致；状态和参考未泄露未来事件；空间映射确在模型输入中；当前Binding与实际输入相同；所需接点/声音证据和入口分支成立。给定约束冲突先回相应设计或绑定责任处；只限制受影响提交。完整实例见[修理店请求](../examples/01-dialogue-scene.md#seedance-filled-example)，失败恢复仍由[提交核对](../generation/05-submit-reconcile.md)负责。

## 同一格式下的任务分支

| 分支 | 七段如何改变 | 执行前实据 |
|---|---|---|
| 新生成，单镜或多镜 | 明确本Job事件、开头/结束状态；多镜Action/Camera标签同步 | 实际入口支持所选表达，按表演与复杂度包装；低于上限不是必须合并理由 |
| 同场反打 | 用新视点表达本镜时段和观看职责，继承适用身份/布局/状态 | 必要自身设计前置成立；不消费前片就不等待它，不强制以前片尾帧锁构图。可重演同一时点动作留试剪余量，最终不把一次动作无意剪成两次 |
| 向后延长 | 明确唯一实际输入视频/版本、目标末边界状态，新内容从该处开始 | 核[真实接续边界](../visual/04-continuity-seams.md#extension-input)及连续画面/必要声音；不能把原Take尾部当剪短Clip出点 |
| 向前延长 | 新内容最终接实际输入的目标首边界，保持其动作趋势与声音 | 同样核实际媒体和可寻址边界，方向与后延长不同，不假定输入支持任意中点 |
| 局部编辑 | 写唯一实际母版、目标对象/区间/属性；未变段简明继承该母版对应内容 | 例：仅改右侧灯颜色，其余人物、时间线、动作/相机继承已定位母版；不重写整场导演方案。无母版可写编辑草案，不能执行消费未知源的编辑 |
| 首尾或多关键帧 | 逐份写状态、顺序、职责与中间事件，区分语义参考和严格锚点 | 真实首/尾角色和画幅约束由入口核验；文字称首帧不等于已设置角色；不推定一切关键帧均逐帧锁定 |

参考动作视频/预演只在入口支持且该源用途合格时消费；静态站位不证明运动速度或完整路径。只有文字状态时可设计或探索，不冒充已严格继承真实动作/声音。不同分支不需要改变的内容继承明确母版对应范围，不能空泛写“保持一致”。

## 结果、失败与旧请求

执行终态与作品资格分开；按实际片段观察事件、身份/道具、动作接触、镜头边界、空间、可见文字及声音，返回的时长/切点不硬套计划。实际实现有效且保留故事约束可更新对应；未听音频不报声画通过。

参数或引用错误先读真实输入/回执，交[引用诊断](../assets/03-reference-binding.md#reference-diagnosis)和[失败回路](../generation/05-submit-reconcile.md#input-error-recovery)，不把用户重贴标签或改名称当验证。文案/覆盖本身错则回设计；文案正确而实现偏离再比较换段、改剪或最小返修，不盲重抽。

模板升级只影响尚未提交的草案及有依据的新请求。已提交/unknown的旧Attempt保留原快照、状态、额度和回执，不因不是七段重投或覆盖；当前编辑器内容不反向改写历史请求。旧素材按当前用途复验复用，升级不是全量重生成理由。产出仍为可追溯请求与用途资格，不声称稳定长篇生产已验证。
