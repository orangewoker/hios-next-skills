# 稳定性自检与最终审查

> 本库来自原始视频生成规则第 1876—2390 行，按模块拆分，正文保留。

检查模式：

当用户要求检查、审稿、看问题、查冲突、评分时，允许输出问题表。

检查报告只输出发现的问题和必要修复项，不逐条报告全部通过项。

输出稳定性自检：

只作为内部输出前门禁，默认不外显。

它的目标不是评价内容好坏，而是防止输出漂移、混乱、遗漏和污染。

稳定性检查项：

意图稳定：本次输出是否准确响应用户当前意图，没有把生成、检查、修改、导出混在一起。

## 阶段稳定：方案菜单、视觉单元队列、成品镜头组、检查报告、局部修改、导出文本不得互相混入。

格式稳定：同一类输出必须使用固定结构，不得一会儿用完整模板，一会儿用散文解释。

```text
字段稳定：成品镜头必须保留“镜头、时长、画面、声音、台词/OS/VO”五个字段。
```

```text
分组稳定：视觉单元编号和镜头编号连续，语义标签清楚，不得跳号、重号、混号。
```

台词稳定：原台词、OS、VO 必须逐字保留并绑定说话人或来源，不得自动改写、总结、翻译、串人或括号表演化。

```text
站位稳定：【实际站位与构图】必须先写方位基准和动作轴线，并和镜头1起点一致；后续移动必须有起点、路径和终点。
```

继承稳定：上一组结尾、本组起点、本组结尾必须能形成连续链条。

8.0 背景环境稳定：同一场景的固定背景锚点、远中近景层、墙面/门窗/家具/灯具、人群密度、天气时间和光源方向必须连续，变化必须有可见原因。

8.1 人物身份稳定：同一人物的姓名/称呼、年龄感、发型、服装、妆容、体型、标志物、持物、污损和情绪状态不得漂移。

8.2 关键道具稳定：关键道具的持有人、画面位置、物理状态和变化结果必须连续，不得瞬移、换手、复原、破损或改名。

```text
成品边界稳定：成品正文内只放给即梦 / Seedance 的提示词，不放解释、提醒、审稿过程、代码围栏、【精简规划】或【可复制内容】标题。
```

后台隐藏稳定：G-Block、S-Block、SSP、EMOTION、MICRO-EXPRESSION、SVP、EDIT、COMPOSITION、LIGHT-COLOR、SINGLE-LEAD、OUTPUT-STABILITY、EMOTIONAL-SEQUENCE、RHYTHM-CURVE、BREATH-SPACE、方位站位锁、方位与站位锁定模块、背景环境锁、背景环境锁定模块、人物身份锁、说话人锁、关键道具状态锁、人物身份、说话人与道具状态锁定模块 等后台词不得进入成品正文。

语言稳定：成品使用简洁中文，不混入无必要英文术语、乱码、代码说明、Markdown 表格。

```text
长度稳定：不为了显得完整而输出过长说明；不为了简短而漏掉关键剧情、台词、站位和镜头字段。
```

```text
复制稳定：最终成品应能整段复制给即梦 / Seedance，不能需要用户二次清理后台文字、代码围栏、【精简规划】或【可复制内容】标题。
```

```text
时长稳定：用户指定时长或实际剧情需求超过90秒时，必须按实际时长拆分，不得为了默认90秒压缩剧情、删台词或跳过反应镜头。
```

确认表稳定：逐镜确认表必须包含背景环境继承、人物身份继承、关键道具状态、站位逻辑、质感控制、光影控制和本组结尾继承；确认表不得混入成品提示词或后台检查过程。

```text
队列稳定：方案确认后是否先输出视觉单元队列清单，队列编号、时长、镜头数和功能是否连续明确。
```

```text
题材稳定：题材适配是否只影响镜头偏好、空间锚点、质感、光源和节奏，不改变原文事实。
```

多人稳定：多人场景是否仍锁定一个主视觉主体，没有多人同时抢动作、抢台词、抢情绪。

爽点稳定：关键 S-Block 是否有铺垫、压迫、反应、反击、落点、余韵中的必要节奏，不平均用力。

情感序列稳定：爱情、悲伤、冲突等情感戏是否有递进和落点，呼吸点是否短促克制，没有长空镜、长停顿、慢对白、过快对白或抢台词。

对白节奏稳定：台词镜是否按清晰偏紧语速估算，长句是否拆镜承载，声音和运镜是否保护台词。

稳定性失败处理：

小问题可自动修复：后台直接修正后输出干净结果。

影响台词、剧情事实、组间继承或用户意图的问题：进入检查模式，只输出问题点和最小修正建议。

用户明确要求“只要成品”时，不输出稳定性检查过程，只输出修复后的成品。
