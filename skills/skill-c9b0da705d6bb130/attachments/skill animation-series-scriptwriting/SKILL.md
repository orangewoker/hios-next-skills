# 动画番剧剧本创作模块

这是“三维动画番剧工作流”的第一个本地开发模块，负责：

脑洞生成 → 故事核心 → 世界观与人物 → 季度／分集结构 → 细纲锁定 → 好莱坞格式剧本。

本模块不负责角色图片、场景图片、道具图片、视频提示词或视频生成；后续模块接收本模块的锁定输出。

## 资料路由

需要全球题材、东方与西方路线、动画番剧脑洞或最终幻想结构母题时，读取：

- `references/final-fantasy-world-brain-library.md`

需要动画剧本格式、时长、人物弧光、阶段确认和细纲锁定时，读取：

- `references/animation-screenplay-source.md`

不要把最终幻想原作角色、专有世界观、台词或具体情节直接复制到新作品；只提取结构、母题、情绪机制和世界观方法，并转化为原创内容。

## 总体原则

1. 先问清或提炼：故事种子、受众、题材、基调、目标时长和单集／特别篇／一季的范围。
2. 默认支持全球题材：东方神话、仙侠、志怪、日本式成长番剧、韩国情感、欧美奇幻／科幻、哥特、末日、跨文化冒险等。
3. 脑洞阶段输出高概念和可开发结构，不直接跳到完整剧本。
4. 剧本正文使用中文，采用好莱坞剧本结构：场景标题、动作描述、角色名、对白、括号提示、转场。
5. 一页 A4 约等于一分钟成片；支持 3、5、10、20、30、45—60 分钟版本。
6. 动画场景必须有可见或可听的变化；不能把动画剧本写成只有对白的小说。

## 阶段工作流

### 阶段一：故事种子与脑洞方向

从用户输入中提炼：

- 一句话核心概念；
- 主角、目标、阻力和代价；
- 题材路线、受众和情绪引擎；
- 视觉奇观与动画化卖点；
- 3个差异明显的脑洞方向：短剧高转化版、番剧长线版、跨文化融合版。

用户没有完整想法时，只需要一个人物、一个画面、一个冲突或一个世界规则即可启动。

### 阶段二：故事核心与世界规则

确定：

- 主线问题与主题；
- 世界运行规则；
- 力量／职业／魔法／科技系统及其边界；
- 主要阵营和反派递进；
- 表层行动线与底层真相线；
- 第一季终点和可持续的后续问题。

每条关键规则必须说明：谁能使用、代价是什么、观众如何看见、违反规则会发生什么。

### 阶段三：人物设计

每个核心角色必须包含：

- 身份、年龄、外在形象；
- 外在目标和内在需求；
- 前史；
- 内在缺陷、恐惧、误解或执念；
- 与主角、对手、伙伴的关系张力；
- 能力与限制；
- 人物弧光：开始时相信什么，结束时改变什么；
- 可被动画表现的习惯动作、道具、表情或视觉标志。

角色行为必须由目标、前史和事件推动，不为制造反转而突然 OOC。

### 阶段四：季度与分集结构

根据时长和集数建立：

- 第一幕／第二幕／第三幕或四幕结构；
- 每集核心任务；
- 主线与副线；
- 中点反转、低谷、高潮和结尾钩子；
- 每集页数与场景数量预算；
- 角色弧光在每集的推进点。

30分钟单集采用：冷开场 → 问题建立 → 第一次尝试 → 问题扩大 → 高潮解决 → 短尾钩子。

45—60分钟单集采用：冷开场 → 目标建立 → 第一次升级 → 中点反转 → 低谷与二次升级 → 高潮 → 余波和下一集钩子。

### 阶段五：分集细纲

每集细纲必须写明：

- 集数、标题、时长、预计页数；
- 场景标题与地点时间；
- 画面内容；
- 核心冲突；
- 角色选择；
- 转折或新信息；
- 付出的代价；
- 结尾钩子；
- 场景／页数分配。

细纲完成后不得自动进入剧本，必须等待用户确认。

### 阶段六：好莱坞格式剧本

只把已确认细纲转译成剧本，不重新设计剧情。

标准顺序：

```text
片名／集数／时长／预计页数

内／外  地点  时间

动作描述。使用现在时态，只写观众能看到或听到的内容。

                         角色名
              （必要的语气提示）
              对白。
```

动作描述短而具体，一段只承担一个主要动作或画面变化。对白不塞进动作段落，场景标题统一，转场只在确有叙事作用时使用。

## 阶段确认协议

除非用户明确要求跳过，否则不得跨阶段。

- 故事种子：等待“确认方向”；
- 故事核心：等待“确认核心”；
- 故事骨架：等待“确认骨架”；
- 人物设计：等待“确认人物”；
- 分集细纲：等待“确认细纲”；
- 剧本分批：等待“满意，继续”；
- 审计结果：等待“确认审计”。

每阶段结束固定输出：当前阶段、本阶段完成、已确认事实、等待确认。用户提出修改时，先停留在当前阶段；用户只回复“确认”时，按当前阶段确认处理。

## 细纲锁定协议

用户回复“确认细纲”后，细纲进入“已锁定”状态：

1. 每集剧本开始前，完整展示该集已锁定细纲。
2. 不得改变事件顺序、人物动机、核心反转、角色选择、代价或结尾钩子。
3. 新增内容只能是动作、对白、表情、声音和必要的视觉连接。
4. 如果发现细纲矛盾，暂停剧本，指出问题并等待“更新细纲”。
5. 用户回复“重新确认细纲”后，新的细纲才生效。
6. 每批剧本结束后检查：事件、角色选择、反转、结尾钩子和页数是否与细纲一致。

## 长文防漂移账本

每轮开始先维护：

- 已确认人物、年龄、关系、目标和状态；
- 时间线和场景顺序；
- 世界规则、能力边界和代价；
- 关键道具的持有人、位置、状态和变化；
- 伏笔、反转和回收计划；
- 本集／本幕的情绪值和人物弧光位置。

新设定必须标记为“新设定”。如果修改已确认事实，必须说明影响范围并获得用户确认。人物、道具、时间线、世界规则和结尾状态不得无原因漂移。

## 输出边界

本模块完成后只交付：

- 脑洞方案；
- 故事核心与世界观；
- 人物设定；
- 季度／分集结构；
- 已锁定细纲；
- 好莱坞格式动画剧本；
- 剧本一致性审计。

不要在本模块中生成角色生图提示词、场景资产提示词、道具资产提示词、视频提示词或视频文件。它们将在后续模块中以本模块的锁定结果为输入。
