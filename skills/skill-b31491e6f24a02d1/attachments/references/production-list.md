# 制作清单与视觉控制包规则

本文件定义正式分镜脚本前必须执行的制片前置流程。目标是避免无素材引用、风格漂移、色板缺失、时长核算污染分镜正文，以及参考图、参考音频、跨镜头连续性无法落地的问题。

---

## 一、默认策略

长故事、多镜头、复杂风格、跨场景、同主体多次出现、需要参考素材或用户未提供完整素材时，默认先输出制作清单、视觉控制包与创作确认清单，不直接输出正式分镜脚本。

只有用户明确要求“先给草案”时，才可输出 `【临时分镜草案】`。临时草案必须标注：

```text
此版本未绑定参考素材，不建议直接提交 Seedance2.0 / LibTV 视频节点。
```

用户确认“素材已生成 / 已提供 / 按清单继续”后，才输出带引用格式的正式分镜。

## 二、制作清单标准结构

```markdown
【编译警告区】阻断错误 / 强警告 / 素材缺口 / 拆分建议。
【故事视觉拆解表】长故事或多事件必须输出：视觉事件、镜头索引、预计时长、模块、风险。
【视觉控制包】风格控制 / 色板控制 / 风格 × 色板一致性规则 / 禁止风格或色彩偏移。
【创作确认清单】
1. 风格来源：用户上传合适风格提示词（推荐）/ 用户输入 / 已确认参考风格。
2. 角色声音：Agent 设计并生成配音/音色样本（推荐）/ 内置音色 / 克隆音色 / 上传音频切分 / 无对白。
3. 特殊表情：表情名称 + 剧情语境 + 来源方式（角色参考图 / 表情参考图 / 关键帧）。
4. 默认生成模型确认与比例：用户须逐项选择自定义值或“使用默认值”。默认值为：图像`Lib Image`2K；单角色3:4；群像`Lib Image`按人数；普通图16:9；视频`Seedance 2.0`720p。比例只同步视频和关键帧/首帧/尾帧。
5. 参考图去噪：色板和灰度深度故事板永不去噪；其他参考图先内容与格式初审，确认需要且用户已启用时才用 LibNano 2，修复后终审通过才使用修复图 nodeKey。
6. 门禁审核：默认（推荐）=批次审核，未通过批次逐个审核；全自动=默认通过；细致=逐个审核。
【参考视觉资产需求】角色/非人类主体/场景/道具/特效参考图/色板/关键帧/特殊表情；每个视频单元的灰度深度故事板为视频 Promote 前强制资产；动作设计图、参考视频和非深度故事板只在必要时建议或询问，不内置模板。
【参考音频节点计划】音色/上传/系统/机器/环境音：列引用名、时长、audio nodeKey、镜头和插桩闭合；明确无BGM。无后期字幕
【跨镜头连续性规划】拆长镜头、延续动作或状态时输出：尾帧→首帧、尾部2秒视频参考、关键帧锁定、A→B状态变化。
【参考视频需求】仅复杂动作、运镜、调度、连续性桥接需要时列出。
【素材生成顺序建议】P0色板→P1角色/场景/参考音频→P2变体/道具/特效参考图→P3状态/表情→P4关键帧→初审→按需去噪与终审→引用闭合→连续性桥接。
【待用户确认项】用户需要确认、生成、上传或连线的素材。
```

## 二点五、生成模型确认与指定方法

创作确认清单必须逐项确认项目比例、模型、参考图去噪选项和门禁审核细致度；用户可为每项明确选择“使用默认值”。默认值为：图像 `Lib Image`、2K；单角色3:4；群像 `Lib Image`，2-7人16:9、8人以上21:9；普通图16:9；特效参考图 `LibNano Pro`、2K、1:1；视频 `Seedance 2.0`、720p；比例只同步视频和关键帧/首帧/尾帧；审核细致度为`默认`。任一项未确认时不得进入资产计划或生成。

### 1. 图像模型

`generate_image_v3.ai_model` 指定。支持：`Lib Image`、`LibNano Pro`、`LibNano 2`、`Midjourney V8.1`、`Midjourney V7`、`Midjourney Niji7`、`Seedream 5.0 Pro`。示例：单角色 `Lib Image,3:4`；群像 `Lib Image`，2-7人16:9、8人以上21:9；场景/道具/色板 `Lib Image,16:9`；特效参考图 `LibNano Pro,1:1,2K`；关键帧/首帧/尾帧比例跟随项目。

### 2. 视频模型

`generate_video_v3.ai_model` 指定。支持：`Seedance 2.0`、`Seedance 2.0 Fast`、`可灵`、`可灵3.0`。默认分镜视频写 `ai_model: Seedance 2.0`；仅用户明确指定时改用其他模型。

### 3. 音频模型

`generate_audio_v3.ai_model` 必须匹配 `type`：配音/旁白 `type: tts, ai_model: Seed Audio`；音乐/BGM `type: music, ai_model: Mureka V8`。指定时必须同时写清 `type`。

### 4. 三种指定写法

1. 全局默认：图像 `Lib Image`、2K；视频 `Seedance 2.0`、`resolution: 720p`；配音 `type: tts, ai_model: Seed Audio`。
2. 资产类型：P0色板 `Lib Image,16:9`；P1单角色 `Lib Image,3:4`；P1群像 `Lib Image` 按人数比例；P1场景/P2道具 `Lib Image,16:9`；P2特效参考图 `LibNano Pro,1:1,2K`；P4关键帧 `Lib Image` 且比例跟随项目；视频 `Seedance 2.0`。
3. 留空：`ai_model` 留空，由系统按 `type` 选默认；用户可对话覆盖。

### 5. 可控参数边界

`generate_image_v3` 可控：`prompt`、`ai_model`、`aspect_ratio`、`quality_spec`、`prompt_template`、`reference_nodes`、`tag`、`title`；不可控采样步数、CFG scale、seed、负面提示词独立字段、LoRA 权重、图像尺寸等底层参数。

`generate_video_v3` 可控：`prompt`、`ai_model`、`aspect_ratio`、`duration_sec`、`resolution`、`sound`、`need_bgm`、`start_frame_image_node`、`end_frame_image_node`、`reference_nodes`、`tag`、`title`。

## 三、视觉控制包

视觉控制包 = 风格控制包 + 色板控制包 + 一致性校验规则。

### A. 风格控制

必须包含：

1. **简单风格描述**：给用户快速理解，1-2 句话。
2. **强风格锚定提示词**：给角色、场景、道具、色板、关键帧生成使用。
3. **分类风格锚定**：按主体类别分别定义。
4. **材质与纹理规则**：定义材质如何呈现，哪些纹理进入/禁止进入哪些区域。
5. **UI / 文字规则**：画内真实显示边界。
6. **风格隔离规则**：多主体或多风格并置时必须写。
7. **负面风格偏移**：禁止错误风格方向。

### B. 色板控制

色板只分两类：

1. **全局色板**：全片或整批镜头共同的色彩气质。
2. **特定剧情部分色板**：服务某个段落、场景群、情绪转折或动作段。

不得按角色、场景、道具或关键帧建立独立的色板归属类别。角色、场景、道具可以有稳定身份色或局部色彩锚点，但不拥有色板类别。

色板控制必须包含：

1. **全局主色关系**：全片共同的色彩气质。
2. **特定剧情部分色板清单**：每个剧情部分使用哪张色板。
3. **主体色彩锚点**：角色、机械、生物、道具、UI 的稳定身份色。
4. **情绪色彩变化**：哪些剧情部分允许色彩转变，转变服务什么叙事功能。
5. **禁止色彩偏移**：避免风格跑偏。
6. **色板与风格对应关系**：每张色板强化哪一条风格规则。

### C. 风格 × 色板一致性规则

必须回答：

1. 哪些风格规则必须由色板强化？
2. 哪些色彩不得破坏风格？
3. 哪些主体颜色必须跨镜头稳定？
4. 哪些剧情部分允许色彩变化？
5. 色彩变化服务什么叙事功能？
6. 哪些局部色彩锚点不得扩散成全片主色？

## 四、色板需求模板

```text
@色板_[全局或剧情部分名]_[色彩用途]
类型：全局色板 / 特定剧情部分色板
用途：[服务哪些镜头 / 哪个剧情部分]
色彩方向：[主色、辅色、点缀色、明暗关系]
主体色彩锚点：[角色/道具/UI/机械的稳定身份色；不是色板归属]
参考影视色调：[1-3部影视作品名及其色调特征]
关联风格：[风格规则]
情绪：[建立/冲突/压迫/觉醒/收束]
生成执行：调用 `@COLOR_PALETTE` 后 promote 给 `generate_image_v3`；`ai_model: Lib Image`，`aspect_ratio: 16:9`，2K。
硬性画面格式：16:9 横图，纯白背景无网格线，纯色块等宽等距，无人物、场景、文字、装饰。
后续引用：[正式分镜中的引用名]
```

## 五、参考视觉资产需求分类

制作清单必须自主检索故事中需要哪些参考视觉资产。详细模板见 `references/reference-visual-assets.md`。

### 1. 角色参考图

用于人物身份、服装、年龄、气质、五官与体态稳定。

硬性格式：纯白网格式背景但无网格线；左上正面头部特写、右上侧面头部特写、左下正面全身、下中侧面全身、右下背面全身；下方全身视图不得生成头部；必须包含完整风格提示。

### 2. 非人类主体 / 生物 / 机械主体参考图

用于机器人、动物、怪物、车辆、拟人道具等。必须写清外形结构、可动部件、材质、尺寸关系、屏幕/UI边界、不可变身份锚点。

### 3. 场景参考图

用于空间结构和场景调性稳定。场景参考图硬性禁止出现角色。必须写清空间布局、时代感、材质、光源、剧情部分色板、禁止偏移。

### 4. 道具参考图

用于跨镜头出现、承担剧情功能或状态变化的物件。硬性格式：纯白网格式背景但无网格线，三视图道具展示；若与角色或场景有关，必须连接相关上游节点并说明关系。

### 5. 色板参考图

必须和风格控制共同出现。色板用于统一全局或特定剧情部分情绪，不得包含场景、人物、文字或装饰。

### 6. 特殊表情参考图

用于夸张、极端、剧情关键表情。必须列出：表情、剧情语境、来源方式。未确认前只写建议，不得伪造引用。

### 7. 关键帧参考图

用于关键状态或视觉母题。关键帧是静态图，但必须代表动态瞬间，可包含运动模糊、摆动、加速、撞击等动态痕迹；必须服务语气、光线、色彩、构图、隐喻和表演，并引用相关角色/场景/道具保持一致。

### 8. 动作设计参考图 / 参考视频 / 故事板

复杂动作、机械调度、追逐、武打、群体走位、物理破坏时，可以建议动作设计图或参考视频。除每个视频单元强制的灰度深度故事板外，普通故事板只在跨多个段落、镜头数量多、场景调度复杂或用户需要整体视觉统一时建议生成。系统只提出普通故事板/动作设计的需求和用途，不内置其生成模板。

## 六、参考音频需求分类

详细规则见 `references/reference-audio-processing.md`。

### 1. 角色音色锁定

```text
@音_[角色名]_音色锁定
用途：
声音性格：
语言 / 口音：
试听文本：
建议来源：内置音色 / voice design / voice clone / 上传音频处理
后续引用：
```

### 2. 上传音频锚点

用户提供音频时，先建参考音频节点清单：引用名、时长、audio nodeKey、使用镜头；必要时切分。正式分镜只引用已确认音频名，不得把未处理音频伪造成角色音色。

### 3. 系统音 / 机器声 / 环境音

用于机器人 UI、系统播报、车载扬声器、企业广播、雨后街道、后巷低频、机械臂、轮胎、水声、玻璃破碎等。

### 4. 声音参数边界

声音参数必须分层：文档 / LibTV CLI 层记录 `enableSound=off/on`；Agent `generate_video_v3` 工具调用层转换为 `sound: "off"` / `sound: "on"`。声音全部默认开启：所有镜头默认 `enableSound=on` / `sound: "on"`；只有用户明确要求静音、关闭原生声音或指定某镜必须后期配音对齐时，才可改为 `off`。

### 5. BGM 边界

若全局规则为“无BGM。无后期字幕。”，参考音频只能是画内声音、角色音色、系统音、环境音或动作音效，不得列出后期配乐。

## 七、制作时间线重组与资产清单划分

### 1. 制作时间线重组

启用：插叙、倒叙、闪回、多线并行、同场景被切散、连续动作被打断、角色状态跨时间跳变，或用户要求按时间线生成再剪辑回排。位置：粗分镜后、资产提取前。

粗分镜输入：原始镜号、故事内时间标签、场景/事件、角色、关键道具、连续动作链。输出：制作顺序号、原始镜号、制作前/后一镜、衔接类型、连续动作链、资产清单归属、剪辑回排位置。按故事内时间排序，同时间按原始镜号排序；原始镜号不变；视频按制作顺序生成；最终剪辑按原始镜号回排。

### 2. 资产清单按场景或运动主体划分

资产清单不是全局总表，也不是角色/道具/状态多域并行表。按粗分镜段落生成多个文件：场景1资产清单、场景2资产清单、运动主体1资产清单……详细分镜只在涉及时采用对应清单。

判定：一个场景内活动、固定空间对话/调查/仪式/室内调度 → 场景资产清单；追逐、竞速、打斗、逃亡等多场景连续运动，且核心角色/随身道具/伤痕状态大致不变 → 运动主体资产清单。同一场景内打斗不离场，可按场景清单并标记场景内运动链。

清单含：清单名、关联粗分镜、经过场景（仅运动主体清单）、角色、随身/场景道具、场景固定元素或运动关系、主体画面方位表。主体画面方位表必须为同一场景或同一运动主体内的主要主体指定画左/画右/居中、由左至右第几个、常用朝向；后续镜头默认沿用，除非明确换轴、越轴或构图反转并说明原因。每镜只写：

```text
本镜资产在场声明（基于清单：[清单名]）：必定在场 / 可能在画面内（负面锁定） / 本镜移除及原因
```

减法原则：默认继承对应清单；必定在场写主体定义或空间与朝向；可能在画面内写在场锁定；确认不出现则移除并说明；无法判断则保留。

## 七点五、分镜审核、连续性协议与生成调度

九步：1 粗分镜（镜号、故事时间标签、场景/事件、角色、关键道具、连续动作链）→ 2 必要时制作时间线重组 → 3 按场景或运动主体生成多个资产清单文件 → 4 按制作顺序完成本次生产范围内全部正式分镜，镜号仍用原始镜号，必要时写“制作时间线信息” → 5 全范围逻辑检索、修正与正式分镜闭合 → 6 按 references/continuity-bridge.md 逐相邻制作镜判定强/弱/无连续性需求；同场景时间连续的多点位进入场景连续参考模式，明确方向进入方向连续参考模式，连续动作选用媒体桥接，只有无连续性才独立生成 → 7 全范围视觉参考完整性复查（静态阶段）：逐镜检查角色/主体、场景与点位、道具与状态、表情与表演、特效、关键帧和连续性参考；逐项记录正式分镜证据、现有 nodeKey、覆盖结论、补图任务或复用依据，并审核所有静态补图 → 8 全范围参考完整性、音频闭合、连续性复核和制作依赖顺序确认；前镜实际视频才能提供的尾帧/派生起幅图列为运行时依赖 → 9 仅为前置已就绪的镜头按制作顺序编译深度故事板，先完成结构/深度审核，再完成与正式分镜的语义合规审核后生成视频；运行时依赖镜须待前镜视频通过、尾帧抽取及审核、派生图审核后才可编译，剪辑仍按原始镜号回排。

硬规则：本节只负责按上述顺序调度。逐镜深度故事板与视频 Promote 包必须遵循 `references/prompt-assembly.md`；不得把整份分镜表或完整动作层原样塞入视频 Prompt。

## 八、引用命名规则

正式分镜只引用已经生成、已提供或用户确认要使用的素材。不得伪造引用。

命名建议：

- 角色 / 主体图：`@图_角色名_角色设定`
- 非人类主体图：`@图_主体名_主体设定`
- 场景图：`@图_场景名_场景设定`
- 道具图：`@图_道具名_道具设定`
- 色板图：`@色板_全局_色彩用途` 或 `@色板_剧情部分_色彩用途`
- 关键帧图：`@关键帧_镜号_动作或状态`
- 表情图：`@表情_角色名_表情名`
- 动作参考视频：`@视频_镜号_动作参考`
- 连续性参考：`@帧_镜号_首帧` / `@帧_镜号_尾帧` / `@视频_镜号_尾部2秒`
- 角色音色：`@音_角色名_音色锁定`
- 系统/机器声：`@音_对象名_系统声`
- 环境音：`@音_场景名_环境音参考`
- 故事板：`@故事板_段落名`

未确认素材时，只能在制作清单中写“建议生成 / 待提供”。正式分镜中不得写虚假的 `@图_`、`@音_`、`@视频_` 引用。

---

## 九、LibTV 上游节点引用规则

当正式分镜用于 LibTV 视频节点生成时：

1. 文档 / LibTV CLI 层：所有被 prompt 调用的参考图、参考视频、参考音频、关键帧、色板都必须作为当前生成节点的左侧上游入边节点连接。
2. 文档 / LibTV CLI 层：prompt 中使用 `{{Node <nodeKey>}}` 插入节点；节点名唯一时可用 `{{Node "节点名"}}`。
3. Agent `generate_video_v3` 工具层：执行前必须把 `{{Node <nodeKey>}}` 转换为 `{{nodeKey}}`；普通参考节点进入 `reference_nodes` 参数。
4. 首帧锁定节点优先进入 `start_frame_image_node`，不得同时重复进入 `reference_nodes`；prompt 正文仍保留工具层 `{{nodeKey}}` 作为语义锚点。
5. 参考素材引用区写的是人类可读资产名和 nodeKey 映射；真正提交工具前必须执行层级转换检查。

## 十、正式分镜中的最小风格锁

完整视觉控制包不得逐镜全文重复。正式分镜每镜只写“引用式最小风格锁”。

```text
风格锁定：
引用全局风格：[风格名称]
引用风格素材：[@图_主体] [@图_场景] [@图_道具]
引用色板：[@色板_全局或剧情部分]
本镜分类风格：[本镜特殊主体或空间沿用哪一类风格]
本镜局部边界：[只写本镜新增或容易混淆的风格/色彩/UI边界]
```

若没有风格参考素材或色板，每镜必须加入 80-120 字以内的“风格胶囊”，但不得复制完整视觉控制包。

---

## 十一、时长核算外置

时长核算属于编译判断，不属于 Seedance2.0 提示词正文。

允许进入正式分镜脚本的只有：

```text
【镜XX】标题 | 时长：Xs
```

不得进入正式分镜脚本的内容：台词估算时长、动作/运镜估算时长、对白占比判断、是否可承载、是否阻断、拆镜建议。这些必须写在 `【分镜时长核算区】`。

---

## 十二、全项目素材清单与单次生成限制

制作清单是全项目级资产规划，可以列出超过单次 Seedance2.0 限制的素材；正式分镜是单次生成级提示词，必须严格遵守单次限制。

1. 全项目参考图清单可以超过 9 张，但每个正式镜头的 `参考图引用` 不得超过 9 张。
2. 全项目参考视频清单可以超过 3 个，但每个正式镜头的 `参考视频引用` 不得超过 3 个。
3. 全项目参考音频 / 音色清单可以超过 3 个，但每个正式镜头的 `参考音频引用` 不得超过 3 个。
4. 每个正式镜头的参考视频 + 参考音频合计时长不得超过 15s。
5. 如果单镜需要超过限制的素材，必须拆镜、分批、合并参考资产，或用角色设定图 / 场景设定图 / 道具图 / 关键帧承载部分信息。
6. 角色音色锁定是全项目资产；正式单镜只引用本镜实际发声角色的音色。
7. 色板按全局或特定剧情部分引用；单镜一般只引用 1 张主色板，除非本镜明确需要色彩对位。

---

## 十三、流程冲突检查

输出前必须确认：

1. 制作清单阶段没有伪造最终引用。
2. 创作确认清单已强制逐项确认选择闭合，不得用总确认代替逐项选择。
3. 正式分镜中的每个引用都能在用户确认素材中找到。
4. 正式单镜引用数量不超过 Seedance2.0 单次限制。
5. 全项目素材清单和单镜引用清单没有混用。
6. 色板只分全局和特定剧情部分，没有按角色、场景、道具或关键帧划分的归属类别。
7. 主体色彩锚点不会被剧情部分色调吞掉。
8. 画内 UI / 文字不会变成后期字幕。
9. 时长核算不进入分镜脚本。
10. 无BGM 规则不会被参考音频误解为后期配乐。
11. 声音全部默认开启，文档层默认 `enableSound=on`，Agent 工具层默认 `sound: "on"`；只有用户明确要求静音、关闭原生声音或后期配音对齐时才使用 `off`。
12. 复杂动作有动作参考或 BLOCKING 降级方案。
13. 长动作拆分已使用连续性桥接规划，首帧锁定节点未重复进入普通参考节点参数。
14. 后期合成前建镜头累计时间轴表，audioList.startTime按实际视频时长累加。
15. 重新生成节点成功后，分镜表标旧节点`deprecated`、新节点“当前有效”；每镜号仅一个有效节点。
16. 临时草案不会被误标为可直接提交的最终分镜。

## 十四、深度故事板驱动的视频调度（最高优先级）

本节只负责将已通过的正式分镜按制作顺序调度为逐镜生成包。范围闭合、故事板状态、视频引用、参数、提示词、节点闭合、参考上限和失效处理均以 `references/prompt-assembly.md` 为唯一准则；尾部 2 秒连续性处理以 `references/continuity-bridge.md` 为准。任一前置未通过时，阻断生成。
