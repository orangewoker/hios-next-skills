# 深度故事板与视频 Prompt 组装硬规则

本文件规定：审核通过的正式分镜必须先编译为深度故事板，再编译为 `generate_video_v3` 参数。正式分镜不得直接作为视频 Prompt 的完整动作、空间或主体正文。任何自由发挥、摘要化、翻译习惯均不得覆盖本文件。

## 一、Promote 状态门禁

一个视频单元只能在本次生产范围已闭合后按以下状态推进：范围内全部正式分镜为通过；全范围视觉参考完整性复查（静态阶段）、逐边界连续性报告和全部静态补充资产均已审核闭合，且参考完整性与连续性复核通过。连续性报告必须区分强/弱/无需求、实际连续参考 nodeKey 和执行方式；同场景时间连续的多点位必须使用场景连续参考，明确方向必须使用方向连续参考。不得因某一分镜批次完成而提前进入本流程。

若本镜的故事板参考必须从前镜实际视频取得，当前镜视频通过、尾帧抽取与初审/去噪/终审、派生起幅图审核之前，本镜不是“已就绪视频单元”，不得生成深度故事板。没有这类运行时依赖的已就绪镜可按制作顺序推进。

```text
本次生产范围 closed
→ 全范围视觉参考完整性复查与静态补图审核 passed
→ 参考完整性与连续性复核 passed
→ 正式分镜 passed
→ 深度故事板生成包 closed
→ 深度故事板 generated
→ 深度故事板结构/深度审核 passed
→ 深度故事板语义合规审核 passed
→ 视频 Promote 包 closed
→ generate_video_v3
```

Promote 只编译本次 `generate_video_v3` 可传入的参数与自然语言 Prompt，不输出项目编号、父镜头、验收状态、链深度或其他跨镜头系统字段。深度故事板、色板、实际使用的图像/音频/视频节点和模型参数必须在本次调用中闭合；缺少深度故事板，或其原文保真、结构/深度、语义合规任一审核未通过时，均阻断视频生成。

## 二、深度故事板生成包

每个视频单元生成一个 `@深度故事板_镜号_九宫格`。独立镜中，它是 3×3 连续时间线图：左上到右下依次表示本镜起幅至落幅的九个连续视觉状态；不得渲染编号、文字或标签。

连续延长镜必须先将正式分镜拆成“尾部视频完全继承段（0.0–2.0 秒）”与“故事板控制段（第 2 秒后）”。深度故事板生成包只输入控制段，不输入继承段；已抽取并审核的尾部视频结束状态作为该控制段的起始条件，本镜落幅为该控制段终点。不得把这 9 格解释为整段视频从 0 秒起的九个状态，也不得由 Agent 预先设计 P1–P9 的具体画面。

### 1. 固定参数

```text
工具：generate_image_v3
ai_model：Lib Image
aspect_ratio：16:9
quality_spec：标准画质，2K
```

### 2. 完整分镜脚本与参考资产写入

深度故事板图片 Prompt 必须在固定提示词之后，完整写入当前有效正式分镜的深度相关正文：主体、空间、动作、摄影机、连续性、状态变化、已确认的起幅/落幅和所有影响九格时序的约束。不得将其压缩为“起幅/中段/落幅”摘要，不得省略已确认的动作、空间或摄影机信息，也不得改写为 Agent 预先设计的 P1–P9 画面。连续延长镜只写第 2 秒后的故事板控制段；0.0–2.0 秒继承段不得进入故事板脚本。色板、色彩脚本、风格层、光影设计、音频节点、尾部 2 秒视频及其他视频节点不得写入或引用。

### 2.1 深度字段原文锁（不得自主改写）

先从当前有效正式分镜建立 `深度字段原文副本`，再把该副本直接写入故事板图片 Prompt。副本不是摘要、改写稿或“更适合图片模型”的连续叙述；它是对深度相关字段的原文保真摘录。

必须保留原始字段标题、标题顺序、每一行/每一表格行的顺序及字段值。至少保留实际存在的：`画面目标`、`主体定义`、`主体画面方位表`、`空间与朝向`、`摄影机与镜头`中的摄影机/镜头组、`本镜视觉优先级`、`景别与运镜`中的摄影机运动动机/轨迹描述/速度差设计、`动作层`、`节奏设计`、连续性/制作时间线信息、起幅/落幅及所有本镜状态变化。触发 `@BLOCKING` 时，角色走位、空间纵深和速度差设计必须逐行保留。

唯一允许的变换是：①排除色板、色彩脚本、画面风格锚点、光影、对白、音效、音频节点、尾部 2 秒视频及其他视频节点；②把文档层 `{{Node <nodeKey>}}` 逐字转换为 Agent 工具层 `{{nodeKey}}`。禁止删除、合并、转述、翻译、重排、补写或把保留字段揉成连续自然语言；不得用“主体在画左、镜头缓推”等概括代替原有方位表、视觉优先级、速度差或动作/调度字段。通用的提示词压缩、反冗余或文风优化规则不适用于该副本。

调用 `generate_image_v3` 前，逐项比对正式分镜与副本：保留字段标题、字段顺序、行/表行数量、每行字段值和实际 nodeKey 必须一致；仅允许上述排除项和节点语法转换。任一字段缺失、被改写、被合并为叙述、顺序变化、遗留占位符或 nodeKey 不一致时，标记 `source_fidelity_failed`，阻断故事板生成并从正式分镜重新建立副本。

### 2.2 时长与动作可行性复核

在生成故事板前，必须根据当前正式分镜的时长、关键可见结果、动作层、节奏设计和摄影机轨迹复核现有时长核算。不得为适配模型而自主删减、合并、提前完成或改写正式分镜动作。

若镜内存在多个独立因果状态变化，且同时有景别/摄影机阶段转换、关键交互、关键特效或台词，必须记录它们能否在本镜时长内被连续看清。结论为“无法承载”时阻断并请用户选择拆镜、调整时长或改写；结论为“高风险但可尝试”时，必须在视频生成前取得用户明确接受，或先通过特效参考图、关键帧、动作参考等已确认资产降低风险。不得把风险结论写进正式分镜或最终视频 Prompt。

固定提示词后必须按以下顺序以自然语言拼接实际内容：

```text
【完整正式分镜脚本】
【深度字段原文副本；按 2.1 原样写入实际内容，不留占位符】

【参考资产定义与空间锚点】
[每项实际非色板图像参考的真实 nodeKey、定义、空间位置、相对关系、朝向和本镜状态；实际内容直接写入，不留占位符]
```

只允许将已确认的非色板图像 nodeKey 作为 `reference_nodes`：角色、场景、道具、特效参考图、表情、关键帧、首帧、尾帧和派生图均可。连续延长镜若需承接尾部视频，只能先抽取该视频尾帧；尾帧作为图像节点加入，不能将视频节点直接传入。所有实际引用的角色、道具、场景或其他图像资产均须在上述资产锚点段落中闭合；缺少定义、位置/关系或朝向时，阻断故事板生成。

### 3. 固定提示词

```text
根据以下分镜脚本生成连续分镜画面的3*3九宫格故事板。后期渲染为单目灰度深度参考图，为每个面板单独估计深度，使用此深度约定：白色=最近的表面，浅灰色=近前景，中灰色=中距离，深灰色=遥远背景，近黑色=最远的云空或地平线，黑色=面板分隔线。保持准确的深度分层、遮挡和平滑距离过渡。物体的较近部分应比较远部分更亮，包括肢体、衣物、道具、地形和穿过空间的细长物体。保留清晰的轮廓和精细细节，如手指、头发、植被、电线和物体边缘。在曲面使用平滑渐变，而不将主体扁平化为统一的灰色形状。深度值仅表示距离。忽略颜色、光照、高光、阴影、反射、纹理、雾、雨、烟和运动模糊。避免光晕、轮廓、双重边缘、环境遮挡、浮雕、纹理阴影和虚假深度。仅输出中性灰度深度图，无文字、标签；不得添加或移除正式分镜未定义的物体，不得改变正式分镜规定的空间布局、对象状态或动作顺序。要求网格化纯白背景，无网格线。
```

“网格化纯白背景，无网格线”指整体画布纯白；仅九个面板之间保留黑色分隔线，不得出现坐标、辅助网格、编号或文字。

## 三、深度故事板审核与失效

故事板必须恰好为 3×3、中性灰度、近亮远暗、遮挡正确、曲面过渡平滑、物体完整且九格时序连续。黑色只用于面板分隔；最远视觉层使用近黑而非纯黑。不得有颜色、光影、纹理、雾、运动模糊、文字、标签，或正式分镜未定义的额外物体、对象缺失和布局改变。审核同时检查生成包确已写入完整正式分镜正文及每项实际参考资产的定义、位置/关系与朝向；仅有起幅/中段/落幅摘要、缺少真实 nodeKey 或遗留占位符均为失败。

结构/深度审核通过后，必须单独进行 `storyboard_semantic_fidelity` 审核。该审核以当前有效正式分镜和 `深度字段原文副本` 为唯一依据，不得用摘要、风格推断或“模型大概会理解”代替。它不在生成前设计 P1–P9；只在生成后记录实际可见证据所在的面板或连续面板区间，并逐项确认：

1. `画面目标`中的关键可见结果、结果出现的瞬间和视觉优先级均可见，且没有被环境或次要主体替代；
2. `主体画面方位表`、`空间与朝向`中的前/中/后景、左右、进出画方向、相对位置、遮挡和距离亮度相互一致；
3. `动作层`、状态变化和节奏的因果顺序从起幅连续推进到落幅；正式分镜要求出现、离开、接触、收集、受损、转向或到达的对象不得被省略、提前泄露或换成其他动作；
4. `摄影机的观察任务`、摄影机运动动机、轨迹描述和速度差设计能够由九格读出；正式分镜未定义的切换、机位重置、方向反转或景别跳变不得出现；
5. 每项实际参考资产仍与其定义、位置/关系、朝向和本镜状态一致；关键特效或关键交互若无法从板中辨认，必须回到视觉参考完整性复查补齐资产，而非带病通过。

审核记录必须逐项写明“正式分镜原文证据 → 故事板实际面板/区间证据 → passed / failed”。任何一项缺失、矛盾、无法辨认，或深度层级与正式分镜方位相反时，标记 `semantic_fidelity_failed`，故事板为 `rejected / needs revision`；不得 Promote 或生成视频。通过时才可记录 `semantic_fidelity_passed`。

深度故事板不走 LibNano 2 常规去噪；只做结构/深度与语义合规审核。任一审核失败时重新生成，不得 promote 视频。

正式分镜、引用资产、空间位置/朝向或连续性方案变化时，依赖故事板立即改为 `needs revision`。重生成成功后，旧故事板标记 `deprecated`，仅新 nodeKey 为当前有效。

## 四、视频 Promote 包与 Prompt

视频仅可使用状态为 `passed` 的深度故事板。固定模型：`ai_model: Seedance 2.0`；默认 `resolution: 720p`。

Promote 的产物就是一段自然语言 Prompt；不得用表格、项目字段、镜头编号、状态块或其他管理文字占用 Prompt。模板中的方括号仅为编译标记，填入实际内容后必须删除方括号、提示文字及不适用的整段。按以下顺序连续写成自然语言：

1. 一句话分镜视频总结。
2. `严格按照深度故事板 {{深度故事板nodeKey}} 作为整个时间线、相机、过程、镜头的主要参考。严格遵循深度故事板的排列顺序，不添加、移除或重新设计动作。`
3. 深度故事板只控制时间线、空间深度、遮挡、调度、动作过程和摄影机过程；不得把灰度、深度编码、九宫格、黑色分隔线或白色背景渲染为成片画面。其他参考资产不得覆盖这些控制维度。
4. 仅连续延长镜加入：`前 2 秒严格完整参考尾部视频 {{尾部2秒视频nodeKey}} 的画面、构图、人物身份、空间位置、朝向、动作相位与摄影机运动，不提前出现后续动作。此要求在 0.0–2.0 秒优先于上一条的整个时间线约束，深度故事板自第 2 秒起主控。第 2 秒后的剩余时长按正式分镜的动作节奏从 P1 推进至 P9；P1 承接该视频结束状态，P9 为本镜落幅，不得把九格当成九个平均切分的独立镜头。`
5. 逐项写本镜实际引用资产及定义；有哪个写哪个，不伪造缺失资产。每项均用自然语言说明“只控制什么、不得覆盖什么”，不得在视频 Prompt 内使用表格：
   - 人物 `{{人物参考图nodeKey}}`：只控制身份与不可变外观；将其置于故事板已规定的画左/居中/画右、前景/中景/后景、相对人物/道具/场景关系、朝向和本镜状态；不得覆盖故事板的时间线、动作轨迹或摄影机过程。
   - 道具 `{{道具参考图nodeKey}}`：只控制不可变结构与材质；将其置于故事板已规定的空间位置、与人物/场景关系、朝向和本镜状态；不得重设动作、时序或摄影机。
   - 场景 `{{场景参考图nodeKey}}`：只控制真实空间结构、时代/环境、固定元素及其位置关系；场景朝向为[方向]；人物与道具的动态位置、动作和摄影机过程仍以故事板为准，不得新增未定义人物、道具或动作。
   - 特效 `{{特效参考图nodeKey}}`：只控制特效的形态、边缘、主/辅色、密度、透明度、交互和变化特征；不得覆盖人物身份、场景结构、时间线或摄影机过程。
   - 关键帧、首尾帧、表情/状态或连续性参考 `{{图像nodeKey}}`：只控制其已确认的静态起始/终止状态、表情、姿态或连续性条件；不得重设故事板的其余动作、时序、场景结构或摄影机过程。
6. 摄影机组。
7. 台词层：逐句保留正式分镜已确认的角色、语言/口音与原文；每句紧邻其前插入对应角色的 `{{音色nodeKey}}`。
8. 音效层。实际引用的环境音、动作音或系统声音频必须紧邻其作用写入 `{{音效参考音频nodeKey}}`，并说明它只控制的声音角色；没有对应音频参考时不插入该节点。
9. 风格层与本镜色板 `{{色板nodeKey}}`；色板只控制色彩与风格倾向，不控制人物、道具、场景结构、空间、动作、摄影机或具体物理光源。
10. 光影设计。
11. 必要的画面约束：将正式分镜中的负面限制转成可执行禁止项，且不得与故事板、尾部 2 秒继承或资产定义冲突。
12. `无字幕。无BGM。`

不得把完整正式分镜、完整动作层、时长核算、模块名、模板名、评级、降级方案、未确认素材或任何跨镜头管理字段写入视频 Prompt。深度故事板已承担完整动作、过程和镜头时序的约束；一句话总结不得与其矛盾。台词语言、已确认原文和必要画面约束不得擅自翻译、改写或遗漏。Prompt 外必须保留 `参考职责记录`：每个实际节点的唯一主控维度、不得迁移的维度及其与故事板的冲突检查；任一需要由参考控制的维度有两个主控者或没有主控者，均不得调用视频生成。

## 五、节点与素材规则

- 深度故事板与本镜色板都必须进入视频 `reference_nodes`，并分别在 Prompt 中插入 `{{nodeKey}}`。其他实际使用的参考节点也必须在 Prompt 中紧邻其定义插入；文档层使用 `{{Node <nodeKey>}}`，Agent 工具层使用 `{{nodeKey}}`。
- 色板不得进入深度故事板，但必须在视频风格层引用。
- 尾部 2 秒视频只允许作为本次连续延长镜的视频 `reference_nodes`；不得进入故事板生成，也不得在没有该节点时臆造前镜画面。
- 首帧锁定节点只进入 `start_frame_image_node`，尾帧锁定节点只进入 `end_frame_image_node`，二者不得重复进入 `reference_nodes`；抽取的尾帧可作为故事板图像参考。连续延长镜从尾部视频抽取的尾帧不得填入首尾帧锁定参数，除非它本身就是本镜已确认的起幅或 P9 落幅；若使用尾帧锁定节点，其状态必须与故事板 P9 一致。
- 视频的唯一图像节点总数最多 9，含深度故事板、色板、首尾帧和普通资产；深度故事板与色板固定占 2 个图像位。
- 参考视频最多 3 个，参考音频最多 3 个，参考视频与音频时长合计不超过 15 秒。
- 有台词时，每个实际发声角色的 3–4 秒音色节点必须进入 `reference_nodes`，且在对应台词行紧前插入 `{{音色nodeKey}}`；单镜最多 3 个音色节点。尾部视频若含台词，前 2 秒的角色、语言与原文必须映射到同一角色的音色节点；尾部视频内嵌声音不能替代音色节点。
- 实际引用的环境音、动作音或系统声音频必须进入 `reference_nodes`，并在音效层紧邻其作用插入 `{{音效参考音频nodeKey}}`；不得把未传入的音频写成参考。
- 文档 / LibTV CLI 层 `{{Node <nodeKey>}}` 执行前转换为 Agent 工具层 `{{nodeKey}}`，且所有上游节点必须闭合。
- 正式分镜中承担关键可见结果、视觉优先级或独立交互的特效，若现有资产不能稳定定义其颜色、形态、边缘、变化与交互，必须在全范围视觉参考完整性复查中生成并审核特效参考图；不得仅依赖灰度故事板中的深度亮度或色板替代。

## 六、提交前自查

- 深度故事板存在、当前有效、状态为 `passed`，且其 `source_fidelity_passed`、结构/深度审核和 `semantic_fidelity_passed` 已完整记录，并被视频 Prompt 与 `reference_nodes` 同时引用。
- 故事板未引用色板、音频或视频节点；视频已引用本镜色板。
- 视频实际引用的人物、道具、场景均已在自然语言 Prompt 中写明定义、空间位置/关系和朝向，且与故事板一致。
- 每个实际引用的图像节点都有唯一主控维度和明确禁止迁移项；深度故事板独占时间线、空间调度、动作过程和摄影机过程，色板只控制色彩/风格倾向，具体物理光源由光影设计定义。
- 有台词时，每名实际发声角色均有 3–4 秒音色节点和台词前插桩。
- 每个实际引用的非音色音频节点均已在音效层说明其作用并完成插桩。
- 连续延长镜的尾部 2 秒视频只位于本次视频层；前 2 秒完整继承、2 秒后按 P1→P9 推进；首尾帧没有重复进入普通参考节点。
- Prompt 含一句话总结，没有表格、项目字段或跨镜头管理信息；深度故事板不以灰度九宫格形态出现在成片。
- 参考数量、时长、声音开关、无字幕和无 BGM 均合规。
