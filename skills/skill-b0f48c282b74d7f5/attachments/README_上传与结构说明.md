# 多层嵌套结构与防漏机制

## 为什么这样拆

按“总控路由 → 主任务工作流 → 公共能力模块 → 输出模板/质检”拆分。不是把“拉片”和“提示词”二选一，而是先完成主任务，再决定展示范围。

## 四层结构

1. `SKILL.md`：总控、任务识别、依赖注入、输出级别和完整性闸门。
2. `workflows/`：八类主任务工作流。
3. `modules/`：产品、人物、逐帧、镜头、声音、Seedance、质检等公共能力。
4. `templates/`：输出契约、输入模板和检查清单。

## 两个最重要的防漏规则

### 规则一：主任务词高于交付词
“拉片、逐帧、1:1、拆解”决定必须做哪些分析；“给我提示词”只说明最终需要提示词。除非用户明确说“只给提示词、不要分析”，否则默认FULL。

### 规则二：人物模块按最终画面自动触发
不看用户是否主动提供人物，只看最终成片是否有人物。参考视频有人、脚本有人、口播/街采/送礼需要人，均自动输出人物设定。有对白再追加逐句微表情和听者反应。

## 上传建议

### 使用多层嵌套版时

必须把根目录 `SKILL.md`、`workflows/`、`modules/`、`templates/`、`docs/` 一起放进同一个 Skill 中，并保持相对路径不变。只上传根 `SKILL.md` 会造成它引用的子工作流和公共模块不存在，嵌套规则无法完整执行。

- 上传入口支持完整 Skill 包或 ZIP：上传整个 ZIP。
- 编辑器支持目录树和多文件：上传根 `SKILL.md`，再按原目录上传所有子文件。
- 当前页面只能替换一个 `SKILL.md`、无法添加其他文件：不要使用嵌套版，应改用单文件完整版。

根目录入口必须命名为 `SKILL.md`。不要只上传某一个 `workflows/*.md` 或 `modules/*.md`，这些文件不能脱离总控文件单独使用。


## 单文件 20000 字限制处理

创建 Skill 页面要求单个文件内容不得超过 20000 字。本版本未删减原规范，仅将原完整正文拆为：

- `docs/full_original_spec_part1.md`
- `docs/full_original_spec_part2.md`
- `docs/full_original_spec_index.md`

上传时三份文件必须全部保留，并保持目录路径不变。不要将两部分重新合并为一个文件，否则会再次超过平台限制。
