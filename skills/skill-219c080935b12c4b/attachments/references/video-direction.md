# 从分镜图到视频提示词

只在用户已经确认故事、画风和分镜图，并准备进入视频阶段时读取本文件。

## 一、先获得视频生成条件

只询问尚未知道的内容：

1. 目标视频模型与版本。
2. 单段最长可生成时长。
3. 输入模式：单图图生视频、首尾帧、多参考、文生视频或视频延长。
4. 是否支持原生对白/音效，以及用户是否需要。

若用户不指定模型，默认提供中性、模型无关的图生视频提示词；不得假装某模型支持尚未确认的功能。

## 二、切段原则

- 每段时长不超过目标模型上限，全部片段时长合计必须精确等于总时长。
- 一段只承载一个主动作或一个连续动作链。需要明显换地点、跳时间、换视轴或切景别时，拆成新段。
- 每段绑定：输入图编号、起始状态、结束状态、下一段接点。
- 动作要能在给定秒数完成。复杂行为拆成可见节拍，不写无法在数秒内读取的多层剧情。
- 镜头运动服务于信息：揭示空间、追随行动、逼近情绪或完成反转；不为“电影感”无目的环绕。

## 三、视频提示词结构

按以下顺序写成一条自然、可执行的单行提示词：

`首帧占位与空间 → 主体身份锚点 → 0–N 秒动作节拍 → 对手/环境反应 → 镜头与焦段感 → 物理细节 → 光线与画风延续 → 结束姿态/接点 → 必要负面约束`

每条必须明确：

- **首帧**：人物在画面哪一侧、朝向哪里、前中后景分别是什么。
- **动作**：用可观察动词，不写“展现力量”“感到命运”等抽象词。
- **节拍**：可用 `0–2 秒`、`2–5 秒` 等时间段；总和等于该段时长。
- **表演**：目光、呼吸、重心、手部、停顿、反应和人物距离。
- **摄影**：静止、推、拉、跟、摇、横移、升降、手持或长焦观察；通常一段只保留一个主要运动。
- **物理**：衣摆、发丝、尘、水、烟、布、马匹、武器或建筑的惯性与碰撞必须符合动作。
- **连续性**：服装、道具持手、伤痕/污渍、天气、光向和人物屏幕方向与前后镜一致。
- **结束状态**：为剪辑或下一段提供清楚接点。

不要把静态图片提示词原样复制成视频提示词。不要在一段中同时要求航拍、特写、环绕、快速推拉和多次剪切，除非目标模式明确支持多镜头生成。

## 四、参考图继承

- 已批准的图片是视觉事实。视频提示词描述“保持参考图中……”并只强调最容易漂移的 3–6 个要点。
- 不重新发明脸、服装、建筑、天气或色调。
- 单图图生视频避免大幅暴露参考图之外的区域；若必须转身、绕背或大范围移动，先补足对应资产/首尾帧。
- 首尾帧模式先检查人物数量、左右位置、视线和光源是否能自然过渡；不自然时先修图，不用文字强迫模型完成瞬移。

## 五、声音与对白

- 模型支持原生声音时，画面动作与声音事件用同一时码对齐。
- 对白单列角色、语气、音量、停顿和口型要求；不要混入 Midjourney 参数。
- 不支持声音时，输出独立声音表：时码、环境音、动作音、对白/旁白、音乐进入与退出。
- 无对白短片仍需设计可听节奏，避免用持续音乐掩盖所有动作。

## 六、输出格式

每段先列：`V01｜00:00–00:06｜6 秒｜输入：S01`，再给提示词：

```text
一整条可复制的单行视频提示词
```

随后标注：`字符数：N/1000`、`结束接点：……`。

视频提示词不附加 `--profile 361karz --stylize 750`。该结尾只属于 Style Image/Midjourney 图片提示词。

## 七、视频审计

- 每段是否有明确首帧、主动作和结束状态？
- 动作量是否适合时长，是否存在一段塞入多个地点或多个镜头？
- 相邻段的屏幕方向、服装、持物、光线、天气和人物数量是否连续？
- 是否错误加入图片模型参数？
- 每条是否经过 `scripts/check_prompts.py --kind video` 并且不超过 1000 字符？
- 所有时码之和是否精确等于总时长？
