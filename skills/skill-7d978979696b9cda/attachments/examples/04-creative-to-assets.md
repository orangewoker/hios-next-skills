# 贯通演练：从创意选择到有用途的资产

**本例为原创离线开发，没有生成图片/视频/声音、调用平台或真实计费。** 它回到修理店故事尚未定稿的起点，演示怎么用创作判断形成资产与任务。模型名沿用 Lib Image、Seedream 5.0 Pro、Seedance 2.5；不推定底层映射、模式、价格或生成成功。

触发是用户希望从“父亲离世后姐弟清点修理店”发展长片/连续剧，但体量和风格尚不完整。输入足以提出创意候选与制作规划；不足以宣布用户已选择某风格、锁定全篇结构或授权付费。已授权的离线开发可继续，并在产物显著处写假设。

## 1. 比较会产生人物选择的前提

| 候选 | 观众承诺与可持续压力 | 一个可演选择 | 主要未知/取舍 |
|---|---|---|---|
| A 归还钥匙 | 通过日常清点看到姐弟如何重新分担责任；账、旧物与客户可持续带来不同责任 | 林舟赶车却决定留下认字 | 内敛戏需要行动/反应可见；不靠不断新秘密撑体量 |
| B 一笔去向不明的款 | 以账目悬念推进对父亲的认识 | 姐姐是否把发现立即告诉弟弟 | 悬疑会改变观众期待；需足够线索、公平信息和结局依据 |
| C 最后一件修理品 | 通过履行具体承诺看两人技能与分歧 | 林舟是否冒误车风险完成父亲没做完的活 | 更多工具接触与复杂动作，需验证可拍/生成表达 |

本例**暂选A为开发假设**，理由是“交还责任变成共同处理责任”能在一个小场景中发生，且不必新增大情节。B/C保留为可能发展方向，不自动塞进同一场。若用户已锁定原作或类型，改为比较表达角度，不擅自重选前提。

长篇引擎暂定：每次处理旧账/旧物都让“谁承担、承担到什么程度”产生后果，既往选择不随集数复位。终局和具体体量仍未决，不能因此称季纲/长片大纲完成。用[长篇开发](../creative/02-series-and-feature.md)继续检查重复冲突与承诺回收。

## 2. 写出场功能，再写动作

S-repair v1沿用原创场：林舟站门内背包说末班车快到；林岚让他留下钥匙；他落钥匙收手；她转账本向空椅说“爸的字，你认得”；他看门、卸包、绕桌拉椅，问“从哪儿开始”；她把笔置中。

场功能不是“交代父亲去世”，而是让姐弟从结束交接走到共同处理一件事。人物要对对方做什么：林岚先收回控制，再借认字求助；林舟先结束交接，受邀请后才选择留下。停顿可以成立；提前卸包会破坏本场选择。

空间草案依[空间模板](../assets/05-scene-and-blocking-templates.md#scene-example)：局部A/B/C/D是图上/右/下/左，非地理实测；账桌中央，林岚在A侧偏D、空椅偏B，B墙靠C处为门。林舟到桌B/C角放钥匙，沿桌B侧到A侧空椅。关键状态是钥匙归属、包在肩/落地、账本朝向和笔的位置；具体手别与包落点待预演，不把未定义细节当成已批准事实。

## 3. 覆盖需求决定先做哪些资产

优先比较完整主镜与主镜加反应的方案。需要观众看清门—桌—空椅、落钥匙、邀请和留下的动作，不因为两位角色就自动做固定数量表情/视角图。

| 所需资产 | 由哪个镜头/事件要求 | 要解决的具体未知 | 暂时不必生产 |
|---|---|---|---|
| 林岚、林舟身份基础 | 双人主镜与林舟反应 | 同人跨角度可辨；身份和本场服装/肩包职责分开 | 全套情绪九宫格、剧情未需的年龄阶段 |
| 修理店空间 | 主镜建立与绕桌动作 | 门、桌、椅及通路真实可理解；摄影机能看到关键交接 | 没出现的街区、仓库等扩展空间 |
| 道具身份与功能用途 | 钥匙交还、账本邀请、笔置中 | 钥匙/账本按独立身份追踪并核默认母板；笔只作本例功能/位置标识，清楚现源可复用。各项仍须核结构、归属与阶段 | 每件旧工具独立高精度资产；笔若后续需辨具体身份再升级 |
| 本场故事状态变体 | 主镜/反应切换 | 包在肩、钥匙已落桌、账本已转等正确时点 | 把所有阶段强塞进一张“通用母版” |
| 场景风格候选 | 夜间清点与人物距离 | 光源逻辑、材质、观看距离；不以变暖强行宣布和解 | 预先烘焙每镜最终调色与所有光照 |

可浏览产物是一页资产需求清单，每项关联 Scene/Shot/事件、保持项、可变项、所需视角和观察用途。只有需求时标清无实际素材；绑定必须待真实产物及用途资格，见[资产规划](../assets/01-asset-planning.md)和[参考绑定](../assets/03-reference-binding.md)。

### 本批应出图与引用交接

以下均是计划，实际素材位置为空。两位持续角色在首次正式使用前各准备[9:16身份母板与16:9设定板](../assets/04-character-and-performance-templates.md#character-example)，从同一身份派生；设定板服装/完整背面/脸区分职责，必要脸图按实际可见性复用或补，不固定新增。

[空间样板](../assets/05-scene-and-blocking-templates.md#scene-example)给主图、实际黑白底图、必要方向、拟合并阶段与灯光依据；先排戏和机位，再补所需角度。它们承担设计前置，只有实际支持且需要才作模型输入。底图+文字阶段表只是草拟，未报正式图形完成。

[道具样板](../assets/06-prop-and-interaction-templates.md#prop-example)给钥匙3:4无人无手母板、账本开页与必要接触画格；角色持物、独立钥匙、桌角状态共用设计。无手仅约束产品板，交互必须看清手/物/桌的关系。普通对白先保留邀请→看门→卸包的表演时序，不先批量做表情图。

每图索引列消费者/Shot、设计前置或媒体输入、实际来源/观察或缺项、补图触发与依赖用途。先准备本批必要项，未来雨夜等状态另补；图组信息区、独立文件、实际调用、计费子任务分开，不按表行计费用。

## 4. 从资产需求到有界任务，不编造能力

| Job 草案 | 选择该目标的理由 | 依赖与能力缺口 |
|---|---|---|
| J-Lan-base / J-Zhou-base | 为人物身份参考提供可观察基础；外貌尚需候选选择 | Lib Image 入口与参数未核，先保留需求/描述草案 |
| J-Lan-sheet / J-Zhou-sheet | 当前稳定角色的完整设定板 | 消费对应实际合格身份源与服装设计；三区不当三份单图，背面/脸部引用另核路径 |
| J-shop-main / J-shop-layout / J-shop-blocking | 主图/黑白底图对齐、必要方向与阶段调度 | 先明确设计，逐项核真实图像/编辑入口和来源；不把坐标或阶段表当正式图形，合并清楚阶段不固定调用数 |
| J-key-product / J-prop-interaction | 钥匙母板及本镜必要交互 | 只补当前缺口；同一道具设计，接触/释放与持有转移须实际观察 |
| J-Zhou-bag-state | 依据[肩包卡](../assets/06-prop-and-interaction-templates.md#bag-card)的共同包体/肩带设计，从同一身份派生本镜所需肩上/卸包接触状态；落地在桌B侧靠C的地面，不挡绕桌通路 | 当前实际包源仍缺；先明确同一有效包设计，若编辑消费实际源须已取得并具本用途资格；选择Seedream 5.0 Pro编辑时核身份源与实际编辑契约。本Job不等于独立包母板已交付，落地及动态须另核实际观察 |
| J-master-scene | 表现钥匙→邀请→选择→共同处理 | 等所需身份/空间/状态资产；视频时长按表演及实际支持范围收敛 |
| J-reaction-choice | 只补主镜不足的选择过程 | 共享已验收资产，不天然等待主镜视频；若用其实际末态则另建真实等待 |

当前网页实际输入、引用与结果证据按[平台能力](../platform/01-libtv-capabilities.md)核对；所需输入方式、费用或引用可靠性有具体缺口时，相应Job保持planned。创意获认可不自动增加生产预算。真实前置满足后，按[任务包装](../generation/01-shot-task-packaging.md)、[提示词](../generation/03-video-prompt.md)和[提交核对](../generation/05-submit-reconcile.md)推进。

Seedance2.5完整请求参见[修理店七段实例](01-dialogue-scene.md#seedance-filled-example)；内部空间编号须在本次模型实际收到的文字或媒体中解释，本页的设计索引本身不等于模型收到布局。

提示词只承载当前任务需要的已选决定：镜头看什么、人物做什么及顺序、空间关系、引用各自职责与允许变化。不要把整个季纲、所有形容词和所有资产说明塞进每个镜头，也不要在能力未知时写貌似生效的参考占位符。

## 5. 观察分支会反过来改变制作选择

假设未来观察发现空间候选A光影漂亮，但主镜看不见钥匙落桌；候选B较朴素却能看清交接和空椅。比较三条实际方案：

1. 采用B的空间关系，并在允许范围改外观；保住场功能。
2. 保留A但调整桌角/机位，先做低成本空间验证；改了布局就更新资产与Shot版本。
3. 保留A并增加交接覆盖，但计入新增镜头、状态接续和成本；不能假定补特写一定更便宜。

如果只是观察看不到足够角度，先补观察，不能把“未知”直接判成布局错误。无声音观察不影响单独合格的身份/空间视觉用途，但不能判断邀请对白或声画接续。

假设未来人物变体看起来像另一人：先查引用是否真实绑定、源版本和保持/改变职责。若绑定正确而编辑漂移，选择其他候选或有界返修；不要每次重建全部角色。若模型入口不能支持所需编辑，比较已有素材、其他受授权方案或改制作方法，沿用用户指定模型名称说明缺口，不静默替换。

## 6. 预算如何影响资产建设

以下均为虚构预算，不是当前报价或授权。

假设预算200元、最多8次计费业务任务，且本例每个下列工件恰由一个计费任务产生（仅此算例前提）：两角色母板+设定板共4项，每项20元；主图/底图/可读合并调度图3项，每项15元；钥匙产品图1项15元。这是另一个“将阶段合成1张且须可读验收”的预算候选，不能默默替代前文D-approach/D-choice两张计划；若仍需两张调度图，则为155元、9项，已越8项上限。一张调度图的候选共140元、8项，尚余60元却已用完数量额度；账本尚缺的默认母板/开页用途、视频、必要额外角度/交互、观察、装配和返修仍未覆盖，因此不能开始这份全批承诺。不能把计费观察藏进验收一行，也不能假设一张总览免费或自动导出多图。

先核已有可复用来源、本批真正缺项和真实计费单位；在原授权内比较缩小为明确探索样片、复用已有图或重排范围，需新增额度才给具体差额。实际入口一请求出多Take时仍按真实契约计数，不把图组张数和Attempt/业务任务混算。

若空间任务返回不明，原最大预留继续占用；可靠依赖和余额成立的独立人物工作可继续，正式空间批次仍等必要设计/素材。只有旧prepared/无回执并非未提交证明；核销与累计规则统一见[项目契约](../core/01-project-contract.md)，换版不重置。

## 7. 给下一阶段的具体交接

交接包应包含：开发假设与未决体量/终局、S-repair场文本/行动谱、空间草案、必要覆盖表、资产需求及其真实素材缺口、Job草案/依赖、能力/费用缺口、首场观察条件。它已经能被人浏览、讨论和继续执行前置工作，但不是资产全部验收、也不是生成完成。

场末计划先记钥匙留桌B/C角、包已落地、账本朝空椅、笔置中；真实素材返回后另记候选观察与最终Clip出点，交[ContinuitySnapshot](../core/03-records.md#continuity-snapshot)，再由Checkpoint保存其真实索引。若后集闪回到交钥匙前，取那个故事时点的包/钥匙状态，不能取最新生成或最大故事时间。探索图后来若要晋升正式接续源，补齐相关设计/图组并观察实际出点，保留晋升理由和原来源；不只改标签，也不永久弃用。

下一阶段的检查条件是：交钥匙能否被看清；邀请发生后人物才卸包；门、桌和空椅能否连成可理解的行动；实际素材中有足够区间让这条因果进入剪辑。若只得到“门口说话”和“已坐下”两个好片，仍回覆盖/返修，而不是宣布完成。具体取段、半开区间、声音限制与返修演算见[文戏示例](01-dialogue-scene.md)。
