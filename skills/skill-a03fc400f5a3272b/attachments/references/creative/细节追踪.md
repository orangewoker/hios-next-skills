# 细节追踪（微短剧版）

> **定位**：解决微短剧跨集"前后矛盾"——身份重复揭秘、物品归属混乱、伤势/状态跳跃、承诺遗忘等一致性错误。
> **适用场景**：全剧强制执行，尤其是中长篇（>30集）。
> **与其他系统的关系**：角色基本档案由 `角色档案.md` 管理，物品/场景外观由 `物品档案.md`/`场景档案.md` 管理，本系统负责跨集**动态状态**的追踪。

---

## 一、追踪范围（5大维度）

| 类型 | 微短剧典型场景 | 追踪核心 |
|:---|:---|:---|
| **身份/关系** | 女主实为豪门千金、男主是隐藏战神、反派是失散亲人 | 信息揭示的**单向性**（已揭示的不能"再揭秘"） |
| **物品归属** | 信物/玉佩/合同/证据/录音笔 | 物品在谁手中、何时转移 |
| **伤势/状态** | 车祸失忆、中毒、功力恢复进度 | 状态的时序逻辑（不能昨天重伤今天打架） |
| **承诺/债务** | "三日后还钱""我会回来娶你""欠你一条命" | 承诺的兑现状态 |
| **伏笔线索** | 关键台词、暗示镜头、可疑物品 | 埋设→提醒→回收的完整链条 |

---

## 二、追踪表格式（项目文件：`关键细节追踪表.md`）

> 在 `/目录` 阶段创建空表，每集 Phase 0 回写更新。

```markdown
> 更新时间：{ISO时间戳} | 当前集：第{N}集 | 总细节数：{M}条

| 首次集 | 细节ID | 类型 | 具体内容 | 相关角色 | 状态 |
|--------|--------|------|---------|---------|------|
| 001 | Z001 | 身份 | 女主林栀实为林氏集团失散千金 | 林栀 | 观众知/角色未知 |
| 003 | Z002 | 物品 | 黑色U盘内含关键证据，男主交予女主 | 顾霆琛, 林栀 | 林栀持有 |
| 005 | Z003 | 关系 | 反派陈峰实为男主失散多年的哥哥 | 顾霆琛, 陈峰 | 观众知/角色未知 |
| 006 | Z004 | 伤势 | 林栀车祸后短暂失忆 | 林栀 | 未恢复 |
| 008 | Z005 | 承诺 | 男主承诺三日后解决陈峰 | 顾霆琛 | 未兑现(限期012集) |
| 008 | Z006 | 伏笔 | 男配沈毅接到神秘电话后脸色骤变 | 沈毅 | 待回收(~015集) |
| 007 | Z002 | 物品 | U盘被陈峰夺走 | 顾霆琛, 林栀, 陈峰 | 陈峰持有 |
```

### 状态栏取值

| 状态值 | 含义 | 示例 |
|:---|:---|:---|
| `观众知/角色未知` | 信息已揭示给观众，角色本人不知 | 身份揭露的关键反转点 |
| `已揭示({集号})` | 身份/关系已在指定集向剧中角色完全揭示 | 打脸时刻 |
| `{角色}持有` | 物品当前归属人 | 关键道具流转 |
| `已消耗` / `已丢失` / `已毁坏` | 物品终态 | 防止"已毁物品再出现" |
| `未恢复` / `恢复中` / `已痊愈({集号})` | 伤势/状态 | 状态时序逻辑 |
| `未兑现(限期{集号})` / `已兑现({集号})` | 承诺/债务 | 防止遗忘 |
| `待回收(~{集号})` / `已回收({集号})` | 伏笔 | 回收链完整 |
| `已过期` | 限期承诺逾期 | 需在后续集解释 |

## 三、回写流程（Phase 0 执行）

> 在 `script.md` Phase 0 数据加载清单中追加本步骤。

### 3.1 触发词扫描

逐段扫描本集剧本正文，命中以下触发词则提取为新细节：

- **身份**：`其实是`、`真正的身份`、`竟然是`、`不是……而是……`、`失散`、`亲生`
- **物品流转**：`交给`、`被夺`、`归还`、`遗失`、`毁坏`、`送出`
- **承诺**：`答应`、`承诺`、`发誓`、`保证`、`欠`
- **伤势**：`受伤`、`失忆`、`中毒`、`昏迷`、`痊愈`
- **伏笔**：刻意强调但未解释的台词/镜头/物品

### 3.2 处理规则

1. **新增**：追踪表中无相关条目 → 创建新行，分配 Z 前缀 ID。
2. **更新状态**：已有条目的状态在本集变化 → 追加新行（同 Z ID、新集号），更新状态列。
3. **不回写**：日常小额消费、临时路人、泛指数值（"几百人围观"）、修辞夸张中的数字。

### 3.3 Z ID 设计

- 前缀 Z（状态追踪），独立编号，每集回写后自增。
- 同一细节的状态变更使用相同 Z ID + 新行记录，形成状态链。

## 四、Phase 0 校验（本集生成前执行）

> Phase 0 收集上下文中，加载 `关键细节追踪表.md` 全文，执行以下校验：

### 4.1 身份不重复揭示

本集若出现"原来你就是……"式揭秘 → 查追踪表确认该身份是否已标记 `已揭示`。
- 已揭示 → **阻断**，提示"此身份已在第X集向角色揭示"。

### 4.2 物品归属一致

本集角色使用某物品前 → 查追踪表确认该物品当前状态。
- 已丢失/已毁坏且未恢复 → **阻断**。
- 在他人手中 → 需解释为何本集出现在当前角色手中。

### 4.3 伤势/状态逻辑

本集角色状态描述 → 与追踪表上一状态对比：
- 昨日重伤今日打架 → **阻断**，除非本集有恢复过程的交代。

### 4.4 承诺限期检查

本集超过承诺限期且仍未兑现 → **警告**，提示在本集必须安排兑现或解释。

### 4.5 伏笔逾期检查

本集超过预计回收集 ±5 集且伏笔仍未回收：
- 超出 5-10 集 → **警告**。
- 超出 >10 集 → **阻断**，必须在本集或下一集回收，或标记为废弃。

---

## 五、Phase 3 自检扩展（门控追加）

> 在 Phase 3 校验清单中追加以下检查。

| 检查项 | 级别 | 判定逻辑 |
|:---|:---:|:---|
| 身份重复揭示 | 致命 | 本集揭秘的身份在追踪表中已为"已揭示" |
| 物品使用矛盾 | 致命 | 本集使用的物品在追踪表中为"已毁坏/已丢失"（且无恢复说明） |
| 伤势跳跃 | 严重 | 伤势从"未恢复"直接跳到"正常行动"无过渡 |
| 承诺逾期未兑现 | 严重 | 本集超过限期且未兑现/未解释 |
| 伏笔逾期未回收 | 严重 | 本集超过预计回收集 >10 集 |
| 物品归属桥接 | 警告 | 物品出现在A手中但追踪表显示为B持有，且无转移描写 |

---

## 六、全剧终结检查（/导出 前执行）

> 倒数第3集开始，逐集检查：
> - 全部身份揭示 → 已揭示
> - 全部承诺 → 已兑现 或 已过期(有解释)
> - 全部伏笔 → 已回收 或 已废弃(有说明)
> - 全部伤势 → 已痊愈 或 转化为永久状态且有交代
> - 全部物品 → 有最终归属
