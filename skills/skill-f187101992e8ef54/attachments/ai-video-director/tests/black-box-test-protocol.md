# 真实端到端黑盒测试流程

状态：尚未执行。

本流程与“合同回归测试（黄金样例验证）”分开。预制样例通过验证器，只证明样例和检查器之间的合同一致，不能证明新会话中的模型会真实执行启动协议、第0层、文件读取和正式输出流程。

## 执行条件

1. 新建不继承当前聊天上下文的独立模型会话或模型进程。
2. 只向该会话提供完整 `ai-video-director` Skill 包和一条测试输入，不提供黄金样例输出、历史对话或人工补充答案。
3. 记录模型名称、版本、会话标识、开始时间、加载的Skill包版本和原始测试输入。
4. 由模型现场生成答案；把未经人工增删、改写或纠错的原始输出原样保存。
5. 对原始输出运行 `scripts/validate_final_output.py`；同时保存验证器版本、命令、标准输出、错误输出和退出码。
6. 保存完整会话日志或API调用记录，证明输出来自该独立会话，而不是预先编写的测试夹具。

## 最小黑盒用例

- 空启动：只加载Skill，不给项目内容；验证仅返回固定启动询问。
- 简单真人对话：一次提供完整故事、时长、画幅、导演取向、保留项与禁用项；验证不重复提问，并现场生成两个正式部分。
- 动画连续空间或复杂动作：验证分场景／分楼层2×2四向板、结构底图和路线图的真实依赖链、即梦镜头组独立执行信息、单组15秒和单组4000字限制；第三部分整体字数不设上限。

## 通过条件

- 原始模型输出未经过人工修改。
- 会话日志证明Skill在独立上下文中被加载并按相对路径读取内部文件。
- 空启动不询问视频模型；第二部分总表／操作卡／资产状态、第三部分固定栏目、逐组时长与字数、音乐规则、声音边界、素材可用性和路径检查全部通过。
- 任何失败都保留原始输出与日志，不用人工修订后的版本替换失败证据。
