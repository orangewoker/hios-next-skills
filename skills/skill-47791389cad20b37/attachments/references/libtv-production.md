# LibTV 动漫 PV 制作流程

仅在用户确认制作单、需要实际操作 LibTV 时读取本文件。凡是 LibTV 画布、项目、节点、模型或素材操作，只使用官方 `libtv` CLI；命令与本文件不一致时，以当前 `libtv --help` 和子命令帮助为准。

## 目录

环境预检 → 模型与 schema → 纯文本脚本/分镜 → 角色资产设定图 → 角色资产验收 → Minimax H3 视频节点 → Mureka V8 配乐 → 时间线合成 → 质检与交付

**图片生成硬限制：只生成角色资产设定图。不得生成场景图、道具单图、分镜关键帧、首帧、尾帧、转场图或任何视频辅助图片。**

## 1. 环境与任务预检

开始任何 LibTV 实际操作前，必须确认用户已在本次项目中明确选择：生图模型、画幅比例、具体时长、清晰度。任一缺失时立即返回主流程继续询问，禁止使用默认值、历史状态或推荐项代填。

1. 检查 `libtv --help`、账号登录、当前画布和节点列表。
2. 没有画布时按官方 CLI 创建并绑定。
3. 节点使用唯一前缀，例如 `PV-片名-角色资产-角色名`、`PV-片名-V01`。
4. 已有同名任务时通过可点击选项决定续做、新建副本或取消。

## 2. 模型解析与 schema 检查

对本次模型执行：

```text
libtv model search --type image "<用户选择的生图模型>"
libtv model search --type video "Minimax H3"
libtv model search --type audio "Mureka V8"   # 仅需要配乐时
libtv model <唯一 modelKey>
```

规则：

- `model search` 用于找候选，`libtv model <modelKey>` 读取完整 schema。
- 节点参数只使用实时 schema 支持的字段和枚举，不猜比例、清晰度、modeType、duration、声音字段或参考图字段。
- 用户选择的 2K/768P 是交付意图，若模型不支持则用可点击选项处理，禁止静默降级。
- 图片模型只用于角色资产设定图，不得因为视频模式限制而自动创建额外图片。
- 视频模型可使用的图片参考数量必须读取实时 schema。即使上限允许多张，也只连接已验收角色资产设定图和用户原始上传参考；不为了凑参考数量生成其它图片。

## 3. 纯文本脚本与分镜

用 `script` 节点或等价文本节点承载镜头表。每行至少包含：

- `durationSeconds`
- `plotDescription`
- `characters`
- `shotSize`
- `characterAction`
- `emotion`
- `sceneTags`
- `lightingAndAtmosphere`
- `audioEffects`
- `dialogue`
- `videoMotionPrompt`

不要求 `imageGenerationPrompt`；若当前 script schema 强制存在该字段，则保留为空字符串或非执行占位文本，且**绝不调用 storyboard 生图**。

校验所有 `durationSeconds` 之和等于目标总时长。分镜行描述内部镜头，不等于视频节点；之后按 `N = ceil(总时长/15秒)` 合并为固定数量的连续视频段落。

每一对相邻内部镜头维护文本“转场交接契约”：记录上一镜头尾帧的主体屏幕位置、角色朝向、运动方向与速度、主要遮挡、主色、图形形状、视线和相机动势；下一镜头至少匹配其中两项。

## 4. 角色资产设定图

### 4.1 生成规则

只为每个主要/重复角色创建 1 个 `image` 节点。提示词使用 [character-asset-template.md](character-asset-template.md)，并填入角色一致性卡与用户参考图信息。

每张图必须同时包含：

- 左侧高张力动态主图。
- 右侧正面、侧面、背面三视图。
- 六宫格表情特写。
- 同图内配件/装备局部放大。
- 右下色板。
- 白色背景、专业角色设定排版、创意标题和简洁注释。

不创建场景 Key Art、道具图、服装图、逐镜关键帧、首尾帧或 storyboard 图片节点。

### 4.2 角色资产验收闸门

全部角色资产成功后查询实际结果 URL 和状态，按角色展示设定图与质检摘要，然后暂停并发送：

- `满意，进入生视频（推荐）`
- `局部返修`
- `整组重做`

局部返修只提供：`脸与发型（推荐）`、`服装与装备`、`排版与色彩`。返修只重跑对应角色资产节点。

未明确满意前，不创建或运行任何视频节点。没有结构化选择工具时，展示角色资产后停止。

## 5. Minimax H3 视频生成

### 5.1 节点数

- 1–15 秒：1 个节点。
- 16–30 秒：2 个节点。
- 31–45 秒：3 个节点。
- 46–60 秒：4 个节点。
- 其它时长：`N = ceil(总时长秒数 / 15)`。

把文本分镜按时间顺序合并为 N 个连续叙事段落，每节点不超过模型实时 schema 允许的时长。

### 5.2 图片参考使用

视频阶段只允许引用：

1. 已验收角色资产设定图。
2. 用户原始上传的角色/Logo/参考图（若用户已明确要求参考）。

不得引用任何新生成的场景图、道具图、关键帧或首尾帧，因为这些图禁止生成。

若当前视频模式支持多图角色参考，优先把当前段落会出现的角色资产图连接给节点。若只支持单图且只能把输入当首帧，先检查是否有“角色参考/主体参考”类模式；没有时通过可点击选项选择纯文本生视频、更换模型或取消，**不得为此补画首帧**。

### 5.3 视频提示词

每个 `videoMotionPrompt` 必须读取 [reference-video-style.md](reference-video-style.md)，并严格按照以下章节：

 1. `生成目标：`
 2. `整体风格：`
 3. `角色设定：`
 4. `主题设定：`
 5. `音乐与声音：`
 6. `画面风格：`
 7. `动态与转场要求：`
 8. `按时间码镜头：`
 9. `表演要求：`
10. `节点尾帧与下段交接：`
11. `不要出现：`

提示词全部使用自然、详细、可执行的中文。只有成片中需要显示或说出的英文保留英文原文并使用半角双引号。

潮流/JRPG/角色宣传类默认平均单镜约 0.3–0.8 秒；开场 1 秒建立强识别，中段高频卡点，结尾突然定格并用原创标题确认音收束。转场优先使用图形碰撞、故障闪断、贴纸覆盖、图层滑移、速度线推切、圆形扩张、漫画分格、文字爆闪、瞬时拉近、卡点闪白、噪点抖动、UI 插入和符号遮挡。

至少有前景贴纸/UI、中景角色、后景图形/色块三层运动。角色动作必须二次元化、利落、张扬或与当前人格一致；不要真实摄影式人物调度。

### 5.4 节点连续性

视频节点按时间顺序同步生成。每段完成后查询实际结果并检查尾帧：角色位置、朝向、动作趋势、主色、主要遮挡图形和相机动势。生成下一段前，基于真实尾帧更新下一段的 `节点尾帧与下段交接` 和开头时间码，但不得修改已验收角色资产。

交接失败时只返修受影响视频节点。不得通过新增关键帧图修复。

### 5.5 声音

每个视频节点原生轨若模型支持对白，提示词写清说话方式与精准对口型(Lip-sync)；

## 6. Mureka V8 配乐

需要配乐时，读取实时 schema。提示词包含总时长、BPM、音乐风格、开头钩子、中段节奏推进、高潮/定格位置、主要乐器、无歌词，以及给对白和同期声留空间。音乐在视频节点生成后进入时间线，不由视频模型原生生成。

## 7. 时间线合成

需要多节点、外部配乐、配音或精确裁剪时使用 `video-clip` 节点：

1. 按段落顺序连接 N 个视频节点。
2. 连接配乐/配音节点。
3. 使用实时支持的 timeline 字段设置起止、时长、来源偏移和裁剪。
4. 精确控制成片总时长与音量层级。
5. 运行终剪节点并等待终态。

## 8. 质检与交付

至少检查：

- 全片纯二维，无 3D、CG 写实、摄影污染。
- 角色与已验收角色资产一致。
- 未生成或依赖任何场景图、道具图、分镜图、首尾帧。
- 角色脸、发型、瞳色、服装、鞋、装备、配色稳定。
- 手指、肢体、文字、UI 没有明显错误。
- 第一秒有强识别，中段持续推进，结尾落版清楚。
- 相邻镜头和节点的方向、图形、颜色、遮挡和动势连续。
- 比例、清晰度、总时长和音画同步符合制作单。
- 视频原生轨无模型自带 BGM；后期配乐与卡点匹配。

交付成片、画布链接、角色资产设定图、纯文本分镜/镜头表、配乐节点（如有）和实际模型规格摘要。
