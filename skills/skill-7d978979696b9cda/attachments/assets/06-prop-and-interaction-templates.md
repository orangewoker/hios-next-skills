# 道具、状态与交互图组模板

关键道具、双面信息物、开合容器、操作部件或人物持物交互需要明确设计时使用。先从[资产需求](01-asset-planning.md)判断叙事职责；普通远景杂物不逐件建全套母板。动作因果归[场面调度](../creative/05-blocking-action.md)，实际源和用途归[Binding](03-reference-binding.md)。

<a id="prop-defaults"></a>
## 默认形式与补图触发

关键道具母板默认3:4单件产品照，完整单件、选有辨识力的角度、无人物无手，结构材质清楚，不靠戏剧光藏细节。已有合格素材符合当前用途和形式时复用；比例不支持时记实际替代及未满足项，不虚称精确默认交付。首次设计候选无既有母板也可从文字起步，制作仍遵守项目预算和真实能力。

| 类型/用途 | 需要表达的内容 | 本批补图与延后条件 |
|---|---|---|
| 普通整体可辨物 | 清楚全貌和必要尺度关系；不承担身份时可复用场景/人物中足够清晰的源 | 握持、局部或尺度成为关键才补；不是每把背景勺都需产品板 |
| 双面信息物 | 正反面的有效设计、差异、文字/标志 | 本批只看一面可延后另一面；翻背、看背或背面线索出现前补足，正面合格不证明背面 |
| 开合/容器 | 外形及本场实际开合、内部和装载状态 | 翻页、取物、装入或破损影响因果时补对应阶段；闭合图不能证明内部结构 |
| 机器/车辆/部件 | 整体、操作部件、作用面及空间/承重关系 | 动作涉及另一侧、装配或运动时补关键结构；不为所有面做机械配额 |
| 人物交互 | 身体/手与物的接触面、尺度、持有转移、放手前后 | 产品母板无手只约束该母板；交互图可且必要时必须有手/人物，先复用合格来源再按缺口补 |

机器人可同时是角色与具有可替换部件的对象；角色身份和部件道具链接同一有效设计与故事状态，不能维护两套矛盾身体。

<a id="prop-interaction"></a>
## 动作与设计的交接

交物分进入接触、接收承重/持有转移、释放离开；物件已经在对方手里的一张图不能证明交接过程。谁的哪只手按人物自身左右登记，再由机位判断画面位置；不能镜像解决另一面或另一手。需要的阶段画格归分镜，静态持物/接触参考归资产，节奏与完整转移靠实际视频观察，不机械三图三次生成。

角色设定中的持物区、独立道具母板、场景中的摆放物共用一个有效设计依据。款式、缺口、铰链、材质或文字冲突先比较来源和已确认事实，回设计决定，不能默默任选最新图。物件结构与故事开合/损坏、持有人、放置点分别记；制作纠错不自动成为剧情事件。

参考背面、局部或交互时，已有可定位合格来源足够则复用；图内某区域不等于独立素材。只用真实可用提取/编辑/派生方式并核算费用，实际保存与观察后再绑定。首次交互候选可根据明确设计、角色身份和道具源制作，不要求先有同动作Take。若多源超限，先按[容量分支](03-reference-binding.md#reference-capacity)保住本镜必要事件，不把关键道具永远排在身份之后。

## 可填写道具与交互卡

- 道具稳定ID、类别/叙事作用、结构/材质/标识；依据、提案与未知分开。
- 故事状态/时点、持有人或位置、变化事件、父状态；制作修订及适用Scene/Shot。
- 母板/双面/开合/局部/交互应出图索引：形式、保持/可变项、消费者、实际来源/观察或计划、缺项和延后触发。
- 交互阶段：人物ID与自身手别、接触点/作用面、承接/释放条件、前后归属、可见范围和动态观察项。
- 依赖用途：道具设计→角色持物/场景摆放/交互；身份→手/身体；故事状态→损坏/开合/归属；布局→接触位置。按[变更影响](../core/05-change-impact.md)查实际引用，不因一个角度看不到就猜不受影响。
- 验收判据、偏差与返回层级；合格用途交Binding，场末归属交[故事快照](../core/03-records.md#continuity-snapshot)。

<a id="prop-example"></a>
## 完整填写例：修理店钥匙、账本与笔

原创应出图计划，无真实图片或生成。钥匙外形与手别是此例的设计提案，未声称用户已经锁定；不改[修理店](../examples/04-creative-to-assets.md)的交还、邀请和留下事件。

| 项 | 本例填写 |
|---|---|
| 关键实体 | PROP-key，修理店钥匙；黄铜色单片钥匙、圆头孔、齿面可辨为D-key r1提案；角色卡中的钥匙同此设计，不另造款式 |
| 默认母板 | A-key-product r1，3:4单件无人无手产品照；轻微斜角展示头孔、齿面和厚度，完整入画、材质清楚；当前无实际源 |
| 状态 | S-key-held：林舟持有；E2接触桌B/C角后收手，转S-key-table：留在同一桌角；不把位置变化写成物件新身份 |
| 交互图 | 本例拟右手自然持钥匙→接触桌面→放手收回；人物自身右手，画面哪侧由机位核。先看现有角色/钥匙源是否足够，不够再补接触画格，产品板无手不约束此图 |
| 观察 | 齿面/头孔一致；手没有穿物，接触桌面后才松手；收手后钥匙仍留桌角。静帧只证所见相位，动态与动作声同步另观察 |
| 补图/延后 | 本场不展示钥匙背面文字或开锁，不编锁孔细节，不为凑数补四面；后场真正开锁再补作用面和接触关系 |
| 账本 | PROP-ledger，因跨镜承担邀请并需认作同一本而独立追踪；同样需要3:4无人无手单件母板。若现有已观察的打开账本图已满足该形式与辨认用途，可兼任；否则补相应产品母板，当前仍未完成。打开页/朝向按本场补，未锁文字不伪造可读父亲原文；闭合封面细节延后到真正需要前。转向是动作，不由终态图证明 |
| 笔 | PROP-pen是本例位置/动作标识，不承担独立款式辨认；需看清林岚置于两人中间及前后归属，清楚现源可满足功能用途，因此本批不强制3:4产品母板，当前来源仍未取得。若后续变成必须认出的刻字笔等，则升级独立身份追踪，补或复用合格默认母板；握持/笔尖动作关键时补局部 |
| 依赖/返回 | 钥匙设计供角色持物、桌角状态、交互及镜头；款式矛盾回设计；牌名/角色对应错查映射；文案漏放手修请求；实际放手后物件消失记录时段交返修 |
| 下场交接 | 计划钥匙留桌角、账本朝空椅、笔置中；实际Take/Clip返回后分别记所见与出点。无真实素材时不把这些计划填成场末观察结果 |

## 验收、失败返回与交付

并看实际图与有效设计，按本用途检查结构、材料、字面信息、比例/接触、状态和归属。不同用途可分别保留或返修；不以母板通过代替交互完成。动态候选检查确切区间和邻接，不只看首尾两帧。已生成部位不合预期先定位[四层原因](../quality/02-repair.md#asset-repair-layers)，在原授权内有界返修；不删掉物件转移或背面发现来迁就参考容量。

交付可浏览道具卡、图与用途索引、具体缺项和下一步；图像编译沿用[请求卡](../generation/02-image-prompt.md)，生产状态仍由core/03定义。项目默认和公开方法范围见[来源](../evidence/01-sources.md#asset-space-methods)。
