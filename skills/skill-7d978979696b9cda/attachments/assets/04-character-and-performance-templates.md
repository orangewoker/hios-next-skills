# 人物图组与表演参考模板

持续人形角色进入稳定制作批次、需要补可辨视角或表演参考时使用。先读[资产需求](01-asset-planning.md)和[制作验收](02-asset-build-review.md)；本文件规定图的形式，状态定义归[核心记录](../core/03-records.md)。没有实际图时交应出图卡，不填虚构来源或通过记录。

<a id="character-defaults"></a>
## 默认图组与建立时机

| 工件 | 默认形式与职责 | 不得误认 |
|---|---|---|
| 身份母板 | 9:16，单人正面全身、中性表情、完整脚部、浅灰背景；面部、比例、发型与可辨特征清楚。默认单图身份基准 | 极端角度/表情气氛图或不合规格的旧帧不自动算该母板已交付 |
| 设定板 | 16:9，清晰分为正面无头服装、完整背面含头部/头发、面部特写三个信息区；从同一身份及有效服装设计派生 | 不是三张完整全身视图，也不是三份已保存的单图；无头区只表达服装，不表达人物断面 |
| 必要补图 | 目标镜头确需但现源不足的侧面、前3/4、背面、脸部单图、状态或交互；范围以用途为准 | 不默认四个全身方向、每镜新脸图或全套情绪九宫格 |

持续人形角色按稳定批次，在首次正式使用前建立并核对母板和设定板；不在立项时先做全季全部角色。已合格素材满足相应形式与用途时复用，不重复调用。明确探索、一次性背景群体和非人形角色按[身份职责分级](01-asset-planning.md#identity-tracking)处理；动物、机器人、面具角色按实际结构和辨认需要调整，不能硬套无头服装版。

首次身份探索可从文字设计或真实已有来源起步，不以已存在的母板为前置。选定身份之后补成正式默认图组；旧合格帧可以作设计或限定用途来源，未达9:16等规格仍记录默认母板未完成。改画幅/排版属于制作修订，不因此改人物身份或故事状态。实际入口不支持所需比例时写明可用替代及差异，可继续限定用途，不把替代品报为精确规格交付。

<a id="character-reference-paths"></a>
## 从图组到实际引用

先查当前镜头所需部位是否在已有合格来源中足够清楚。身份母板默认承担单图身份；设定板首先承担服装结构、背面和面部的设计/审阅。整板作为实际输入时，明确各区用途：无头正面区仅供服装，背面区供后部结构，脸区供面部细节，不把三个区搬成三个演员或将无头衣服变成人体。

当前入口允许图像引用时，可用这些明确职责做有界探索并观察结果，不要求先有同一路线的成功结果；没有证实的ROI/区域输入工具不能被假造。探索正确也只取得实际观察的用途资格，不能推定其他角色、角度或整个模型都适用。

若需要背面或面部独立参考，而当前来源无法清晰、可靠地表达：使用实际存在的提取/裁切能力，或从同一身份和有效设计派生必要单图。真实保存、定位和观察后交[Binding](03-reference-binding.md)；裁切不是新角度，看到板内区域不等于已有独立文件，费用按[授权](../core/01-project-contract.md)核算。已有脸部源够清楚则直接复用。图像入口本身的引用容量也要核对，不假设它可以吞下视频入口装不下的全部参考。

<a id="performance-templates"></a>
## 表情、姿态与动态表演

表情先写剧情触发、注意对象、眼眉口/头部可见变化、强度和允许变化。静态定型、关键画格或表情漂移返修：优先复用可定位、已观察的合格帧；没有才从同一身份补目标表情。对照时尽量保持观察角度、尺度和清楚照明，不能把角度差当表情差。

普通对白、现有参考足够且无定型用途时，保留表演设计即可。警觉到克制、听后决定等时间中的变化由[表演](../creative/04-directing-performance.md)与[视频观察](../post/01-observation-selection.md)验证；端点图片不证明转变或停顿。首次视频不等待尚不存在的合格Take。

姿态/交互图显示足够身体、接触点及道具。静态体态属于资产；某镜开始/转折/结束的画格归[分镜](../visual/03-storyboard-previs.md)；接触、承接、释放等动态时序归[调度](../creative/05-blocking-action.md)及实际视频观察。按需要取阶段，可复用合格源，不把三阶段机械算成三次新生成。

人物卡可以记录“处境如何留下稳定的体态、手部使用和步态习惯”，例如长期劳作造成的站姿或拿工具方式；这是身份与生活痕迹的设计依据。某一场的赶车、握包、受伤或听后停手属于故事状态和表演，不应烘焙进中性9:16身份母板。设定板说明服装和结构，也不证明动态表演已经成立。

为避免这条设计依据停留在说明文字，持续角色卡在有原文、用户决定或可观察来源支持时，可填写一行“稳定体态／手部／步态习惯”：写明生活处境或身体条件、可重复观察的外在表现、哪些镜头可见，以及哪些表现只在特定故事状态出现。没有依据时明确写“未定／无依据”，不能为了填表编造经历。该行只约束身份与长期行为倾向；它不能把某场的受伤、赶车、持包、听后停手等状态写成母板默认姿势，也不能用静态卡代替视频验证。

## 可填写人物与表演卡

- 角色稳定ID／追踪职责；身份设计依据、已确认事实与设计提案。
- 本批Scene/Shot/故事时点；服装、伤势、持物、声音等状态另链接，制作修订另记。
- 应出图：母板、设定板、必要补图；各图形式、当前消费者、保持/可变项、已用来源和观察范围。
- 不对称特征：人物自身左/右；镜头观看侧；预计画面位置（由机位判断，不能镜像推另一侧）。
- 表演：触发→注意对象→可见变化→强度/时序；是否需要静态定型或动态观察。
- 稳定体态／手部／步态习惯（可选）：依据、可重复表现、可见镜头与仅属故事状态的表现；无依据时写“未定／无依据”。
- 依赖用途：身份→设定板/视角/状态/表情，服装设计→服装区，独立道具设计→持物/交互；保存确切版本与用途，交[变更影响](../core/05-change-impact.md)。
- 当前缺项、可延后项及触发镜头；实际素材位置/用途结论或“应出图计划”；下一步与失败返回。

## 完整填写例：修理店的林舟

以下为原创制作提案，未生成或观察任何图。外貌为本例补充设计，不冒称原文事实；故事沿用[修理店](../examples/04-creative-to-assets.md)。

| 项 | 本例填写 |
|---|---|
| 实体与依据 | C-Zhou，需跨镜辨识的持续人形角色；短黑发、瘦长脸、深灰工作夹克为设计提案 D-Zhou r1；没有擅加伤疤、年龄或亲属经历 |
| 稳定体态／手部／步态习惯 | 当前原文与来源没有长期身体习惯依据，暂记“未定／无依据”；邀请后看门、停手和卸包属于本场表演，不写入身份母板 |
| 故事状态 | S-repair 当夜；邀请前肩包仍在肩，听完看门之后才卸包；身份与衣着/持物状态分开 |
| 母板计划 | A-Zhou-base r1：9:16正面全身、中性、完整脚、浅灰底；双手自然可见，不用强戏剧光锁定正片照明；用途为Sh-master/Sh-reaction身份及设定板父源 |
| 设定板计划 | A-Zhou-sheet r1：16:9；正面无头夹克衣裤、完整背面含短发后部、清楚脸部特写。包体/肩带共用[肩包卡](06-prop-and-interaction-templates.md#bag-card)中待补的D-bag r1设计提案，当前无实际包源；佩戴与落地另列状态，由J-Zhou-bag-state处理人物带包状态，不在服装区把包融合为身体 |
| 引用路径 | 先取得并按身份用途核对实际母板，再派生设定板；当前均无来源。Sh-reaction若母板脸部不足，复用合格脸源或从同一身份派生脸部单图；未证实裁切就不写已提取 |
| 必要补项 | Sh-master需包带/卸包接触与本场身体范围；若默认板已够，不新增。背面绕桌只有镜头实际需要时补独立背图；后续雨湿状态延至对应故事场次前 |
| 表演 | 邀请→看门→停住→卸包；注意对象先林岚、再门、再账桌。普通对白不作全套情绪图；若反应表情漂移才补同角度目标表情；停顿和先后靠视频观察 |
| 方向 | 具体手别/身体转向依已选调度版本；不从屏幕右侧推成角色右手，不用镜像另一侧作新证据 |
| 验收与缺口 | 检查同人、脚部完整、三区职责、夹克/包结构与故事时段；当前全部为计划，未赋acceptable、未绑定、未计实际调用 |
| 返回 | 源设计冲突回资产需求；脸/服装误继承查Binding及请求；结果漂移保留具体图/部位后走最小返修；不重建全部角色 |

## 本批验收与交接

用实际图并看父源，逐用途检查身份、可见结构、故事状态、本人左右、图组区域与清晰度。格式不合可保留有据的局部身份用途，但默认图组交付状态仍据实。新视角/编辑区域重新观察，未见面不报通过。表演图片不能替代动作、口型或听审。

合格源交[引用](03-reference-binding.md)，缺陷交[四层返修](../quality/02-repair.md#asset-repair-layers)；状态影响交[故事时点快照](../core/03-records.md#continuity-snapshot)。人物卡/图组索引供用户浏览，具体请求仍沿用[图像请求卡](../generation/02-image-prompt.md)，不另造工具字段。版式来自本项目决定，工艺来源范围见[资产与空间方法](../evidence/01-sources.md#asset-space-methods)。
